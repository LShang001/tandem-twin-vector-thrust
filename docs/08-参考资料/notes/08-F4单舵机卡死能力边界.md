# F4 单前摆舵机卡死：控制律能力边界（2026-10-21）

## 结论

当前构型下，前摆 δ_f 是**滚转唯一主控**；它卡死后没有第二条滚转执行通道。
因此 F4 不是“调增益能修”的问题，而是**硬件单点故障**：

- 可做：检测、切油门/受控下降、遥测告警；
- 不可做：保持滚转可控、正常降落；
- 要真正恢复，需要硬件冗余（双滚转舵机/差速滚转/气动副翼）或接受坠机风险。

## 现有证据

| 场景 | 结果 |
|---|---|
| F4 前摆卡死 0.05 rad | 41.3 km / 84° 发散 |
| F4b + 仿真 failsafe | 72 m / 102 m 有界坠落 |
| 固件检测层 | `ActuatorFaultMonitor` 只读接入，`afm_sjam/afm_desc` 遥测 |
| 控制响应 | **未接入**（`g_actuator_controlled_descent_request` 只是标志） |

## 可用方案（按代价）

1. **检测+切油门**（最低成本）：
   - 姿态误差 >25° 且 δ_f 指令饱和持续 0.5 s；
   - 切油门/进入有界下降；
   - 已有检测层，缺执行路径与系留验证。
2. **差速滚转**（需控制分配改造）：
   - 用 Δω 产生滚转力矩，但当前 Δω 是偏航主控，且力矩方向/权限需重新分配；
   - 会牺牲偏航，需重新设计 B 矩阵和权限。
3. **双滚转舵机/副翼**（硬件）：
   - 真正的容错路径；
   - 需要结构/重量/成本评估。

## 安全边界

- 不能在未做系留/单舵机台架前默认启用切油门；
- 检测阈值 25°/0.5 s 只是仿真值，实机需按噪声/机动包线标定；
- 任何自动下降都必须有“飞行员可超控/退出”路径。

## 建议

短期：保留只读检测 + 遥测，做单舵机台架和系留试验；
中期：评估差速滚转的权限与偏航代价；
长期：若任务要求单点故障后可控，必须加滚转冗余。
