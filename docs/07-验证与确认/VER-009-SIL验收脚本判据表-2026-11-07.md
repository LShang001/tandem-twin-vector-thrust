## 2.5 待查：SIL 的 `--rate-gain-scale` 疑似不生效

本轮尝试用它做控制律鲁棒性扫描，发现 0.6 / 1.0 / 1.5 / 2.0 / 3.0 五档下
**所有输出字段完全相同**（`max_roll=11.066`、`pos_rms=0.637`、`nav_att_rmse=3.300`
等逐个字符一致）。缩放到 3 倍仍无任何变化，不像是「场景不敏感」。

已排除的可能：
- **参数解析正确**：`fw_sil_env_main.cpp:2893-2897` 确实置 `rate_gain_scale_set=true`。
- **应用点存在**：`3378-3390` 的 `scale_pid` 直接改 `kFlightCtrlParams`；
  固件分支是 `extern FlightCtrlParams`（运行时可变），不是 `constexpr`
  （`FlightCtrlParams.h:439/442` 用 `#ifdef` 区分固件与宿主测试）。
- **消费端是运行时读**：`flight_control.cpp:2624` 的 `fc.rate_roll.kp`。

**未定位根因**。可疑方向：该读取发生在某个「进入模式」函数里（调用一次），
而 SIL 的缩放在其之后被后续初始化覆盖；也可能该场景根本不走这条控制路径。

> ★ **在根因查清前，不要用 `--gain-scale / --rate-gain-scale / --att-gain-scale`
> 做 A/B 结论**——无法确认参数是否真的作用到了控制律。

## 3 口径提醒
- **共轴必须用 rigorous plant**：`run_coaxial_acceptance.sh` 与 `run_coaxial_suite.sh`
  的 L1 集总 plant 俯仰/姿态约定有误，会误报 `max_pitch≈23°`；用 L1 结果判共轴无效。
- **`final_alt` 判据是 8–11 m，不是「接近 10 m」**：两端都有边界，
  偏低说明定高环没拉住，偏高说明过冲未收敛。
- **失效保护矩阵的 `land_t` 必须为负**：plant 一旦触地就判失败，避免
  「掉到地上但高度指标还勉强够」的假通过。
