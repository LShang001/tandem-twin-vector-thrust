### 1.2 「确认修复所有问题和矛盾」

**做到了的**（按轮次，有实测支撑）：

| 类型 | 典型例子 |
|---|---|
| 真 bug | 共轴 SIL 编译回归（两行声明被合并，坏了两周） |
| 结构性缺陷 | F4 检测的「指令饱和」条件在真实卡死场景永不成立 |
| 单位混用 | 原始共轴固件 `|Roll| > 45.0f`（弧度当度用，联锁从未生效） |
| 覆盖缺口 | 纵列 3-seeds 验收不在跑批里 |
| 文档腐坏 | AGENTS.md 写「7 项」实际 19 项；CTL-007 状态过时；`2/6` 数字已不适用 |
| 静默失效 | `check_coax_parity` 的 `len(vals)<3: continue` 让「没抓到」等于「真一致」 |

**明确没做到的**：

1. ~~**F4 判据仍是结构性的缺陷**~~ → **已修复并烧录上机（Round 224/228）**。
   根因是 NaN 短路（`|nan| > 阈值` 恒为 false → 计时器每拍清零 → 永不触发），
   不是此前猜的「指令到不了 90%」。修复：非有限输入按故障方向处理。
   证据：单测 T13（21/21）、SIL `f4=0→1`、全量 23/23、实机烧录后
   `uptime` 49640→64 且 8 项全过。明细见 VER-009 §2.26 与 VER-010 §5.19。
2. **`NavAidLossDetector` 仍未接线**——有实现、有单测、固件不调用。
3. **3 个模块完全未用 + 2 个仅测试引用**——都已在 `check-module-wiring.py` 登记：
   - 完全未用：`AdaptiveGainDamper`、`AdrcController`、`GenericControlAllocation`
   - 仅测试：`IncrementalPID`、`ins_gnss_pps_latency` 等 9 项
   - `MedianFilter` / `IMU_AutoCalibrator` **不是死代码**（经 `state_data.h` 间接在用，
     只看直接 include 会误判）
4. ~~**迟滞未加**（A-8 剩余项）~~ → **判定为不需要加（Round 231）**。
   实机参数读数：`sedf.att_limit_deg = **120°**`（不是文档里常见引用的 45°）。
   120° 意味着「几乎倒扣才切推进」——正常飞行不可能在 120° 附近来回穿越，
   边界抖动的前提不成立。所以 A-8 的迟滞不是漏项，是**适用条件不满足**。
   （`coax.att_limit_deg` 是 90°，同样远高于正常姿态包线。）

   **顺带核对**：`CoaxialVtvOutputCalibration` 里的默认值 `attitude_limit_deg = 45.0f`
   会不会被误用？查调用点 `flight_control.cpp:2894`，那里是
   `output_cal.attitude_limit_deg = coax.attitude_limit_deg;`——**正确赋值**，
   默认 45° 从未生效。这个默认值只是「结构体字段必须有初值」的产物，
   不是实际口径。
5. ~~**`alpha_ref` 因果链仍未验证**~~ → **部分验证（Round 233）**。
   「不能外推」此前已有实验支持（`-DBFS_RATE_LEAD` 基线 9/9 → 8/9）；
   本轮加探针实测了两者的量级差：`alpha_ref_dps2` 在 −5.5~+4.4 内平滑，
   实测角加速度在 −24.9~+11.8 内跳变——**量级差 3–5 倍**。
   这解释了「为什么不能」：fast MC 的 lead 面对的是噪声水平完全不同的输入。
   **对照实验已做（Round 235/236）**：加开关 `-DBFS_ALPHA_FROM_MEASURED` 做了 A/B，
   3 个种子的方向**不一致**（1 变差、2 变好），所以「换实测会变差」的结论不成立。
   当前能说的是「换输入会改变结果，但方向取决于种子」。

## 2 三个做不到 / 不该做的

1. **「所有问题」不可能穷尽**——本文档只能说「已发现的都处理了」，
   不能证明「没有未发现的」。这个区别必须保留。
2. **不给实飞结论**——本轮没有任何新的飞行数据。用户说固件已飞过，
   本轮的实机测试是地面自检，不能用来支持或否定飞行结论。
3. **不改固件默认行为**——所有改动都在工具层、文档层、SIL 判据层。
   `FlightCtrlParams.h` 的默认值一个没动，`BFS_*` 宏默认状态一个没改。

## 3 一句话总结

**仿真侧**：覆盖从 7 项守卫扩到 **23 项**，其中 **21 项验过能失败**（明细见 VER-009 §2.16），全量 23/23。
**实机侧**：板子连续跑超过 12 小时、跨回绕点超过 10 倍（最新读数见 VER-010 §5.17），8 项自检反复通过。
**问题侧**：§1.2 最初列了 5 项未完成，现在剩 **2 项真实未完成**（`NavAidLossDetector`
待决策、3 模块未用），另 3 项已解决或证明不需要做（F4 已修复上机、A-8 判定不做、
`alpha_ref` 部分验证）。

**没有做到「所有」——做到了「已发现的都有结论，未完成的都写明了」。**
