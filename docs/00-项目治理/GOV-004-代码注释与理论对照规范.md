## 1 目的

1.1 **可读**：读者不打开公式文档，只看代码与注释，就能回答“这段在算什么、单位是什么、坐标系是什么、公式出自哪本书哪一页”。

1.2 **可核查**：每条公式性实现都能通过 `@ref` 定位到教材/论文/项目推导文档，理论核对结论可复查、可审计，而不是“某人说过一致”。

1.3 **可维护**：改代码必须同一次提交改注释；注释腐烂（stale comment）本身按缺陷对待。

1.4 **可教学**：注释面向“第一次读这个项目的人”（低年级研究生、新 Agent、评审专家），承担教材与工程实现之间的翻译职责。

> 一句话原则：**注释解释“为什么”和“从哪来”，代码自己说明“做什么”。**

| 类别 | 例子 | 理由 |
|------|------|------|
| 第三方库 | `lib/eigen/**`、`lib/MAVLink/**`、`lib/ublox-main/**`、`lib/DPS310-Pressure-Sensor/**` 等 | 上游代码，保持原样便于升级比对 |

### 2.3 例外与豁免

- 自动生成文件：在文件头写 `@generated` 并注明生成器与命令，即可豁免 L1/L2 检查。
- 纯数据表（无逻辑）：允许只写 L0 文件头 + 每段数据一个分组注释。
- 确实无法解释的历史遗留：用 `@legacy` 标注并登记到核查报告“待澄清”列表，不得沉默。

## 3 三层注释模型

| 层级 | 位置 | 回答的问题 | 强制程度 |
|------|------|------------|----------|
| **L0 文件头** | 文件最顶部 | 这个文件是什么、属于哪层、实现什么模型、单位/坐标系、有哪些坑与红线 | 每个文件必填 |
| **L1 符号文档块** | 函数/类/结构体/导出常量之前 | 输入输出、单位、公式、文献出处、前置条件、误差/限幅 | 对外符号与复杂内部符号必填 |
| **L2 行内注释** | 关键语句上方或行尾 | 为什么这样写、边界条件、符号翻转、经验常数来源 | 只在“非显然”处出现 |

**L2 的判定标准**：如果删除这行注释，读者需要额外查资料或停下来推导才能明白，则保留；如果注释只是把代码翻译成中文，删除。

## 4 L0：文件头模板

### 4.1 字段表

| 字段 | 必填 | 内容要求 |
|------|------|----------|
| `@file` | 是 | 文件名（与磁盘一致） |
| `@module` | 是 | 所属分层/子系统，如 `core/姿态数学`、`固件/导航`、`GCS/协议` |
| `@brief` | 是 | 一句话职责（≤ 40 字），动词开头 |
| `@details` | 是 | 输入→处理→输出，2–5 行；写清关键不变量与调用方 |
| `@theory` | 理论文件必填 | 本文件实现的公式/模型清单，逐条给出 `@ref`；非理论文件写 `N/A` |
| `@frame` | 是 | 坐标系约定（NED/FRD、机体系/导航系/世界系）；纯 UI/工具写 `N/A` |
| `@units` | 是 | 单位约定（SI、角度 rad/deg、时间 s/ms）；无物理量写 `N/A` |
| `@redline` | 触及红线时必填 | 命中的红线条目（与红线清单逐字对应）；未触及则省略 |
| `@note` | 否 | 依赖、限制、已知偏差、历史决策 |
| `@see` | 否 | 相关文件/文档/测试 |
| `@generated` | 生成物必填 | 生成器路径 + 生成命令 |

## 5 L1：符号文档块

### 5.1 统一标签

| 标签 | 用途 | 示例 |
|------|------|------|
| `@brief` | 一句话功能 | `@brief 由四元数提取 3-2-1 欧拉角` |
| `@param[in/out/in,out]` | 参数名 + 含义 + **单位** + 符号 | `@param[in] dt_s 积分步长 [s]` |
| `@return` | 返回值含义/单位/失败语义 | `@return 姿态角 {phi,theta,psi} [rad]` |
| `@formula` | 该函数实现的公式（单行） | `@formula theta = -asin(R13)` |
| `@ref` | 文献/文档出处（格式见 §6） | `@ref REF-120 §9.2 (9.2.14) p.268` |
| `@pre` / `@post` | 前置条件 / 后置保证 | `@pre 输入四元数已归一化` |
| `@note` | 坑、边界、经验值来源 | `@note 空速下限 0.5 m/s，低于此值分母保护` |
| `@deviation` | 与理论/文档不一致的已知偏差 | `@deviation 用级数重力式，与 (7.2.17) 差 ~1e-5 m/s²` |
| `@approx` | 有意的近似及量级 | `@approx 忽略 F(β,P)，量级 ≤1e-9` |
| `@test` | 覆盖该符号的测试 | `@test test_host/test_ekf_15state.cpp T7` |

### 5.2 何时必须写

- 所有导出/公有函数、类、结构体、枚举（有物理语义时）。
- 所有超过 10 行的内部函数。
- 所有带物理意义的常量与参数表（可分组写一个块，逐项注释单位）。
- 简单 getter/setter：允许一行 `///< 单位/含义` 行尾注释。

### 5.3 示例（C++）

```cpp
/**
 * @brief 由双子样角增量与速度增量递推 15 状态误差协方差
 * @param[in] dtheta_1 第 1 子样角增量 [rad]
 * @param[in] dtheta_2 第 2 子样角增量 [rad]
 * @param[in] dv_1     第 1 子样速度增量 [m/s]
 * @param[in] dv_2     第 2 子样速度增量 [m/s]
 * @param[in] dt_s     更新周期 [s]
 * @return 无；就地更新 state_ 与 cov_
 * @formula ΔV_scull = (2/3)(Δθ₁×ΔV₂ + ΔV₁×Δθ₂)
 * @ref REF-120 §9.6 (9.6.25) p.301
 * @pre 两个子样时间等分，dq 已含圆锥补偿
 * @test test_host/test_ekf_15state.cpp T7
 */
```

## 6 理论对照注释（本规范核心）

### 6.1 标准公式块

凡是实现教材/论文公式的位置，按下列五段式写；短公式可压缩为一行 `@formula` + `@ref`。

```cpp
// ── 速度更新（比力方程在 NED 下的离散形式）────────────────────────────
// 公式：V̇^n = C^n_b·f^b − (2ω_ie + ω_en)×V^n + g^n
// 符号：V^n 导航系速度 [m/s]；C^n_b 机体系→导航系 DCM；
//       f^b 比力 [m/s²]；ω_ie 地球自转 [rad/s]；ω_en 传输率 [rad/s]；
//       g^n 正常重力 [m/s²]（NED 下 z 分量向下为正）
// 来源：@ref REF-120 §7.4 (7.4.6) p.189
// 实现：本函数中 `v_mid = v_prev + (a_sf + a_cor + g)*dt` 一段
// 等价变换：秦书为 ENU/RFU，本项目为 NED/FRD；分量次序与 ± 号见 MOD-002 §2
// 数值证据：@test test_host/test_ekf_15state.cpp T7（速度增量残差 1.25e-4）
// ─────────────────────────────────────────────────────────────────────
```

**五段式要求**：公式（可抄成 ASCII/Unicode）、符号与单位、出处、实现映射（函数名或段落，不写死行号）、等价变换与数值证据。五段缺一不可（无变换/证据时写“无”）。

### 6.2 引用格式（强制）

| 类型 | 格式 | 示例 |
|------|------|------|
| 教材 | `@ref REF-120 §章节 (式号) p.印刷页` | `@ref REF-120 §9.6 (9.6.19) p.298` |
| 教材（无式号） | `@ref REF-121 §2.2.1 p.33` | `@ref REF-121 §2.2.1 p.33` |
| 项目推导 | `@ref THY-00x §n` | `@ref THY-003 §4` |
| 建模/控制文档 | `@ref MOD-00x §n`、`@ref CTL-00x §n` | `@ref MOD-002 §3` |
| 论文 | `@ref TandemVec-Paper/ch05 (5.12)` | `@ref TandemVec-Paper/ch05 (5.12)` |
| 代码位置 | 反引号写符号名，不写行号 | `` `PropagateStateFromIncrements()` `` |

规则：

1. 页码一律用**印刷页**（REF-120 印刷页 = PDF 页 − 8；REF-121 见 `notes/02` 页偏移说明）。
2. 无法确认页码时，至少写“章节 + 式号”，**禁止**只写“见书/见文献/参考教材”。
3. 引用项目文档必须用编号（GOV/MOD/CTL/THY/REQ/VER/COMM/PROTOCOL），便于全站检索。
4. 引用其他代码用符号名，**不写行号**（行号随重构漂移，是注释腐烂的高发点）。

### 6.3 等价变换必须写明

教材与本项目坐标约定不同（秦书 ENU/RFU，本项目 NED/FRD；误差角 φⁿ vs δβᵇ；δ 方向取反），符号看起来“对不上”不等于实现错误。凡做过变换，必须写明：

```cpp
// 等价变换：φ = C^n_b·δβ（秦书 φ 为导航系失准角，固件 δβ 为体系右乘误差）
//           秦书 δ = 计算值−真值，固件 δv = 真值−估计，故速度项相差一次取反
```

### 6.4 近似与偏差

- 有意的截断/近似：`@approx <忽略了什么> <量级> <为什么可接受>`。
- 已确认的偏差：`@deviation <现象> <量级/影响> <依据> <处置：保留/待修/已登记>`。
- 偏差必须同步登记到 `docs/04-数学建模/代码理论核查/` 对应模块记录，**不得用注释掩盖**。

### 6.5 数值证据优先

“手算过/应该没问题”不算证据。优先引用：单元测试断言、回归基线夹具、宿主测试编号（T1/T2…）、复算脚本输出。无测试时，在核查记录里给出可复算命令。

## 7 单位、坐标系与符号

### 7.1 强制约定

| 项目 | 约定 |
|------|------|
| 单位制 | SI；角度内部一律 rad，UI/日志可用 deg 但变量名必须带 `_deg` |
| 时间 | 秒 `_s`，毫秒 `_ms`；帧周期、时间戳必须标明基准（上电/Unix/单调） |
| 坐标系 | 默认 NED（导航系）+ FRD（机体系）；世界系/摆座系/电机系必须显式写出 |
| 符号 | 与 [MOD-002](../04-数学建模/MOD-002-坐标系与符号约定.md) 符号表一致：`q`、`C_n_b`、`ω`、`f`、`δ`、`Δω` |
| 后缀 | `_raw` 原始、`_est` 估计、`_cmd` 指令、`_ned`/`_body` 坐标系、`_deg`/`_ms` 单位 |
| 执行器语义 | 同时写“体轴映射”和“构型语义”：上摆 δf→体轴 x（滚转）、下摆 δt→体轴 y（俯仰）、差速 Δω→体轴 z（偏航）；悬停构型语义见 AGENTS.md 轴映射踩坑记录 |

### 7.2 姿态角约定（易错，必须写）

- 3-2-1 顺序，`theta = -asin(R13)`（项目约定，见 MOD-002 §3）。
- 四元数右乘：`q̇ = ½·q⊗[0,ω_b]`；误差状态为体轴右乘 `q_true = q_est⊗Exp(δβ)`。
- 渲染力臂 ≠ 物理力臂（±1.78 m vs 0.315 m），注释不得混用。
- **两套轴名必须显式区分（2026-10-23 核查新增）**：
  - 固件源码 / `TandemVec_Config.h` / `flight_control.cpp` mix 层使用**存档系**：`z_b = 推力轴 = 机身纵轴`（悬停时竖直指地），`x_b/y_b` 为两条横向轴；
  - 仿真 `TandemVec_Propulsion.h` / `MOD-001` / `CTL-001 §3` 使用**模型系**：`x' = 推力轴`，`y' = 尾摆轴`，`z' = 前摆轴`；
  - 两套轴名固定置换 `x' = −z_b, y' = +y_b, z' = +x_b`（det=+1，见 `flight_control.cpp` mix 层与 `TandemVec_FCS/AGENTS.md`）。写轴/通道注释时必须注明“存档系”或“模型系”，**不得只写 x/y/z**；悬停构型语义（上摆=滚转 / 下摆=俯仰 / 差速=偏航）另见根 AGENTS.md 轴映射踩坑记录。

## 8 L2：行内注释规则

### 8.1 应该写

- 单位换算与量纲（`deg→rad`、`µs→归一化`）。
- 符号约定与翻转（`NED 下 z 向下，故取负`）。
- 边界/奇异保护（`低速分母保护：空速下限 0.5 m/s`）。
- 经验常数来源（`0.28 s 为电机一阶时间常数，来源：台架辨识`）。
- 时序/并发假设（`本函数在 200 Hz tick 内调用，禁止阻塞`）。
- 与理论不同的工程取舍（`用中点姿态，二阶精度，理由见 @deviation`）。

### 8.2 禁止写

| 反例 | 问题 | 改法 |
|------|------|------|
| `// i 自增` | 复述代码 | 删除 |
| `// 定义变量 x` | 零信息 | 删除或写用途 |
| `// 这里很重要` | 无信息 | 写清为什么重要 |
| `// 暂时这样，以后再说` | 无 owner/日期/条件 | `TODO(name, 2026-10-23): …` 或删除 |
| `// 旧实现：...（整段注释代码）` | 注释掉的代码 | 删除，git 保留历史 |
| `// 见书` | 不可追溯 | 补 `@ref` 章节/式号/页码 |
| emoji/颜文字 | 编码与检索问题 | 删除 |

### 8.3 风格

- 中文注释使用中文标点；技术名词、变量名、单位符号保留英文/符号。
- 注释与代码同缩进；段落分隔用 `// ── 标题 ──` 或空注释行。
- 单行 ≤ 120 字符（含中文按显示宽度宽松处理，机检按字符数）。
- 不使用制表符对齐。

## 9 禁止项（机检规则）

| 编号 | 禁止项 | 级别 | 处理 |
|------|--------|------|------|
| R01 | 缺 L0 文件头或必填字段 | error | 补齐 |
| R02 | `@ref` 目标格式非法/无编号 | error | 改为 §6.2 格式 |
| R03 | `TODO/FIXME` 无 `(owner, YYYY-MM-DD)` | error | 补全或删除 |
| R04 | 连续 ≥3 行注释掉的代码 | warning | 删除 |
| R05 | 注释行 > 120 字符 | warning | 换行 |
| R06 | 纯英文注释块（无中文、≥6 词） | warning | 翻为中文 |
| R07 | 理论关键文件无任何 `@ref REF-/MOD-/CTL-/THY-` | error | 补引用 |
| R08 | 公共符号缺 L1 文档块 | warning | 补文档块 |
| R09 | 文件头 `@theory` 非 N/A 却无 `@ref` | warning | 补引用 |
| R10 | 模糊引用（“见书/见文档/参考教材”无编号） | warning | 补编号 |

评分：文件基准 100 分，error −20，warning −5，下限 0。门禁：**error = 0**；warning 数量逐轮下降并记录在核查报告。

## 10 维护规则

1. **同提交原则**：改代码行为/公式，必须在同一次提交内更新相关注释与 `@ref`。
2. **改公式**：同步更新 `@formula`、`@ref`、`@deviation`，并在核查记录中留痕。
3. **红线文件**：触及红线清单的文件，L0 必须有 `@redline`，且改动需按红线流程重采基线。
4. **重构/移动符号**：更新所有 `@see`、核查记录、追溯矩阵中的符号名（不写行号）。
5. **新增模块**：先写 L0 + 关键公式引用，再写实现；核查记录新增一节。
6. **注释腐烂检查**：发版前跑 `py -3.12 tools/check-code-comments.py --check`；核查报告随版本更新。
7. **禁止批量脚本改注释**：跨文件机械替换需人工复核，避免误改字符串/正则/协议字段。
