# DEC-002 六项 P0 的修复决策与验证

## 状态

已接受

## 日期

2026-10-23

## 背景

2026-10-23 全仓“代码-理论对照核查”在 [MOD-004](../04-数学建模/MOD-004-代码理论对照核查报告.md) 中登记了 6 项 P0。它们分两类：

- **固件（2 项）**：F3 单发推力损失判据的垂直速度误差符号相反（C-01）；惯量交叉耦合前馈把存档系角速度/角动量传给模型系函数（C-02）。二者都只在“前馈/诊断层”，首飞未致失控，但会漏报故障、污染调参与诊断。
- **研究仿真（4 项）**：`ekf_core` 旋转效应双计（A-01）；P0 航向仍为 π（A-02）；`initialize()` 未设置 `home_lla`（A-03）；25° 配平口径与固件 15° 限幅冲突（A-04）。

用户要求“深入研究清楚 6 项 P0 应该怎么处理最好，然后自己决策最佳方案”。本决策记录给出逐项依据、选择、实施与验证；原则是：**以固件实码/教材公式为真值，只修确定性错误，不碰红线参数（增益、限幅、差速公式、轴映射），每项都要有可复跑的回归证据。**

## 决策

### C-01 F3 垂直速度误差符号

**决策**：把符号契约收口到监测器头文件，新增

```cpp
bfs::thrustLossVerticalVelocityError(vertical_vel_mps, target_vertical_vel_mps)
// e_v = measured − target；下沉为负
```

`flight_control.cpp::updateActuatorFaultDiagnostics` 改用它，并把 F3 限定在 `AUTO_ALTITUDE / AUTO_POSITION / GUIDED`（手动模式 `target_vertical_velocity` 是上次自动模式的陈旧值，不能参与判据）。监测器 `update()` 增加默认 `thrust_detection_enabled=true` 参数，手动模式显式传 `false`，只重置 F3 计时器、不影响 F4。

**不选择的方案**：把监测器判据改成 `> +1.0`（会让“爬升”变成故障语义，且与现有测试/注释冲突）；在调用方就地相减（同一符号契约仍分散在两处，易再次写反）。

**阈值保持 0.75（2026-10-23 修正）**：SIL 里修好符号后 F3 仍不触发——本机 SIL 悬停油门约 45–50%，自动定高在 12.5 m/s² 加速度限幅下最大指令约 57%，75% 门限在 SIL 中不可达。但**实飞 PID/门限是飞行验证基线，不用未标定仿真反向覆盖**：`thrust_throttle` 保持 **0.75**，SIL 观察只作为“F3 可能在当前气动/油门水平下失效”的风险登记，是否参数化/下调须等实机悬停油门与故障日志。T4b 边界测试相应锁定 0.75（0.74 不触发 / 0.76 触发）。下沉误差 −1.0 m/s、持续时间 1.0 s 与 F3/F4 优先级保持不变。

### C-02 惯量前馈跨坐标系

**决策**：保留 `computeInertiaCompensation()` 作为**模型系**（x′=推力轴）纯函数，新增存档系封装：

```cpp
computeInertiaCompensationFromArchive(omega_archive,
    I_roll, I_pitch, I_yaw_axial, h_along_thrust, mask)
// ω′=(−ωz, ωy, ωx)、h′=(h,0,0)、I′=(I_axial, I_pitch, I_roll)
```

mix 层改用它，输出已是模型系，直接 `Mx+=ff.Mx_ff; My+=ff.My_ff; Mz+=ff.Mz_ff`，删除原手写 `-ff.Mz / +ff.My / +ff.Mx` 置换。惯量入参按语义取 `P.Iz`（滚转）、`P.Iy`（俯仰）、`P.Ix`（推力轴）；本机后两者数值相同，但语义正确才能在参数分化后仍成立。

**不选择的方案**：①在调用方手写置换后直接调模型系函数（置换散落在业务代码，难测试）；②保持“存档系输入 + 存档系惯量”并用现有映射（需要给 `h` 一个负 z 分量，符号更绕）。封装方案把唯一一次坐标变换放进可单测的头文件函数。

**为什么不直接关闭前馈**：`inertia_comp_mask` 默认全开是既有设计；关闭会掩盖问题并损失机动补偿。修复后仍保留在线 A/B 能力。

### A-01 仿真旋转效应双计

**决策**：删除 `time_update()` 里的 `0.5·Δθ×ΔV`，新增 `two_sample_delta_v()` 统一双子样增量（`ΔV + (2/3)(Δθ1×ΔV2 + ΔV1×Δθ2)`），与固件 P0-0 修复后语义一致。

**依据**：REF-120 §9.6.1 (9.6.17) p.298 的 `½Δθ×ΔV` 是配合**区间起始姿态**的旋转补偿；本仿真用**中点姿态** `Cnb_mid` 旋转，半程旋转已包含，再叠加即双计。单步多算量 `½|ω×f|dt²` 已由 `verify_p0_fixes.py` 数值锁定。

**影响**：此前用该仿真得到的动态段速度/位置数字（notes/05、优化研究报告）需按新口径复核；本决策不追溯重跑全部历史场景，改为在报告中明确“旧数字口径”。

### A-02 仿真 P0 航向

**决策**：`ekf_core.cfg_p0["hdg"]` 与 `opt_ekf.FW["p0_hdg"]` 默认改为 **0.2 rad**（固件 2026-10-21 修复值）。π 只保留为显式覆盖（`spec["p0_hdg"]=π`）用于复现历史失效链。

**理由**：默认参数必须代表当前固件；旧 π 是已废止的失败配置。候选基线 `CUR_SPEC` 本来就是 0.2，本次只是把默认值对齐，减少“忘记覆盖”导致的假失败。

### A-03 仿真 `home_lla`

**决策**：`Ekf15.initialize()` 设置 `self.home_lla = self.lla.copy()`；外部脚本仍可在初始化后覆盖为不同起飞点。

**理由**：`measurement_update_gnss()` 的 NED 位置观测以 `home_lla` 为参考；缺省时直接调用会 `AttributeError`。初始 LLA 天然是合理起飞点，设为默认不改变任何显式设置 `home_lla` 的脚本行为。

### A-04 15° 限幅下的巡航配平

**决策**：**不改** `aircraft-model.json` 的 `vTrim=28 m/s`、`dMax=25°`，也**不放宽**固件 15° 限幅；改为把“模型概念窗口”和“固件包线”显式分开：

1. `scripts/trim_solve.py` 新增 `--dmax-deg`、`--scan`，按固件限幅逐速度判定；
2. MOD-003 §3.2 与 ASM-017 写入 15° 可行包线：**下限约 29.8 m/s，30–40 m/s 可行**（30 m/s 时 dt=−14.76°）；
3. 明确“不是降速就安全”：低于阈值尾摆需求反而增大；28 m/s 若必须使用，只能放宽限幅（需硬件复核）或重新设计配平。

**理由**：改 `vTrim` 会触发参数红线与回归基线重采，且 28 m/s 是模型/论文多年口径；改固件限幅需要舵机行程/结构复核，不能在代码层拍板。把事实与包线写清、给出可复算工具，是风险最低且可执行的处置。

## 备选方案

| 方案 | 说明 | 采纳/否决理由 |
|------|------|---------------|
| 全部只登记、不改代码 | 保持“核查轮”零行为变化 | 否决：用户明确要求处理；C-01/C-02 是确定性符号/坐标系错误，继续保留会持续漏报/污染诊断 |
| 只改仿真、不改固件 | 先让分析链自洽 | 否决：F3 与惯量前馈是真实固件缺陷，且修复范围小、可 host 回归 |
| 直接改固件限幅到 20° 解决 28 m/s 配平 | 让模型配平点可用 | 否决：限幅属硬件/安全红线，需舵机行程、结构、实机验证；不能用代码决策替代 |
| 改 `vTrim` 到 30 m/s | 让模型与 15° 包线一致 | 否决：触发参数红线、重采全部回归基线，且论文/历史数据口径全变；本轮不扩范围 |
| 关闭惯量前馈（mask=0） | 规避跨系错误 | 否决：掩盖问题、损失机动补偿；修复后仍保留在线 A/B |

## 后果

### 正面影响

- F3 在真实下沉时能触发，手动模式不再用陈旧目标误判；F3/F4 判据仍只做诊断，不改变操纵。
- 惯量前馈在机动段回到正确通道；跨系置换被封装并可单测，后续参数分化不会再次出错。
- 研究仿真默认口径与固件一致（旋转项、P0 航向、home_lla），减少“仿真通过/实机失败”的口径噪声。
- 15° 巡航包线有可复算数字（≥29.8 m/s），避免把 28 m/s 配平点直接用于实机。

### 代价与风险

- C-02 改变机动段前馈力矩（示例 ω=(0.5,0.3,1.0)、h=0.005 时模型系差异约 0.019 N·m）；**尚未实机 A/B**，建议首飞前做 `inertia_comp_mask=0/0x03` 对照，并保持低杆量。
- C-01 只改诊断，但 F3 标志现在会真正出现；地面站/飞手需知道“ThrustBoost 只是建议、无自动执行”。
- A-01/A-02 使旧仿真数字口径变化；历史报告中的速度/位置结论需标注“旧口径”。
- A-04 的 30 m/s 方案只剩约 0.24° SAS 增量裕度，**不代表可安全巡航**；仍需控制裕度评估与实机包线试飞。

## 仿真验证（2026-10-23 追加，详见 [P0 修复仿真验证](../04-数学建模/代码理论核查/P0修复仿真验证-2026-10-23.md)）

- **C-02 温和耦合 SIL A/B**：3 seed 中 mask=3 未劣化（seed1 滚转峰值 2.08° vs 3.37°），仍待实机 A/B。
- **A-04**：15° 可行区间 30.00–40.00 m/s，阈值约 29.8 m/s。

## 回滚方式

- C-01：`git revert` 对应提交即可；F3 仅诊断，回滚不影响操纵。
- C-02：可先 `inertia_comp_mask=0` 在线关闭前馈（无需回滚代码）；确认方向后再启用。
- A-01/A-02/A-03：改回默认值/保留 `home_lla` 显式赋值即可；均不影响固件。
- A-04：纯文档与工具，无运行时回滚需求。
