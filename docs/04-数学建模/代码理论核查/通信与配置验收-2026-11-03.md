# 通信与配置验收（2026-11-03，上板）

> 对象：TandemVec_FCS 默认飞行固件，板载 NEO-F10N + 香橙派 Serial5 +
> 荣耀本 Serial6。室内弱信号，GNSS `fix=0` 属预期，不参与定位精度判定。

## 1. GNSS（UART4，921600）

`ubxcfg status`（重启后）：

```
detect=YES baud=921600
prt=OK rate=OK msg=OK/OK val=OK nav5=OK gnss=OK sbas=OK save=OK verify=OK 帧=4 ack=4
```

`ubxcfg monver`：`EXT SPGL1L5 6.00 (041e8a)`、`protver=40.00`。

静默 60 s 后 `ubxstat`：

```
rx_bytes=82584 valid_msgs=1784
bad_pvt=4 bad_other=1
pvt=594 eoe=596 eoe_no_pvt=5
queued=591 queue_overflow=0
```

**根因/修复**：921600 下 UART4 RX 中断优先级不足，字节间隔 10.8 µs，
被其他中断延迟即丢字节，曾出现 `bad_pvt≈25%`。`Serial4.begin(921600)` 后
`NVIC_SetPriority(UART4_IRQn, 0)` 解决。详见踩坑记录 2026-11-03 条。

## 2. Serial5 上行（香橙派 → 飞控）

- 香橙派 100 Hz、20 s 发 14 B 帧：`sent=1961`
- 飞控 `health`：`uplink rx=1887 bad=0 age_ms=3896 txskip=0`
- 送达率 ≈ **96.2%**，坏帧 0；缺失在香橙派 USB 串口发送侧，不是解析错误。
- 500 Hz 批量（10 帧/20 ms）复测：发 9370、收 9137，送达 **97.5%**、
  bad=0；同样无解析错误。UART5 RX 中断已提到最高优先级（与 UART4 同策略），
  对吞吐无副作用。

## 3. Serial6（AnoCom 地面站）

- `link`：遥测 **725 帧/s**，坏帧累计 **0**，参数数量/读值/读信息/写回
  全部 5/5，结论“链路健康”。
- `device`：164 参数在位。

## 4. 配置持久化

- `ubxcfg save` 后重启，GNSS 仍 `baud=921600` 且全项 OK，说明波特率/
  消息速率已固化到接收机。
- 固件默认 env 保持 921600 目标；输入异常时自动留在已检测波特率，不切死链路。

## 5. 未覆盖

- CAN、CRSF（接收机未上电）未纳入本次验收。
