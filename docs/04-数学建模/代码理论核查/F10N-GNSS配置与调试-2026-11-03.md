# F10N GNSS 配置与调试（2026-11-03）

> 对象：u-blox **NEO-F10N**（EXT SPG 6.00，protocol 40.00）+ 本仓库飞控
> `TandemVec_FCS` 的 UBX 配置/解析/调试链路。
> 资料：REF-175（数据手册）、REF-176（集成手册 R04）、REF-177（F10 SPG 6.00
> 接口说明 R02）；旧 CFG-MSG 8 字节定义另见 F9 HPG 1.30 §3.10.10（p.72）。
> 本文所有结论均来自上述原文或本机实测，实测命令见 §6。

## 0. 结论摘要

1. **F10 的正确配置入口是 UBX-CFG-VALSET + `CFG-MSGOUT-*` 键**，不是
   CFG-MSG。F10 接口说明里已没有 `UBX-CFG-MSG` 章节（protocol 40.00，
   CFG-MSG 自 >23.01 起 deprecated）。
2. **CFG-MSG 8 字节 payload 的端口字段必须分清**：
   `msgClass, msgID, rateDDC, rateUART1, rateUART2, rateUSB, rateSPI, reserved`。
   本项目旧实现把 rate 只写进 `rateDDC`，UART1/2 为 0，接收机仍回 ACK，
   但串口上 **NAV-PVT 永不输出**。这是“`ubxcfg status` 全 OK、`ubxstat`
   的 `pvt=0`”的根因（2026-11-03 实测复现并修复）。
3. F10N 默认 UART 为 **38400 8N1、无流控**；默认输出 NMEA V4.11；默认星座
   GPS+Galileo+BeiDou+SBAS；多星座 10 Hz、单星座可 20 Hz。
4. **ACK 不等于输出**：配置后必须看 `ubxstat` 的 `pvt/eoe` 计数是否增长，
   不能只看 `ubxcfg status` 的 `msg=OK`。
5. 室内/无天线时 `fix=0` 是正常的，但 NAV-PVT 应持续输出；`ubxcfg ant`
   报 `SHORT/OPEN` 时应先查天线/馈线，不要把 `fix=0` 归因于解析器。

## 2. UBX 配置模型（F10 口径）

### 2.1 CFG-VALSET（推荐）

载荷（REF-177 §3.10.5 p.56）：

```
version(1B)=0x00
layers (1B): bit0=RAM, bit1=BBR, bit2=Flash
reserved(2B)
重复: key(4B 小端) + value(1B)
```

本项目用到的键（REF-177 §4.9.10 p.142–143）：

| 键 | 值 | 含义 |
| --- | --- | --- |
| `CFG-MSGOUT-UBX_NAV_PVT_UART1` | `0x20910007` | NAV-PVT 在 UART1 每 N 个导航解输出一次；1=每历元 |
| `CFG-MSGOUT-UBX_NAV_EOE_UART1` | `0x20910160` | NAV-EOE 同上，用于历元配对 |

固件实现：`src/ubx_config.cpp::_cfg_valset_pvt_eoe_uart1()` 一次 VALSET 写两个键，
`layers=0x01`（RAM）。`ubxcfg status` 的 `val=OK` 表示接收机 ACK。

### 2.2 CFG-MSG（接口说明未收录；实测兼容层）

**基准澄清（REF-177 审计）**：F10 SPG 6.00 接口说明的消息总表只有 5 条 CFG
（CFG-CFG/RST/VALDEL/VALGET/VALSET），**没有 UBX-CFG-MSG、CFG-PRT、MON-HW**。
因此 CFG-MSG 不是 F10 的文档路径；本文保留它是因为**实测仍被接收机 ACK**，
且本板旧固件正靠它恢复 PVT 输出。长期必须迁到 VALSET。

8 字节 payload 的端口顺序（来自 F9 兼容文档 §3.10.10 p.72，不是 F10 文档）：

```
msgClass | msgID | rateDDC | rateUART1 | rateUART2 | rateUSB | rateSPI | reserved
```

**关键坑**：旧实现写成 `{cls,id,rate,0,0,0,0,0}` → rate 落在 DDC，UART1/2 为 0。
F10 对 CFG-MSG 仍回 ACK（兼容层），于是出现：

- `ubxcfg status`：`msg=OK/OK`（配置被接受）
- `ubxstat`：`valid_msgs` 持续增长，但 `pvt=0`、`eoe=0`
- `last cls=0x1 id=0x4`（NAV-DOP，接收机默认输出之一）——证明链路/解析都正常

修复：`{cls,id,rate,rate,rate,rate,0,0}`（DDC/UART1/UART2/USB 同速率）。
实测修复后 `pvt=110`、`eoe=115`，且 VALSET `val=OK` 双路径同时生效。

### 2.3 相关消息长度

| 消息 | 长度 | 说明 | 来源 |
| --- | --- | --- | --- |
| UBX-NAV-PVT | **92 B** | fixType/numSV/hAcc/vAcc/sAcc/pDOP 等 | REF-177 §3.14.11 p.102 |
| UBX-NAV-EOE | **4 B** | 历元结束标记 | REF-177 §3.14.5 p.97 |
| UBX-MON-VER | 可变 | boot/PROTVER/ANTSUPERV | REF-177 §3.13.9 p.94 |

固件解析器 `lib/ublox-main/src/ubx.cpp` 对 PVT/EOE 按 `len` 严格匹配后配对，
`nav_pvt_count()` / `nav_eoe_count()` / `queue_overflow_count()` 可经 `ubxstat` 读。

## 4. 实测记录（2026-11-03，荣耀本 COM9 + DAPLink）

| 步骤 | 结果 |
| --- | --- |
| 旧固件 `ubxstat` | `valid_msgs=7958`，`pvt=0`，`eoe=0`，last `cls=0x1 id=0x4 len=18` |
| 只改 CFG-MSG 端口后 | `pvt=58`，`eoe=75`，`eoe_no_pvt=17`，`queued=58`，`queue_overflow=17` |
| 加 VALSET 后 `ubxcfg status` | `prt=OK rate=OK msg=OK/OK val=OK nav5=OK gnss=OK sbas=OK verify=OK` |
| 加 VALSET 后 `ubxstat` | `pvt=110 eoe=115 eoe_no_pvt=6 qovf=16 last=0x1/0x61/4` |
| `ubxcfg ant` | `antenna: SHORT/OPEN`（未接天线，fix=0 的物理解释） |
| `gpsproto` | `protocol=AUTO fix=0 sv=0 age_ms=0`（无天线/室内） |

> `queue_overflow=16` 出现在上电初期：epoch 队列在导航任务开始消费前已填满。
> 当前不影响运行（随后 `q=0`），但值得后续在初始化阶段限流或扩大队列。

## 6. 调试命令速查

```text
tvc --port COM9 dbg "ubxcfg status"     # 配置结果：prt/rate/msg/val/nav5/gnss/verify
tvc --port COM9 dbg "ubxstat"           # 解析：pvt/eoe/qovf/last cls-id-len
tvc --port COM9 dbg "gpsproto"          # 协议/fix/sv/NMEA 统计
tvc --port COM9 dbg "nmea"              # NMEA 备用链路
tvc --port COM9 dbg "ubxcfg ant"        # 天线 SHORT/OPEN
tvc --port COM9 dbg "health"            # 一屏：IMU/气压/GNSS/EKF/Serial5
tvc --port COM9 dbg "tasks"             # 任务耗时/迟到/负载
tvc --port COM9 dbg "ubxcfg msg pvt 10" # 运行期改 PVT 速率（CFG-MSG 兼容路径）
tvc --port COM9 dbg "ubxcfg nmea"       # 重跑 UBX+NMEA 混合配置
```

判据：

- `pvt/eoe` 持续增长 = 接收机在输出、解析器在收；
- `fix=0` 但 `pvt` 增长 = 无星/无天线，不是解析故障；
- `val=OK` 且 `pvt>0` = F10 VALSET 路径正常；
- `val=NA` 但 `msg=OK` 且 `pvt>0` = 老接收机兼容路径正常；
- `pvt=0` + `last id=0x04` = 报文速率配置未落到 UART1（本文的坑）。

## 7. 待办与风险

1. **天线**：当前 `SHORT/OPEN`，无法验证定位精度；接合格双频 L1/L5 天线后
   复测 `fix/sv/hAcc/vAcc`。
2. **初始化队列溢出**：`queue_overflow=16` 需要确认导航任务启动顺序，必要时
   上电初期丢弃/限流，而不是扩大 RAM 队列掩盖问题。
3. **CFG-MSG 兼容路径**：F10 文档已无 CFG-MSG，长期应只依赖 VALSET；老 M8N
   仍需 CFG-MSG，保留双路径并分别验证。
4. **MON-VER 查询**：建议增加 `ubxcfg monver`，直接读 PROTVER/ANTSUPERV，
   用于确认接收机型号与天线监督能力（接口手册 §3.13.9）。
5. **无磁/无光流**：本机只有 IMU/气压/GNSS，`magcal chip=NONE`、
   `flow sensor=None` 是预期，不是故障；EKF 姿态依赖 IMU+GNSS，无 GNSS 时
   按现有降级策略运行。
