## 1 NMEA 0183 句子结构

### 1.1 帧格式

GPSD 原文：句子由"起始定界符 + 逗号分隔字段 + `*` + 校验和 + 行结束符"组成；
起始定界符通常是 `$`（ASCII 36），AIS 的 AIVDM/AIVDO 用 `!`，且"在 4.00 之前这是唯一允许的起始字符"；
首字段称 tag，通常为**两字符 Talker ID + 三字符语句类型码**；坐标以"度+分（含小数分）"给出；
句子以 `<CR><LF>` 结束。

```
$<TT><SSS>,<field1>,<field2>,...,<fieldn>*<hh><CR><LF>
  │   │      │                             │  │
  │   │      └ 逗号分隔数据字段            │  └ 两位大写十六进制校验和
  │   └ 三字母语句类型（GGA/RMC/GSA/GSV/GBS/GST/VTG/ZDA…）
  └ 两字母 Talker ID（GP/GL/GA/GB/GI/GQ/GN/…）
```

F9 手册每类句子的结构行给出同样的骨架，例如：

- GGA：`$xxGGA,time,lat,NS,lon,EW,quality,numSV,HDOP,alt,altUnit,sep,sepUnit,diffAge,diffStation*cs<CR><LF>`
- RMC：`$xxRMC,time,status,lat,NS,lon,EW,spd,cog,date,mv,mvEW,posMode,navStatus*cs<CR><LF>`
- GSV：`$xxGSV,numMsg,msgNum,numSV{,svid,elv,az,cno},signalId*cs<CR><LF>`

> 注：F9 手册 §2.1 的"帧结构图"是位图，`pdftotext` 抽不出图形，本节结构以 GPSD 文字定义 + F9 各句 Structure 行为准。

### 1.2 校验和（异或范围）

- GPSD：校验和是句子中 `$` 与 `*` 之间**所有字符的 8 位异或**（含 `,` 与 `^`），以两位十六进制、**高位在前**发送；
  校验和是**强制**的，也是句子的最后字段。
- `minmea.c::minmea_checksum`（`minmea.c:29-42`）实现一致：跳过一个可选的 `$`，逐字节 XOR 到 `*` 或 NUL 为止。
- `minmea.c::minmea_check`（`minmea.c:44-86`）额外解析 `*hh`、比较、并只允许尾部出现 CR/LF；
  `hex2int` 同时接受 `A-F` 与 `a-f`（比标准宽一点，工程上无害）。
- **工程要害**：`strict=false` 时允许"没有校验和的句子"（`minmea.c:71-74`），而 `ubx.cpp:557` 正是用 `false` 调用，
  于是"被截断/丢尾的句子"会被当作有效句 —— 见 §8.2 D-02。

### 1.3 字段约定

| 约定 | 内容 | 依据 |
|------|------|------|
| 空字段 | 表示"无有效数据"；u-blox 明确"默认不输出无效数据，而是输出空字段" | F9 §2.5.6 |
| 前导零 | 卫星号/仰角/方位角等常带前导零（`08`、`067`） | F9 §2.7；GPSD |
| 坐标 | `ddmm.mmmm` / `dddmm.mmmmm`，小数点前两位是整分；不含符号，用 `N/S`、`E/W` 定方向 | GPSD §Encoding；F9 §2.5.3 |
| 小数位 | 可变：默认 4 位（`ddmm.mmmm`），兼容模式可少，`HIGHPREC` 为 7 位 | F9 §2.2 |
| 负号 | 只出现在数值字段（高度/残差/磁偏/时区等），不出现在经纬度数值中 | F9 各句字段表 |
| 无效标志 | `status=A/V`、`quality=0`、`posMode=N`、`navMode=1` 等；u-blox 在 `OUT_INVFIX` 打开时**仍输出位置但配 `V`** | F9 §2.5.5、§2.5.6 |

### 1.4 句长与版本

- GPSD：**最大句长 82 字节（含 `$` 与 `<CR><LF>`）**。
- F9 手册中"82"是**可配置的严格上限**：`CFG-NMEA-LIMIT82` "Enabling this mode will limit the NMEA sentence length to a maximum of 82 characters"，
  而该配置默认值是 `0 (false)`（配置默认表 `CFG-NMEA-LIMIT82 ... 0 (false)`）⇒ **u-blox 出厂允许超过 82 字符**。
- `CFG-NMEA-HIGHPREC` 把经纬度小数位提到 7 位、高度 3 位，并注明**不能与 `COMPAT`/`LIMIT82` 同时设置**（F9 §2.2）。
  按字段估算，7 位小数 + 三位高度的高精度 GGA 约 88 字符，已超 82 —— 所以"82 是标准上限，但不是 u-blox 的实际上限"。
- 版本差异（影响解析器必须容错的地方）：
  - NMEA 2.3 起 RMC/GLL/VTG 末尾增加 FAA mode 字段；4.10 起 RMC 再加 `navStatus`；
  - 4.10 起 GBS/GNS/GRS 增加 `systemId`+`signalId`，GSA 增加 `systemId`，GSV 增加 `signalId`（F9 §2.5.2）；
  - BeiDou/Galileo 需要 NMEA 4.10+，QZSS 需要 4.11+（F9 §2.4）；
  - F9 默认版本是 **4.11**（配置默认表：`CFG-NMEA-PROTVER = 42 (V411)`），手册 §2 亦声明"默认基于 NMEA 0183 4.11"。

## 2 常用句子字段

> 字段号从 1 开始（不含 `$xxGGA` 标识本身）；"—"表示常为空。全部字段名/含义取自 F9 手册对应小节，GPSD 用于交叉核对。

### 2.1 GGA — 定位与高程（F9 §2.7.5）

| # | 字段 | 单位/格式 | 说明 |
|---|------|-----------|------|
| 1 | time | hhmmss.ss | UTC 时间（无日期！） |
| 2 | lat | ddmm.mmmmm | 纬度 |
| 3 | NS | N/S | 纬度方向 |
| 4 | lon | dddmm.mmmmm | 经度 |
| 5 | EW | E/W | 经度方向 |
| 6 | quality | 0/1/2/4/5/6 | 0 无定位、1 自主、2 差分、4 RTK 固定、5 RTK 浮点、6 推算值（F9 脚注） |
| 7 | numSV | 0–12 | 参与解算卫星数（F9 描述范围 0–12） |
| 8 | HDOP | — | 水平精度因子 |
| 9 | alt | m | **海拔高（MSL）** |
| 10 | altUnit | M | 固定 `M` |
| 11 | sep | m | 大地水准面差距（椭球−MSL） |
| 12 | sepUnit | M | 固定 `M` |
| 13 | diffAge | s | 差分龄期，未用差分时为空 |
| 14 | diffStation | — | 差分基站 ID，未用差分时为空 |

**关键换算**：椭球高 = `alt + sep`。仓库实现正确（`ubx.cpp:655-658`），且对 `sep` 空值做了 0 兜底。

### 2.2 RMC — 推荐最小定位（F9 §2.7.17）

| # | 字段 | 说明 |
|---|------|------|
| 1 | time | UTC 时间 |
| 2 | status | `A` 有效 / `V` 无效 |
| 3–6 | lat, NS, lon, EW | 同 GGA |
| 7 | spd | 对地速度（**节**） |
| 8 | cog | 对地航迹（度，真北） |
| 9 | date | ddmmyy（**RMC 是常规句里唯一带日期的**） |
| 10–11 | mv, mvEW | 磁偏角与方向（常为空） |
| 12 | posMode | N/E/A/D/F/R（NMEA 2.3+，可空） |
| 13 | navStatus | （NMEA 4.10+，固定 `V`） |

RMC 是常用句里**唯一同时带"完整日期 + 速度/航迹"**的句子（GGA 只有时间没有日期；ZDA 有日期但没有速度）。
**仓库只用到 1（时间）、2（状态）、7–8（速度/航迹）**（`ubx.cpp:585-596`、`673-697`）；
坐标以 GGA 为准；`rmc.date` 虽被解析进临时结构体，但**没有进入快照**，等于丢弃。

### 2.3 GSA — DOP 与参与解算卫星（F9 §2.7.13）

| # | 字段 | 说明 |
|---|------|------|
| 1 | opMode | `A` 自动 2D/3D，`M` 手工 |
| 2 | navMode | 1 无定位 / 2 2D / 3 3D |
| 3–14 | svid ×12 | 参与解算卫星号；不足 12 个留空，多于 12 个只输出前 12 |
| 15–17 | PDOP/HDOP/VDOP | 位置/水平/垂直精度因子 |
| 18 | systemId | （4.10+，可选）GNSS 系统号 |

**多系统必读**：F9 §2.4 明确"每星座各输出一条 GSA"（`GPGSA`/`GLGSA`/`GAGSA`/`GBGSA`…），
单系统接收机只输出一条。多系统时若直接用最后一条 GSA 的 PDOP，会被某一星座的几何质量带偏。

### 2.4 GSV — 可见卫星（F9 §2.7.15）

| # | 字段 | 说明 |
|---|------|------|
| 1 | numMsg | 本组总句数（1–9） |
| 2 | msgNum | 本句序号（1–numMsg） |
| 3 | numSV | 本 talker（+Signal ID）下可见卫星总数 |
| 4–7 | svid, elv, az, cno | 每颗星 4 个字段，**每句最多 4 组** |
| — | Signal ID | 4.10 引入（对应 `Table 19`；F9 手册字段名 `signalId`）；4.11 勘误明确**该字段不得为空**（早期称 GNSS System ID，经 # 0183 20190507 / 20190515 改为 Signal ID） |

要点（官方 4.11 原文见下）：
- 每句最多 4 星（F9 与 **NMEA-4.11-ERRATA** 一致）；
- 多系统时一星座一组，talker 为 `GP/GL/GA/GB/GQ/GI`，**`GN` 不得用于 GSV**；
- SNR 是 C/N0（dBHz，00–99），"null when not tracking"；
- 末句可能不足 4 组；4.11 明确"Null fields are not required for unused sets when less than four sets are transmitted"
  （**空字段不是必需的**）⇒ 解析器必须同时容忍"末尾 `,,,`"与"提前结束"两种形态（示例见 `minmea.c:548`）。

**NMEA-4.11-ERRATA 逐字要点**（Technical Bulletin # 0183 20190515 GSV Sentence，正文即 4.11 该章节）：

- "The GSV sentence contains four satellites maximum per transmission. The total number of sentences being
  transmitted and the sentence number being transmitted are indicated in the first two fields."
- "If multiple GPS, GLONASS, Galileo, BDS, QZSS, NavIC (IRNSS) satellites are in view, use separate GSV sentences
  with talker ID GP … GL … GA … GB … GQ … GI …"
- "When more than one ranging signal is used per satellite, separate GSV sentences with a System ID corresponding
  to the ranging signals shall be required."（多信号必须按 Signal ID 再分组）
- "**The GN identifier shall not be used with this sentence.**"
- 注 2："Null fields are not required for unused sets when less than four sets are transmitted."
- 注 3：卫星编号约定——GPS 1–32；SBAS 33–64（PRN = SV ID + 87）；GLONASS 65–96（64 + 槽号，24 星满编 65–88）。
- 注 4："Signal ID according to Table 19. This field shall not be null."
- 分组与计时："use of the NMEA TAG Block structure (§7) and the TAG Block Sentence-grouping Parameter (§7.9.3)
  reliably links the related sentences together"；并建议配发 **ZDA** 以标明星空观测时刻。

### 2.5 GBS — RAIM/伪距残差（F9 §2.7.4）

| # | 字段 | 说明 |
|---|------|------|
| 1 | time | 所属定位的 UTC 时间 |
| 2–4 | errLat / errLon / errAlt | 期望 1σ 误差（m）；**仅 RAIM 通过时输出**，≤4 星参与解算时永不输出 |
| 5 | svid | 最可能故障星号 |
| 6 | prob | 漏检概率（u-blox 固定为空，不支持） |
| 7 | bias | 该星伪距偏差估计（m） |
| 8 | stddev | 偏差估计标准差（m） |
| 9–10 | systemId / signalId | （4.10+） |

语义：`5–8` **只在确实有卫星未通过 RAIM 时输出**，正常定位时是空的 —— 解析器不能把"空"当作 0。

### 2.6 GST — 位置/速度误差统计（F9 §2.7.14）

| # | 字段 | 说明 |
|---|------|------|
| 1 | time | 关联定位的 UTC 时间 |
| 2 | rangeRms | 伪距残差 RMS（m） |
| 3–5 | stdMajor / stdMinor / orient | 误差椭圆长半轴/短半轴（m）与长轴方向（deg） |
| 6–8 | stdLat / stdLong / stdAlt | 纬度/经度/高程误差标准差（m） |

**这是 NMEA 里最直接、最该用于融合加权的精度量**：`stdLat/stdLong/stdAlt` 可直接映射到水平/垂直观测方差，
比"HDOP×UERE"这种假设模型可靠。当前仓库完全没用（见 §8.1）。

### 2.7 VTG — 航迹与地速（F9 §2.7.20）

`cogt,T,cogm,M,sogn,N,sogk,K,posMode`：真航迹/磁航迹/节速/公里时速 + 模式位。
与 RMC 的 `spd/cog` 冗余；多星座接收机里可作为交叉校验。当前未解析（`ubx.cpp:616` 归入 unknown）。

### 2.8 ZDA — 时间与日期（F9 §2.7.21）

`time,day,month,year,ltzh,ltzn`：**唯一给出 4 位年份**的常用句；`ltzh/ltzn` 在 u-blox 上固定 `00,00`。
当前未解析；这也是"只跑 NMEA 时拿不到绝对 UTC 日期"的直接原因之一（RMC 的日期同样被丢）。

### 2.9 精度信息的三层来源（便于设计权重模型）

| 层次 | 字段 | 特点 | 当前使用 |
|------|------|------|----------|
| 几何 | GSA 的 PDOP/HDOP/VDOP、GGA 的 HDOP | 无单位、随星座几何变化 | GGA HDOP→`horz_acc=hdop×2.5`；GSA PDOP→`pvt_pdop` |
| 统计 | GST 的 stdLat/stdLong/stdAlt | 直接是米，含解算内部一致性 | 未使用 |
| 完好性 | GBS 的 errLat/errLon/errAlt、RAIM 标记 | 反映 RAIM 是否通过 | 未使用 |

## 3 Talker ID 多样性与多系统混合

### 3.1 Talker ID 表（F9 §2.5.1，与 GPSD 的 Talker 表一致）

| GNSS | Talker | 备注（F9） |
|------|--------|------------|
| GPS, SBAS | `GP` | NMEA 2.3+ |
| GLONASS | `GL` | NMEA 2.3+ |
| Galileo | `GA` | NMEA 4.10+ |
| BeiDou | `GB` | NMEA 4.10+（4.11 才正式） |
| NavIC | `GI` | NMEA 4.11+ |
| QZSS | `GQ` | 4.11+（2.3–4.10 用 `GP`） |
| 任意组合 | `GN` | 组合解主 talker |

GPSD 补充：`BD`（BeiDou，旧写法）、`QZ`/`PQ`（QZSS 变体）等也可能出现；`P` 前缀是厂商私有（如 u-blox 的 `$PUBX`）。

### 3.2 多系统时协议要求的输出变化（F9 §2.4 原文要点）

1. **主 Talker 变为 `GN`**（除 GSV 外的所有句）；
2. **GSV 的 talker 是系统专属的**（`GPGSV`/`GLGSV`/`GAGSV`/`GBGSV`/`GQGSV`），**不能用 `GN`**；
3. **GSA 与 GRS 每星座各一条**（"one for each GNSS"），会打破"每次定位只有一条"的旧假设；
4. **GGA 按 talker 分别输出**（NMEA 规范里 GGA 本是 GPS 专属，u-blox 支持每个 talker 一条）；
5. BeiDou/Galileo 需 4.10+，QZSS 需 4.11+；
6. 支持"扩展卫星编号"，QZSS 用 193–202 等**三位数**编号，老解析器可能不认。

### 3.3 卫星编号空间

GPSD 汇总（2018 年最佳猜测，u-blox 扩展模式另有一套）：

| 区间 | 归属 |
|------|------|
| 1–32 | GPS |
| 33–64 | SBAS（NMEA-ID = PRN − 87；IMES 另有 173–182） |
| 65–96 | GLONASS（`GL` talker 下是 1–32，`GN` talker 下已是 65–96） |
| 193–202 | QZSS |
| 201–235 | BeiDou（u-blox 扩展编号，非 NMEA） |
| 301–336 | Galileo |
| 401–437 | BeiDou（NMEA 编号） |

F9 的 `CFG-NMEA-SVNUMBERING` 默认 `0 (STRICT)`：**严格模式不给没有 NMEA 编号的卫星编号**；
`EXTENDED` 才用私有编号。所以"同一颗北斗星在两种配置下编号不同"，解析器只能把 `svid` 当不透明标识，
真正做星座归类要靠 Talker ID（或 4.10+ 的 `systemId`），不能靠编号区间硬推断。

### 3.4 对解析器的硬性要求（本项目必须遵守）

1. **不要按 `GP` 过滤**。否则多系统/组合解接收机会一条都收不到（当前 `ubx.cpp` 未过滤 talker，这点是对的）。
2. **GGA 可能多句**：以 `GN` 优先，其次任一 `G*`；同一历元的多条 GGA 只取一条，避免同秒重复刷新。
3. **GSA 可能多句**：`GN` 是组合解，PDOP 用它；单星座句只作兜底 —— 但兜底**必须能持续更新**，
   当前实现只在"还没有 PDOP"时接受，之后永久冻结（§8.2 D-03）。
4. **GSV 必须按 talker（+Signal ID）分组重组**，不能跨星座拼（§4；4.11 官方勘误明确多信号必须再按 Signal ID 分组）。
5. **重复句去重**：多系统接收机同一秒内同类型句会出现多条；按 (talker, type) 维度或按时间戳去重。

## 4 GSV 多句重组

### 4.1 为什么必须重组

单句 GSV 只含最多 4 颗星，而 `numSV` 是整组的总数；只有把 `msgNum=1..numMsg` 全部收齐，
才能得到"本星座本信号"的完整可见星空，用于：
C/N0 质量评估（抗干扰/遮挡）、可见星与参与解算星的一致性检查（欺骗/多路径迹象）、
按仰角加权的观测噪声建模、以及"卫星数骤降"这类故障检测。

### 4.2 建议的重组状态机（键 = talker + Signal ID）

> 4.11 官方约定（NMEA-4.11-ERRATA）：前两个字段分别是"总句数"与"句序号"（均 1–9）；
> 多信号必须按 Signal ID 再分组（"shall be required"）；相关句之间可用 NMEA TAG Block（§7）与
> Sentence-grouping 参数（§7.9.3）显式绑定；并推荐同时输出 **ZDA** 以标明星空观测时刻。
> 注 1 还说明：为效率起见，多句消息中"相对首句未变化的字段"可用空字段 ——
> 因此重组时**不能用空值覆盖已有值**。

```
收到 GSV:
  key = (talker, SignalID)             # 4.11 的 Signal ID 不得为空；缺失时退化为 (talker, -1)
  若 msgNum == 1:                      # 新批次开始
      重置该 key 的组: count=0, svs=[]
  否则若该 key 无进行中的组:
      丢弃（半截批次，无法校验一致性），计 dropped_group++
  否则若 numMsg 与组内记录不一致:
      以新值为准并标记 inconsistent=true（接收机中途改了星数）
  若 msgNum 已在组内（重复句）:
      覆盖该槽位（UART 重传/双端口重复时常见）
  存入该句的 1..4 个四元组（svid, elv, az, cno；空 SNR → NaN；空字段跳过，不覆盖）
  若已收到 numMsg 句  或  距 msgNum==1 超过 T 毫秒:
      交付该组；校验 收集到的 svid 数 == numSV（不等只记诊断，不丢数据）
      若收到 numMsg 句 → 正常交付；否则标记 partial=true 后交付
```

### 4.3 容错规则（本项目的取舍建议）

| 情况 | 建议行为 | 理由 |
|------|----------|------|
| `numMsg` 句中有 1 句丢失 | 用已收到的部分交付，标记 `partial`；不阻塞下一批 | 星图是"软信息"，不值得为完整性牺牲时延 |
| 批次超时（如 2×NMEA 周期） | 交付 partial 并清空，防止半截组吃掉下一批 | 否则下次 `msgNum==1` 才恢复，期间星空全丢 |
| `msgNum` 重复 | 覆盖同槽位 | UART 重传/多端口镜像 |
| `msgNum` 跳号 | 记 gap，等超时后交付 partial | 可能是丢句，也可能是接收机在两句间改变了星数 |
| 同组内出现空字段（注 1 允许） | **跳过，不覆盖已有值** | 4.11 注 1：未变化字段可用空字段 |
| `numSV` 与收集数不一致 | 只记诊断计数 | 接收机在移动中星数会变，属正常 |
| 同一 talker 出现多个 Signal ID | 各自独立成组（如 GPS L1 + L5） | 4.11："separate GSV sentences with a System ID … shall be required" |
| 有 TAG Block（§7.9.3） | 优先用其分组号作批次键，比 `msgNum` 更可靠 | 官方推荐用它跨传输介质绑定相关句 |
| `GN` talker 的 GSV | 规范禁止，但收到也应按 `GN` 单独成组，不丢 | "The GN identifier shall not be used with this sentence"；兼容非标设备 |

### 4.4 现有实现的差距

- `minmea.c::minmea_parse_gsv`（`minmea.c:545-581`）**只解析单句**，结构体里就是 `sats[4]`（`minmea.h:174-180`），
  没有"组"的概念，也没有"本组已收/总句数"的会话状态；
- 结构体**没有 Signal ID 字段**（`minmea.h:174-180` 只有 `total_msgs/msg_nr/total_sats/sats[4]`），
  4.11 的双频/多信号场景无法按 Signal ID 分组；
- `ubx.cpp` 连单句都没调（`ubx.cpp:616` 把 GSV 计入 `nmea_unknown_count_`）；
- 结论：**GSV 全链路缺失**，是"通用 NMEA 解析"最大的一块空白（见 §8.3 D-10）。

## 5 校验和与容错

### 5.1 校验和策略

| 策略 | 说明 | 现实现 |
|------|------|--------|
| 必检 | 无 `*hh` 或校验不符 → 丢弃并计数 | 校验不符会丢弃（`minmea.c:69-70`），但**无校验和句被接受**（`strict=false`） |
| 坏句计数 | 便于诊断链路质量 | `nmea_bad_checksum_count_`（`ubx.h:404`） |
| 大小写 | 标准是大写，容错可接受小写 | `hex2int` 已兼容（`minmea.c:24-25`） |
| 校验范围 | `$` 与 `*` 之间（含逗号） | 一致（`minmea.c:38`） |

**建议**：`strict=true`（校验和必需）。NMEA 标准规定校验和强制；飞行器上"宁缺毋滥"比"多收一条可疑句"更重要。
若要兼容极少数不带校验和的设备，应做成显式编译开关，而不是默认宽松。

### 5.2 空字段与"看似有效"的陷阱

- u-blox 默认**不输出无效数据，而是输出空字段**（F9 §2.5.6）；示例：
  有效 `$GPGLL,4717.11634,N,00833.91297,E,124923.00,A,A*6E`；
  无效（时间有效）`$GPGLL,,,,,124924.00,V,N*42`；时间未知 `$GPGLL,,,,,,V,N*64`。
- 但 `CFG-NMEA-OUT_INVFIX` 打开后，接收机会**输出失效位置并配 `V` 状态**（F9 §2.2）。
  ⇒ 解析器必须**同时检查 status/quality 与字段非空**，只判"字段能解析"是不够的。
- 本仓库 GGA 路径用 `fix_quality >= 1` 作为门槛（`ubx.cpp:568`），这是对的；
  但 `quality=0` 时**不刷新也不失效**，旧快照继续被当作有效（实测 `nmea_valid()` 仍为 1）——见 §8.3 D-06。

### 5.3 负号、小数位、整数溢出

- 负数只出现在值字段；经纬度靠 `N/S/E/W` 定符号，`minmea_tocoord` 用 `degrees + minutes/60` 且保留符号（负值经 `%` 自然带符号，结果正确）。
- 小数位可变（0–7）。`minmea` 用 `{value, scale}` 定点保存，`int_least32_t` 上限约 2.1e9：
  - 4 位小数坐标（`4717.1139` → 47171139）安全；
  - **7 位小数坐标（`4404.1403600` → 4.4e10）溢出**，`minmea.c:174-183` 走"截断多余精度"分支（`break`），
    实测仍能得到正确量级（`value=440414036, scale=1e5`），但**静默丢精度**，且没有任何计数器暴露这件事。
- `'i'` 字段用 `strtol`（`minmea.c:223`）：接受前导空格、超 `long` 范围时按 `LONG_MAX` 截断再赋给 `int`，
  对卫星号/星数这类小整数无实际风险，但不是严格的逐字符整数解析。

### 5.4 超长句

- 标准 82 字节（GPSD）；u-blox 默认**不启用** 82 上限（`CFG-NMEA-LIMIT82 = 0`）。
- `MINMEA_MAX_SENTENCE_LENGTH 80`（`minmea.h:26`）**没有任何代码引用**（全仓库仅上游 README 示例引用），
  实测 `minmea_check` 对 131 字符合法句返回 true ⇒ `minmea` 本身**没有长度保护**，全靠调用方缓冲。
- 调用方缓冲 `kNmeaSentenceBufLen = 96`（`ubx.h:374`），超限丢弃并计 `nmea_overflow_count_`（`ubx.cpp:540-545`）。
  按字段估算：高精度 GGA 约 88 字符、扩展编号 + signalId 的 GSV 约 77–90 字符 ⇒ 96 **偏紧但可用**；
  建议上调到 128 并在文档/静态断言里写清依据，同时保留"超限丢弃 + 重新同步"。

### 5.5 跨 UART 分块到达

`ubx.cpp::nmeaProcessByte`（`ubx.cpp:510-547`）是逐字节状态机：`$` 起始、`\r`/`\n` 结束、缓冲满丢弃、
句中出现 `$` 重新同步。**这个设计与分块到达天然兼容**：不管 UART 一次给 1 字节还是 64 字节，状态都一致。

反面做法（应避免）：`readStringUntil('\n')`/`Stream::readBytes` 阻塞式读整行 —— 在 9600 波特下，82 字符要
**约 85 ms**（10 bit/字符 ⇒ 1.04 ms/字符），阻塞读会直接顶住导航任务；且超时后残句处理容易丢整句或错位。

### 5.6 其他"脏数据"来源

| 现象 | 处理建议 |
|------|----------|
| NMEA 4.x TAG block（`\...*hh\` 前缀，F9 §2.8 "secondary output messages"） | 跳过 `\` 段，只在 `$` 处起句（当前实现靠"非 `$` 字节丢弃"天然兼容，但 TAG 里的 `$` 不存在，安全） |
| AIS 的 `!` 开头句 | 不认，直接跳过（本项目不需要） |
| `$PUBX,00/03/04` 私有句 | 可作补充定位/星空来源，但不应混入标准字段解析 |
| 上电文本/TXT 句 | 丢弃；不要计入"坏校验"（当前会计成 bad_checksum 或 unknown，诊断会脏） |
| 半双工/RS-422 共总线反射 | 校验和会挡住；但要做"连续 N 句坏校验 → 链路降级"判断 |

## 6 与 UBX 共存

### 6.1 同一条字节流里的两种帧

| 协议 | 起始 | 终止 | 载荷 |
|------|------|------|------|
| NMEA 0183 | `$`(0x24) | `<CR><LF>` | 可打印 ASCII |
| UBX | `0xB5 0x62` | 长度字段决定 + 2 字节校验 | 任意二进制（**可含 0x24/0x0D/0x0A**） |

`ubx.h` 中 `UBX_HEADER_ = {0xB5,0x62}`、`UBX_MAX_PAYLOAD_ = 1024`（`ubx.h:414`）。

### 6.2 当前实现的共存方式与隐患

`Ubx::Pump`（`ubx.cpp:244-289`）对**同一个字节**同时喂两个解析器：

```cpp
if (ubx_enabled) { if (ProcessUbxByte(b)) {...} }   // ubx.cpp:263-273
if (nmea_enabled) { nmeaProcessByte(b); }           // ubx.cpp:274-277
```

- 好处：不需要预先判断链路是哪一种，`kAuto` 的实现成本低。
- 隐患：**UBX 帧的二进制载荷里出现 `$` 时，NMEA 切分器会开始收集垃圾句**；载荷里再出现 `0x0D/0x0A` 就"结句"，
  于是产生一条必然校验失败的伪句 ⇒ `nmea_bad_checksum_count_` 被无意义地抬高（诊断失真），并浪费 CPU。
  极端情况下若伪句恰好校验通过（1/256 量级），还会被计入 `nmea_sentence_count_`/unknown。
- 改进（低风险）：给 `nmeaProcessByte` 加一个"UBX 帧组帧中"门控——`ProcessUbxByte` 返回"当前处于帧内"状态时，
  NMEA 切分器直接丢弃该字节；或反过来在 NMEA 切分器里维护"上一帧是否是 UBX"的抑制窗口。
  最彻底的做法是**先做协议分帧、再把完整帧分发给对应解析器**（见 §8.5）。

### 6.3 u-blox 的"UBX + NMEA 混合输出"是怎么配出来的

| 配置项 | 作用 | 依据 |
|--------|------|------|
| `UBX-CFG-PRT` 的 `inProtoMask`/`outProtoMask` | 按位选择本端口启用哪些输入/输出协议；手册明确"Through that, **multiple protocols can be defined on a single port**" | F9 §3.10.15 |
| `UBX-CFG-MSG`（0x06 0x01） | 按 (class,id) 设置 6 个端口的输出率 | F9 §3.10.10 |
| `NMEA-PUBX-RATE`（`$PUBX,40,msgId,rddc,rus1,rus2,rusb,rspi,reserved`） | 按 NMEA 句名设置各端口输出率（0=关闭，1=每历元） | F9 §2.9.3 |
| `CFG-NMEA-PROTVER` | 选 4.11/4.10/4.0/2.3/2.1 | F9 §2.2 / §6.9.15 |
| `CFG-NMEA-LIMIT82` / `HIGHPREC` / `COMPAT` | 句长/精度/兼容模式 | F9 §2.2（默认 LIMIT82=0、HIGHPREC=0、PROTVER=42） |
| `CFG-NMEA-MAINTALKERID` / `GSVTALKERID` / `BDSTALKERID` | 覆盖主/GSV/BeiDou Talker（默认 AUTO/GNSS/0） | F9 §6.9.15 |

**关键事实：`lib/ublox-main` 里没有任何一处向接收机写配置**：`ubx.cpp`/`ubx.h` 中 `CFG_MSG`、`CFG-VALSET`、`PUBX`
出现次数均为 0，也没有任何 `bus_->write(...)`；`ubx_defs.h:87-103` 只定义了端口号（`UBX_COM_PORT_UART1_` 等）与
协议位掩码（`UBX_COM_PROT_UBX_ = 0x01`、`UBX_COM_PROT_NMEA_ = 0x02`），注释即写明"本解析库本身不发配置，
仅在需要构造配置报文的上层代码里作参照"。
⇒ `kAuto` 的"NMEA 兜底"**只在接收机已被外部配置成同时输出 UBX 与 NMEA 时才有效**。
要么在飞控里补一条"配置接收机输出"的初始化路径（CFG-VALSET 或 PUBX,40），要么在文档/参数里明确这是前置条件。

### 6.4 时间戳对齐（RMC/GGA 的 UTC 与 UBX 的 GPS 时）

- GGA 只有时间没有日期；RMC 有 `ddmmyy`；ZDA 有 4 位年份。**只有 NMEA 时，绝对 UTC 必须由 RMC/ZDA 提供**。
- NMEA 报的是 **UTC**，UBX `NAV-PVT.iTOW` 是 **GPS 周内时**，二者相差 **GPS−UTC 闰秒**
  （2017-01 起为 18 s，此后 IERS 未再插入闰秒；此值需按任务日期复核）。
- 当前实现把 NMEA 的 UTC"日内秒"当作 `pvt_tow_ms`，并写进 `epoch.gps_tow_s`（`ubx.cpp:706`）：
  - 导航层目前只用 `pvt_tow_ms` 做映射/去重，`gps_tow_s` 在全仓库**没有任何消费者**（`src/navigation_task.cpp:1758-1763` 只传 `pvt_tow_ms`）；
  - 但 `UbxEpoch::gps_tow_s` 的注释写的是"GPS 周内秒"（`ubx.h:65`），NMEA 路径实际给的是 UTC 日秒 ⇒ **字段语义被污染**，
    后续一旦有人用它做 GPS 时间/周计算就会错 18 s。
  - `PushEpoch` 每帧都刷新 `latest_epoch_tow_ms_`（`ubx.cpp:486-487`），而 `InsGnssMapEpochToLocalTime` 用
    "与参考帧的 tow 差 ≤10 s"判定参考是否可用（`include/ins_gnss_epoch_timing.h:81-90`）。
    在 `kAuto` 下从 UBX 切到 NMEA 的**第一帧**，两者 tow 差约 −18 s ⇒ 该帧映射退化为"用本帧接收时刻"（仍 valid，
    但丢掉排队延迟修正）；之后参考帧变成 NMEA 自身，恢复正常。影响是**一帧的时延修正损失**，不是错数据，但属于隐式耦合。
- 传输延迟：一串 82 字符在 **9600 波特 ≈ 85 ms**、38400 ≈ 21 ms、115200 ≈ 7.1 ms。
  NMEA 兜底时若沿用 UBX 的 15 ms 延迟先验（见 `docs/.../GNSS接收机延迟调研-2026-11-01.md`）会明显偏乐观。
- 建议：
  1. UBX 可用时**始终以 UBX 的 iTOW/PPS 为时间基准**，NMEA 只作位置/速度补充；
  2. 纯 NMEA 时用 `RMC.date + RMC.time`（或 ZDA）构造 UTC，再按"UTC + 闰秒"换成 GPS 时；
  3. 给 NMEA 单独一套延迟先验（9600 建议 ≥100 ms，115200 建议 10–20 ms），不要与 UBX 混用。

### 6.5 双通道重复融合

`kAuto` 用"最近 UBX epoch 300 ms 内则不合成 NMEA"（`ubx.cpp:780-784`，`ubx.h:379`）避免同一接收机被融两次。
这个思路正确；但要注意：
- 300 ms 窗口对 1 Hz 输出足够，对 5–10 Hz UBX 输出也足够；
- 若接收机 NMEA 与 UBX 的**历元相位**错开（NMEA 在整秒后 200 ms、UBX 在整秒后 10 ms），窗口内仍会抑制，行为正确；
- 若 UBX 丢帧但链路没死（例如只丢了 NAV-EOE），可能短暂双通道，需靠 `tow` 去重兜底。

## 7 性能

### 7.1 逐字符状态机 vs 行缓冲

| 维度 | 逐字节状态机（现状） | 行缓冲（`readStringUntil`） |
|------|----------------------|------------------------------|
| 内存 | O(1)（96 B） | 需整行缓冲 + 超时管理 |
| 分块到达 | 天然正确 | 依赖 read 语义，容易半个字段 |
| 阻塞风险 | 无 | **9600 波特下一行 85 ms**，会顶住任务 |
| 错误恢复 | `$` 重新同步即可 | 超时/半行难恢复 |
| 可测性 | 可直接喂字节（现有 host test 正是如此） | 难做确定性回放 |

结论：**保留逐字节状态机**。需要改的不是"逐字符"，而是"逐字符 + 多趟扫描"。

### 7.2 多趟扫描的实测代价

`ubx.cpp::nmeaParseSentence`（`ubx.cpp:550-619`）对一句话做了：

1. `minmea_check`（算一遍 XOR + 尾部检查）— `ubx.cpp:557`
2. `minmea_sentence_id` → 内部**再** `minmea_check` + `minmea_scan("t")` — `ubx.cpp:562`（`minmea.c:377-393`）
3. `minmea_parse_*` → 再 `minmea_scan` 一遍 — 如 `ubx.cpp:568`

即 **4 趟扫描、2 次完整 XOR**。宿主机实测（gcc 13.2 -O2，x86_64）：

```
3-call chain (check + sentence_id + parse) × 500k : 0.47 µs/句
parse only                                  × 500k : 0.26 µs/句
```

即"校验/判型"占了约 **44%** 的解析时间。目标平台是 STM32H743VIT6 @480 MHz Cortex-M7（`platformio.ini:12-15`），
按 5–20× 折算约 **几 µs/句**；1 Hz + 6 句/历元远不是瓶颈，但 10 Hz + 多系统 GSV（每历元可 20–40 句）时开始有意义。
**优化方向**：一趟扫描同时完成 (a) 校验和、(b) 句子类型识别、(c) 字段边界切分，产出 `{offset,len}` 数组，
后续按需取值；避免 `va_list` 与重复扫描。

### 7.3 内存分配

- `minmea.c` 无 `malloc/calloc/free`（全文仅在 `#include <stdlib.h>` 后用 `strtol`/`abs`），符合上游"no dynamic memory"声明（`README.minmea.md`）。
- `Ubx` 的句缓冲、快照、计数器都是成员/静态常量（`ubx.h:374-411`），epoch 队列是固定 4 深度环形（`ubx.h:87`）。
- **GSV 重组也要坚持零分配**：固定 `sat[最大星数]`（如 64）+ 每 talker 一个小状态，不要用 `std::vector`。

### 7.4 最大句长

| 口径 | 值 | 依据 |
|------|-----|------|
| 标准上限 | 82 字节（含 `$` 与 CRLF） | GPSD |
| u-blox 可配置严格 82 | `CFG-NMEA-LIMIT82`，默认关闭 | F9 §2.2 + 默认表 |
| 本项目缓冲 | 96 字节 | `ubx.h:374` |
| 建议 | 128 字节 + 静态断言 + 超限丢弃计数 | 高精度 GGA ≈88，扩展编号 GSV 可达 ~90 |

### 7.5 `Pump` 的字节循环

`while (bus_->available() && ...) { bus_->read(); }`（`ubx.cpp:252-282`）在 Arduino 上是**每字节两次虚调用**。
115200 下约 1.15 万字节/s，开销可忽略；但若把 NMEA 开到 10 Hz 多系统（每历元 400+ 字节、每秒 4000+ 字节）仍无压力。
真正建议改的是"按块读 + 内部环形缓冲"（`bus_->read(buf, n)`），顺便解决 `available()` 返回 0 时的忙等。

### 8.5 目标架构建议（供后续改造，不在本次改动范围）

```
字节流 ──► 协议分帧器（UBX / NMEA / 未知，带互斥门控）
             ├─ UBX 帧 ──► 现有状态机（NAV-PVT/EOE…）
             └─ NMEA 句 ──► 单趟扫描器
                              ├─ 校验和 + 类型 + 字段边界（一次遍历）
                              ├─ 字段视图（offset,len，零拷贝）
                              ├─ 句子解析表（GGA/RMC/GSA/GSV/GBS/GST/VTG/ZDA/GNS）
                              ├─ GSV 重组器（按 talker+signalId，超时交付）
                              └─ 质量/完好性聚合（GST/GBS/GSA → acc & DOP）
                                   └─ 时间基（RMC 日期 + 时间 [+ 闰秒] 或 UBX iTOW）
                                        └─ NMEA 快照（带"位置时戳/速度时戳/有效性"）──► epoch 队列
```

关键不变量：
1. 一个 epoch 的位置与速度各自带时戳，合成前校验年龄；
2. 任何"无效/推算/人工/模拟"解不得映射成 `FIX_3D`；
3. 校验和必检，坏句只计数不污染；
4. GSV/精度字段只作"加权与诊断"，不参与状态外推。
