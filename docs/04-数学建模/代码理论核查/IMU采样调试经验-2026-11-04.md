# IMU 采样率/通信调试经验（2026-11-04）

> 对象：ICM-42688-P，STM32H743，协作式主循环 + TIM8 6.4 kHz。
> 结果：从默认约 1429 Hz 提升到稳定 **约 2000 Hz（mean≈1996–2001、std≈70–75、
> ring_drop=0）**，默认 `[env:CoaxialVTVL]` 已启用。
> 本文只记录实际验证过的结论、错误路线和可复现步骤。

## 1. 测量方法论（最重要）

- **高频采样/时序测量禁止用 DBG**（health/tasks/vars watch）。DBG 会暂停遥测、
  阻塞调度任务，读数被自己的命令污染；曾把正常 FIFO 测成 3198 Hz、21 m/s。
- 唯一可信通道：普通遥测 **0xF4**（`imu_rate_hz`/`imu_prof_*`/`imu_ring_drop`）
  + `tvc record` CSV；或逻辑分析仪。
- 判据不只看 `imu_rate` 均值：同时看 **std、min/max、Navigation max、
  imu_ring_drop、conv、静态 vel**。
- 自动判定：

```bash
tvc record start -o p1.csv -d 10
py -3.12 TandemVec_FCS/tools/verify_imu_p1.py p1.csv
```

通过条件：mean≥1950、std≤100、ring_drop=0；本机实测 1996–2001/70–75。

## 2. 从现象到根因的顺序

必须按“传感器→通信→调度→处理”逐层排除，不要先改 ODR/PID/控制：

1. **传感器/FIFO 产率**：DBG 内阻塞命令（其他任务停）读 FIFO，
   实测 2.12 包/ms≈2120 Hz、Packet3 时间戳持续前进 → 传感器/FIFO/SPI 正常。
2. **通信**：`getAGT()` 是 1 次 INT_STATUS(0x2D) + 1 次 14B burst；
   **INT_STATUS 不是 0x19**，状态与温度/六轴不连续，不能凭直觉合并 18B。
3. **调度**：TIM8 6.4→12.8 kHz 实测 mean1409/std267，无改善；
   扩展任务推迟 mean1416/std220，只降抖动；说明不是 tick/优先级。
4. **处理成本**：分段计时发现每样本总 114.8 µs：
   - SPI 52.3 µs
   - 前置校准/滤波/轴变换 5.1 µs
   - 增量 1.9 µs
   - Madgwick 26.0 µs
   - 其余欧拉/打包/AHRS 约30 µs
   最大头是 SPI 和姿态/打包，不是 FIFO 产率。

## 3. 真正有效的优化（按收益）

| 优化 | 效果 |
|---|---|
| SPI 逐字节 `transfer` → 缓冲 `transfer(dest,count)` | 总 114.8→93.6 µs；SPI 52→30 µs |
| SPI 10→24 MHz | 总 93.6→84 µs；SPI 30→20.6 µs |
| 备份 Madgwick/欧拉/四元数降到约200 Hz（IMU增量/EKF仍每样本） | 总 84→36 µs |
| 2kHz ISR 单包→SPSC ring，Navigation 200Hz 排空 | 消费2k稳定，mean≈2000/std≈71 |
| 去掉读寄存器逐次 `endTransaction` | **无效果**（不要重复） |

注意：
- SPI 缓冲传输是最大单点收益；逐字节循环是 CPU 开销，不只是时钟。
- 24 MHz 在当前板上静态稳定；仍有信号完整性风险，动态/振动需复核。
- 姿态降频只影响备份 AHRS/遥测，不影响 `IMU_Packet` 的加速度/角速度打包；
  不能把 Madgwick 降频当成处理链优化（单独降频反而更差，实测 1358/310）。
- 提高 ODR、改 TIM8 时基、继续加 FIFO 包数均为**无效路线**。

## 4. P1 架构（最终采用）

```
TIM8 6.4kHz ISR
  └─ 按2kHz相位累积触发 imuSampleIsr()
       └─ readFifo(1包) → SPSC ring.push（只搬运，不做浮点）
Navigation 200Hz
  └─ readIMUData() 一次排空 ring（≤64）
       ├─ injectFifo → 现有校准/滤波/轴变换/增量
       ├─ 备份姿态200Hz（Madgwick/欧拉/四元数）
       └─ IMU_Packet每样本更新
```

关键不变量：
- ISR 绝不跑 Madgwick/滤波/串口；只读 FIFO + push。
- ring 满时**只计数不覆盖**；`imu_ring_drop` 进 0xF4 遥测。
- FIFO 初始化/读取失败自动回退 UI 轮询（`s_fifo_fallback`）。
- 默认 `[env:CoaxialVTVL]` 启用 P1；`[env:CoaxialVTVL_UI]` 保留纯轮询回退。

## 6. 错误路线（不要再试）

- FIFO 批量一次读8包：4218Hz、EKF退化；批量消费/重复计数不可靠。
- FIFO 2包主循环：3198Hz、std571；消费节拍不稳。
- 单次 status+data 18B：读错寄存器（INT_STATUS=0x2D），cal=0/EKF坏。
- TIM8 12.8k、任务推迟、Madgwick单独降频：无改善/更差。
- 提高 ODR、SPI 20/24MHz 单独做：不解决主循环消费。
- 用 DBG 的 health/tasks/vars 当采样率证据：假象。

## 8. 给后续 agent 的检查单

1. 先确认测量不是 DBG；用 0xF4+`tvc record`。
2. 看 `imu_rate` 的 mean/std/min/max + `ring_drop` + `conv` + `vel`，不只看均值。
3. 先分层：产率（FIFO/时间戳）→ 通信（SPI 事务/缓冲）→ 处理（分段耗时）
   → 消费节拍（ISR/ring/Navigation）。
4. 任何优化先实验宏+独立 env，默认 UI 保留回退；不飞直到动态验证。
5. 更新本文件/AGENTS，不要只留在对话里。
