# IMU 通信与采样率方案（ICM-42688-P）

## 1. 现状（先排除误判）

- 驱动 `ICM42688::getAGT()` 已经是 **一次 INT_STATUS 读 + 一次 14B TEMP/ACC/GYRO burst**；
  `accX()/gyrX()` 只是内存取值，不是六次 SPI 事务。
- SPI1 = 10 MHz，2 kHz ODR。通信时间不是 1.4 kHz 的唯一原因。
- `readIMUData()` 由协作式主循环 `handleICM42688` 轮询；名义 0.5 ms，
  但任何耗时任务都会让 flag 合并。`health`/DBG 读取时更明显。
- 实测 `imu_rate` 约 1.4–1.6 kHz（AnoVars，非 DBG）；2 kHz 标称不等于实际。

## 2. 已有但未接入的能力

- `ICM42688::enableFifoStream()` / `disableFifoStream()`；
- `ICM42688::readFifoPackets()`：Packet 3 16B/包，一次 `FIFO_COUNT` + 一次
  burst（当前最多 8 包），已按 FSR/校准换算为 g/dps；
- `imufifo` DBG 自检能读 8 个有效包；
- `imu_delta` 64 深缓冲 + 200 Hz Navigation 消费。

**没有接入飞行链路的原因**：早期按“逐包 16B 事务”试过，单次 IMU 任务
136 µs/max 531 µs，Navigation 掉到 183 Hz/max 10.3 ms；不是 FIFO 本身错，
而是读法/批量策略错。

## 3. 推荐方案（按代价从低到高）

### A. FIFO 批量读取（首选）

1. 使能 Stream-to-FIFO（accel+gyro，temp 可选）；
2. `handleICM42688` 改为 1 ms 调度（2 kHz 下每次约 2 包），一次
   `FIFO_COUNT` + 一次 ≤8 包 burst；
3. 逐包走现有单样本处理（校准/滤波/轴变换/增量/Madgwick），不要逐包发 SPI；
4. 保留 `imu_delta` 64 深缓冲，Navigation 仍 200 Hz 消费；
5. 验收：`imu_rate`≥1900 Hz、Navigation avg≤6 ms/max<15 ms、EKF 不退化、
   SIL 24/24/40/40 不回退。

### B. 数据就绪中断/水位

- 用 INT1 DRDY 或 FIFO watermark 置 flag，主循环只在有包时读；
- 不能在 ISR 里做 Madgwick/浮点大批处理；ISR 只置位/抓时间戳。

### C. SPI DMA / 提高时钟

- H7 SPI1 DMA 读 FIFO burst，释放 CPU；需改驱动与并发保护；
- SPI 10→20/24 MHz 只在信号完整性验证后做，单独提速不会解决主循环合并。

### D. 独立高优先级 IMU 任务/定时器

- 协作式调度器没有抢占；若 FIFO 仍不足，把 IMU 采集放到 TIM 中断或
  独立高优先级任务，只把样本写入 ring buffer，处理仍在主循环。
- 这是最后手段，优先用 A/B。

## 4. 判定口径

- 用 `tvc vars watch imu_rate -t 60`，不要用 `health`/`tasks` 的 DBG 读数；
- 同时看 `tasks` 的 Navigation avg/max、`imu_drop`、`imu_delta_overflow`；
- 只提升 `imu_rate` 但 Navigation max 变差，不算解决；
- 目标不是盲目追 3.2 kHz；现役 42688 的 ODR 是 2 kHz，滤波器按 2 kHz 设计。

## 5. 2026-11-04 FIFO 首次接入尝试（已回退）

按 A 方案做了最小注入式批处理（FIFO 读 ≤8 包、强制 dt=1/ODR），上板 A/B：

- `imu_rate` 显示 **4218 Hz**（不可能是 2 kHz ODR）；
- `conv=0`、`vel=1.43/0.33/2.49 m/s`、`pos_sig=11.34`，EKF 明显退化；
- 默认轮询版回退后 `imu_rate≈1263–1400 Hz`、`conv=1`。

判断：批处理的时间戳/包计数/消费速率有一致性问题，不能把“每包强制
dt=1/ODR”当作真实采样时间；也说明 `imu_rate` 本身会被重复样本放大。
实验代码和 `CoaxialVTVL_FIFO` env 已回退，飞行默认仍走轮询 UI 路径。
下次必须先用 FIFO 包时间戳/计数校验、单包注入，再逐级增加批量；不能直接
以 4 kHz 读数当成功。
