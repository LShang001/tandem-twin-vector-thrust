# CTL-007 共轴 PID 统一架构（2026-11-04）

> 决策：**共轴不再保留独立 PID 参数变量**。上层姿态/速率/位置算法共用
> `kFlightCtrlParams.att_* / rate_*`；机型只描述执行机构与硬件动力模型
> （质量、推力、力臂、惯量、舵机行程、PWM、差速力矩）。
> 本文是首飞前统一改造的设计基线；改造完成并重跑 SIL/台架前，飞机停飞。

## 1. 当前架构债

`CoaxialCtrlParams.ctrl`（`BFS_COAX_PARAM_LIST` 中 18 项）同时包含：
- 控制参数：att/rate PID 增益、积分/输出限幅、滤波 alpha、max_rate；
- 硬件参数：mass、thrust、servo、PWM、lever、inertia、yaw moment。

GCS 因此出现 `coax.att_kp_pitch`、`coax.rate_kp_pitch` 等独立 PID；
这与“上层算法通用、机型只换执行机构”冲突。

## 2. 为什么不能直接改名

| 层 | 通用 TandemVec | 当前共轴 |
|---|---|---|
| 姿态外环输出 | deg/s | deg/s（同量纲，可直接共享） |
| 速率内环输出 | deg/s²（角加速度） | **deg 修正角**（再经 `g=l·T/I` 转 α） |
| 执行机构 | BTRUE 力矩分配 | TVC 摆角/差速 PWM |

共轴速率环 `rate_kp=0.25` 的量纲是“deg 修正 / (deg/s)”，通用
`rate_kp=16.04` 是“deg/s² / (deg/s)”；直接改名会让共轴增益变化约
`g·0.25` 与 `16.04` 的比值（随推力变化），不可首飞。

## 3. 目标架构

```
姿态外环（通用 att_*） → 目标角速率 [deg/s]
        ↓
速率内环（通用 rate_*） → 机体系角加速度 α [deg/s²]
        ↓
CoaxialAllocator：α + 推力 + 硬件参数 → TVC 摆角 / 差速 µs / 电机 µs
        ↓
ActuatorOutputMap：PWM/舵机百分比（机型 profile）
```

- **唯一 PID 变量**：`att_roll/pitch/yaw`、`rate_roll/pitch/yaw`（kFlightCtrlParams）。
- **共轴硬件参数**：mass、max_thrust、servo_half、motor_min/max、attitude_limit、
  lever、yaw_moment、inertia；不再包含 PID/滤波/积分限幅。
- 通用 rate PID 的输出统一为 deg/s²；`CoaxialAllocator` 用 `τ=I·α` 和
  `δ=asin(τ/(l·T))` 做机型逆解。
- 速率环输出限幅由**物理 α 权限**（`α_max=(l·T/I)·sin(δ_max)`）在分配器/出口
  做硬限幅；通用 PID 的 out_max 作为软件上限，两者都保留，避免只靠一个静态值。

## 4. 迁移步骤

1. **控制器**：共轴 `run_coaxial_control` 改用通用 `PositionPID`（att/rate），
   速率输出 `deg/s²` 后转 rad/s²；删除 `CoaxialVtvController` 内部 PID 状态
   （或改为只做滤波/限幅的薄层）。
2. **参数表**：删除 `BFS_COAX_PARAM_LIST` 中的 PID/滤波/积分项；
   `CoaxialCtrlParams` 只留硬件字段；GCS 不再出现 `coax.*kp/ki/alpha`。
3. **默认值**：通用 PID 默认值保持 TandemVec 基线；共轴首飞值通过
   **机型 profile 的硬件参数 + 一套通用增益**标定，不新增变量。
4. **限幅**：`max_corr_deg`/`max_yaw_us` 作为硬件/安全限幅保留；
   速率环软件限幅由通用 rate `out_max` 与分配器 α 权限共同约束。
5. **验证**：
   - 逐拍参考等价测试改成“通用 PID + 共轴分配器”新参考；
   - 共轴 24 例 SIL：`max_pitch <20°`（当前 22.9–23.5°，必须解决）；
   - 台架/断桨：TVC 方向、差速方向、45° 锁电机、未解锁输出；
   - 上板 `health veh=CoaxialVTVL` + 参数表确认无 coax PID 副本。

## 5. 首飞门

在步骤 1–5 完成前：
- 不把当前共轴 PID 副本当最终架构；
- 不进行自由飞；最多断桨/系留检查；
- 旧 `VTVL_ElectricDualRotor_FCS_原始飞行存档版` 仅作控制语义参考，不直接
  替代新多机型固件。

## 6. 已知风险

- 通用 rate 环与共轴 `α` 分配器的耦合需要重新标定；现有 TandemVec 增益
  不能直接用于共轴。
- 当前 SIL 俯仰超调 23° 是改造前遗留问题；统一后必须重新验收，不能沿用
  “旧参数等价”作为通过依据。
- 参数在线写入仍会 `apply` 到统一 PID；共轴硬件参数变更单独 apply。

## 7. 2026-11-04 实施进度

- 已实施：共轴 `coax.*` PID 副本从参数注册表/GCS 删除，只保留 15 项硬件参数；
  共轴控制律参数由通用 `att_*`/`rate_*` 在悬停点按 `g=l·T/I` 派生，不再有独立
  PID 变量。
- 已实施：GCS `expected_names()`/`COAX_PARAMS` 同步为 148 项、15 项共轴硬件；
  `test_coax_params` 197/197、GCS 参数测试 12/12。
- **未通过**：共轴 SIL `mag_clean/mag_nominal` 6 例仍 `max_pitch 22.9–23.5° > 20°`；
  已确认峰值时 `omega_ref≈0`、舵机接近限幅，是位置保持目标/分配耦合，不是简单
  PID 跟踪超调。该门未解决前不首飞。
- 当前板子已烧统一 PID 的 CoaxialVTVL，`health veh=CoaxialVTVL`；仅断桨检查。

## 8. 2026-11-04 SIL 定位补充

在 SIL CSV 增加 `tgt_roll/tgt_pitch` 后发现：23° 峰值时 **目标俯仰≈0°、实际−23°**，
`ch2≈39%` 已接近 TVC 修正限幅。这说明不是位置环目标 23°，也不是 PID 跟踪超调，
而是**共轴俯仰配平/TVC 权限方向在 SIL 中已饱和**。统一 PID 后该现象不变，属于
改造前遗留的执行机构/plant 配平问题。

首飞前必须先在地面断桨确认：
1. 两轴 TVC 中位对应舵机 50%（33.33–66.67%）；
2. 正俯仰修正产生的力矩方向与 IMU 俯仰角变化符号一致；
3. 共轴电机/舵机安装中位没有持续偏置；若存在，先在台架做机械/软件配平，
   不能靠把 `att_pitch.kp` 调大硬顶。

## 9. 俯仰符号 A/B（2026-11-04）

为排除“共轴俯仰力矩符号反了”，只在 SIL plant 中把 `w.My` 取反后重跑：
`max_roll=178.8°、max_pitch=89.4°、alt=0`，系统直接发散。说明**原符号正确**，
23° 不是符号反，也不能靠翻混控符号解决。恢复 plant 后仍是 `tgt_pitch≈0、
truth_pitch=-23、ch2≈39%`，指向：
- 共轴俯仰存在持续配平力矩（推力线/CG/舵机中位偏置）；
- 或 TVC 可用权限不足以在该配平下回零。

下一步必须是断桨/台架测量舵机中位、推力线相对 CG、正俯仰修正的力矩方向；
不能再用 SIL 或 PID 调参替代机械配平。

## 10. 2026-11-04 模型修正（推翻 §8/§9 的配平/权限结论）

- **L1 集总 plant 的共轴俯仰力矩/姿态约定有误**：它会在 `mag_clean/mag_nominal`
  误报 `max_pitch≈23°`；用户实测零修正舵机≈50%、喷管机械中位，说明不存在
  机械配平偏置。
- 改用 `--coax-plant-model rigorous`（刚体/摆座/转子耦合）后，保持
  **`max_correction_deg=10°` 原限幅**，24 例全部通过（max_pitch<20°）。
- 因此：
  - 不把限幅改成 15°；15° 只是把 L1 模型误差顶过去的错误做法；
  - 不再把 23° 当配平/权限问题；
  - **共轴 SIL 默认强制 rigorous plant**，L1 仅保留作对照。
- 结论：统一 PID + 原 10° 限幅在严格模型下闭环稳定；首飞前仍需断桨确认
  TVC 中位/方向（用户已确认中位≈50%），不再需要“机械配平”这一步。
