# CTL-004 固件-仿真一体化

> 目标：**固件是唯一算法源，仿真只是适配器**。任何算法（导航、控制、分配、参数）
> 只保留一份实现；仿真通过稳定 ABI 调用它，而不是在 Python/JS 里再写一遍。
> 本文给出分层、ABI 契约、消费者登记表、扩展步骤与边界；控制律本身见
> [CTL-001](CTL-001-控制架构与SAS.md)，多机型抽象见 [CTL-003](CTL-003-多机型与执行器抽象.md)。

---

## 1 要解决的问题

| 症状 | 后果 |
|---|---|
| 同一算法在固件与仿真各一份（如 `hifi_core.FirmwareControl`） | 固件修复（nav-raw、速率环量纲、轴置换）必须再改一次 Python；两份结论可能相反 |
| 仿真脚本各自维护编译参数/源清单 | 宏不同（如 `FW_SIL_REAL_NAV`、`EKF_NAV_TELEMETRY`）⇒ 跑的不是同一份代码 |
| 实验不知道"这条特性到底编进去了没有" | 把"没启用"误判成"无收益"（§4.24o 构造性无差异） |

一体化后的判据：**删除任何一份复刻实现，仿真结论不变**；新增算法只改固件源码 + 源清单。

## 2 架构：一份源码，两个链接目标

```
TandemVec_FCS/src/*.cpp + include/*.h（平台无关模块）
        │
        │  唯一源清单：test_host/fw_algo/build_fw_algo.sh::CORE_SOURCES
        │
        ├──► fw_real.exe      SIL：固件核心 + plant 主循环（test_host/fw_sil）
        │
        └──► fw_algo.dll      宿主直调：固件核心 + 三组 C ABI
                 ├─ L1  fw_ekf_*    15 态 ESKF（fw_algo_api.h）
                 ├─ L2  fw_alloc_*  分配 / 推力（fw_ctrl_api.cpp）
                 └─ L2  fw_gnc_*    控制链 + 能力查询 + 参数注册表（fw_gnc_api.h）
```

- **SIL 与直调库共用同一份 C++ 源**：`flight_control.cpp`、`navigation_task.cpp`、
  `state_data.cpp`、`ano_params.cpp`、`ublox`、DPS310、Madgwick、单位库、SIL 桩。
- 库默认输出到 ASCII 临时目录（MinGW 不能在中文路径链接），Python 侧按 mtime 增量构建。
- 新增一个固件 `.cpp` 时，**必须同时加进 `test_host/fw_algo/core_sources.sh`**；`build_fw_algo.sh`
  会先做漂移检查（SIL 的 `build_incremental.sh` 缺同一条目就直接失败），避免两侧跑不同代码。

## 3 ABI 契约（v1）

| 约定 | 内容 |
|---|---|
| 版本化结构 | 所有入/出结构前两字段 = `struct_size` + `abi_version`；加字段只能追加尾部，库只写自己已知长度 |
| 返回码 | `fw_gnc_step`：0 成功 / 1 空指针 / 2 ABI 不匹配 / 3 输入结构过小 / 4 输出缓冲过小 / 5 数值非法 |
| 单例 | 控制层 PID/滤波器是全局状态：一个进程一个实例；多条独立轨迹用子进程隔离 |
| 角速度 | 输入必须是**已去偏**的实测角速度（库内 `nav_ekf` 不运行，零偏恒 0） |
| 时间 | 调用方推进：每次 step 把虚拟时钟前移 `dt_s`（`millis()/micros()` 与固件一致） |
| 单位 | 遥控 PWM µs；执行器输出 **%**（0–100，固件混控层原值）；姿态 rad / 角速率 rad/s / 摆角 deg |
| 可观测性 | 输出同时回报 `mode_degraded_heading/gnss`、`failsafe_in_flight`、`actuator_fault_bits`（舵机卡死/推力损失/请求下降）⇒ 实验能区分"控制变差"与"门控降级/故障"；另回报 `target_alt_m`、`specific_force_up_mps2`、`thrust_cos_tilt`、`throttle_cmd_pct`，用于把"高度环输出"与"推力分配"分开对拍 |

### 3.1 能力查询（`fw_core_caps`）

回报 `core/ekf/ctrl/gnc` 四个 ABI 版本、`param_count`、`vehicle_profile`
（tandemvec / coaxial_vtvl / liquid_rocket）、`feature_bits`（raw-imu、失联速度保持、
失联定高、长失联下降、气压健康门、GNSS 垂直门、gnc_available）、`build_id`（git 短哈希）。

> 实验脚本必须用 `fwapi.caps()` 断言特性位，而不是假设"默认开/关"。

### 3.2 参数注册表（`fw_param_*`）

直接复用固件 `ano_params.cpp` 的 **133 项注册表**（与 GCS 0xE0–0xE3、MAVLink PARAM_SET
同一份）：按名查找、读、写、写后 `applyFlightCtrlParams()` 无扰同步。
⇒ 仿真调参与实机在线调参语义一致，不再维护第二张参数表。
`fwapi.param_dump()` 可一次性导出名字→值字典，实验开始时落盘即可复现参数集。

## 5 扩展步骤

1. **新增算法**：写到 `src/`（有硬件依赖）或 `include/`（平台无关），配宿主测试与
   opt-in 宏；加进 `CORE_SOURCES`；SIL 与直调库同时获得。
2. **新增 ABI 字段**：追加到结构尾部 → 升 `abi_version` → 在 `fw_core_caps` 增特性位 →
   Python 结构体同步；旧调用方按 `struct_size` 自动兼容。
3. **新增消费者**：只依赖 ABI（Python/MATLAB/C++/未来 WASM），禁止复制算法。
4. **新增机型**：编译期 profile（`BFS_COAXIAL_VTVL` 等）+ `caps.vehicle` 标识；
   运行期多机型仍是下一步（见 §7）。
5. **新增实验设施**：SIL 研究开关放 `FW_SIL_REAL_NAV` 内并进 trace/JSON 自证据，
   不改变生产默认。

## 6 验证记录（2026-10-29）

- 构建：`bash test_host/fw_algo/build_fw_algo.sh` → `fw_algo.dll`（1.2 MB，冷构建约 4 min，增量约 3 s）。
- `run_fw_gnc_demo.py`：caps（`gnc_abi=1`、`param_count=133`、`vehicle=tandemvec`）、参数往返、
  上锁电机 <5%、定高误差 0→5 m 时油门 31.2%→43.1%、ABI 返回码 0/2/3/5 全通过；
  `python -m fwapi` selftest PASS。
- **SIL ↔ 直调库逐拍对拍**（`sim/check_fw_gnc_parity.py` + SIL `--trace-ctrl`）：
  5 个 profile（mag_clean 20 s；nominal / mag_nominal / degraded 各 15 s；manual 8 s），
  每 profile 1600–4000 拍。**修复根因后全部通过预登记严格判据 C4b 与工程判据 C6**：

| profile | 模式不一致 | 最差控制通道 max\|Δ\| | 角加速度 | 角速率指令 | 摆角/差速 | 诊断 alt_err |
|---|---|---|---|---|---|---|
| mag_clean（20 s） | 0 | **0.0054 %**（电机） | 1.2e-3 dps² | 5e-5 dps | 2.6e-3° / 6.9e-5 | 0.35 m |
| nominal | 0 | **0.0048 %** | 7.8e-5 | 5e-5 | 5.6e-4° / 5e-5 | 0.35 m |
| mag_nominal | 0 | **0.0047 %** | 1.3e-3 | 5e-5 | 5.6e-4° / 5.5e-5 | 0.35 m |
| degraded | 0 | **0.0057 %** | 6e-5 | 5e-5 | 5.7e-4° / 5e-5 | 0.35 m |
| **manual**（SAS/手动油门） | 0 | **5.5e-5** | 5.5e-5 | 5e-5 | 5e-5° / 5e-5 | —— |

  ⇒ **控制输出（执行器/摆角/差速/角速率指令/角加速度）在全部 profile 上达到 CSV 精度量级**
  （最差 0.0057%，阈值 1%）。`alt_err` 是**只读诊断**：它只在 AUTO 分支刷新，手动模式保留
  各自最后一次 AUTO 的历史值 ⇒ 不参与控制等价判定（单独限 0.5 m）。
- **根因（2026-10-29 收口）：`is_origin_lla_set` 是控制链的隐藏输入。** 固件
  `process_control_inputs()` 在“原点未建立”时把 `relative_*` 兜底清零（真机上电未定位时
  防止上一架次残留）。宿主 ABI 只注入 `relative_down`，从未置位该标志 ⇒ 控制链每拍看到
  高度 0，表现为 `alt_err ≡ target`、自动模式电机 % 残差 0.24–4.89%（手动模式不经高度环，
  所以一直是 5e-5）。修复：`fw_gnc_step` 在注入点**每拍**重申 `is_origin_lla_set = true`
  （`fw_gnc_create` 也置一次）；修复后残差 4.89% → 0.0057%。
- 本轮对拍抓出并修复的 ABI 缺陷（每条都有“失败→通过”的实测证据）：
  1) **原点标志**（上述，影响最大）；
  2) **航向口径**：固件 `AHRS_Packet.Heading` 用 `wrapAngleTwoPi`（[0,2π)），ABI 原用
     `quaternionToEuler`（±π）⇒ yaw 指令差 ±24 dps；
  3) **角速度源**：控制链用 `icm_gyro_*` 重新两级滤波，ABI 只注入滤波后值 ⇒ 二次滤波
     且实际忽略了输入（姿态环差 2968 dps²）；
  4) **单例生命周期**：`fw_gnc_destroy` 未清空静态指针 ⇒ 第二次 `create` 返回悬空指针（堆损坏）；
  5) **缺失输入**：导航层门控 `g_heading_hold_allowed / g_pos_hold_degraded /
     g_gnss_outage_age_s` 未注入 ⇒ 航向锁走保守分支（yaw 0 vs ±24 dps）。
- **诊断代码自身的坑**：`alt_err/target_vz` 最初只在“油门杆死区内”分支赋值，出死区后
  两边各自停在不同的历史值，制造出**假的 4.39 m 高度误差差**（看起来像固件缺陷）。
  已改为函数末尾每拍无条件刷新。**判据：任何被用作对拍/验收信号的诊断量，必须每拍刷新，
  不能在单分支里赋值。**
- 行为中性对照：missile seed 73 @23 500 N 在加入 trace/注入设施前后均为
  `pos_rms 35.16 / 拒帧 25 / 重锚 1`（共享核心与新增设施不改导航行为）。

## 7 边界与未做

1. **浏览器仿真未接**：本机无 emscripten，`vector-thrust-lab` 暂不接 WASM；
   其控制律明确标注为"设计模型"，不是固件复刻。
2. **单例**：固件控制层 PID/滤波器为全局状态，一进程一个实例；批量独立轨迹用子进程。
3. **机型编译期**：运行期多机型需要把 `runGNCExecutive` 的机型分支改成 profile 查表，
   属 CTL-003 的后续工作。
4. **L3 导航步进 ABI（`fw_nav_*`）未做**：当前 Python 全闭环仍走 SIL 可执行；
   若要 Python 直接驱动 `handleNavigationSystem()`，按 §5.2 追加同风格 ABI。
5. **hifi 复刻迁移未做**：`FirmwareControl` 仍保留；迁移验收判据是
   "静态输入序列逐拍输出与 `fwapi.Gnc` 一致（容差内）"，不是闭环结果对比
   （hifi 闭环本身已发散，见 §4.24）。
6. ~~高度/油门回路的等价性未闭环~~（2026-10-29 已闭合）：根因是宿主未置位
   `is_origin_lla_set`，控制链每拍看到高度 0。修复后 5 个 profile 全部通过严格判据
   （最差 0.0057%）。**余留**：`alt_err` 等诊断量在手动模式下是历史值，不能当控制等价信号。
