## 结果

从默认约 1429 Hz（std 263）提升到稳定 **1996–2025 Hz、std 44–77、ring_drop=0**，
默认 `[env:CoaxialVTVL]` 已启用 P1；CPU 41.5%、conv=1、静态 vel=0。
FIFO 失败时的轮询降级是运行时行为（`s_fifo_fallback`），不是独立 env。

## 要点

### 1. 测量方法论是第一位（否则后面全错）

- **高频时序测量禁止用 DBG**（health/tasks/vars watch）：它会暂停遥测、阻塞调度，
  读数被自己的命令污染。曾把正常 FIFO 测成 3198 Hz / 21 m/s。
- 唯一可信通道：普通遥测 **0xF4**（`imu_rate_hz` / `imu_prof_*` / `imu_ring_drop`）
  + `tvc record` CSV，或逻辑分析仪。
- **只看均值会误判**：判据 = mean + std + min/max + Navigation max + `ring_drop` + conv + 静态 vel。
- 自动判定：`tvc record start -o p1.csv -d 10` →
  `py -3.12 TandemVec_FCS/tools/verify_imu_p1.py p1.csv`（mean≥1950 / std≤100 / drop=0）。

### 2. 排查顺序：传感器→通信→调度→处理→消费节拍

不要一上来改 ODR 或 PID：

1. **产率**：DBG 内阻塞读 FIFO，实测 2.12 包/ms≈2120 Hz、时间戳持续前进 → 传感器/FIFO/SPI 正常。
2. **通信**：`getAGT()` = 1 次 INT_STATUS(0x2D) + 1 次 14B burst；INT_STATUS 不是 0x19，
   状态与六轴不连续，**不能凭直觉合并成 18B**（会读错寄存器，cal=0/EKF 坏）。
3. **调度**：TIM8 6.4→12.8 kHz 实测 1409/267，无改善；任务推迟 1416/220 只降抖动
   → 问题不在 tick/优先级。
4. **处理**：分段计时节拍每样本 114.8 µs（SPI 52.3 / 前置 5.1 / 增量 1.9 / Madgwick 26.0 / 其余约30）。
5. **消费节拍**：主循环消费速度跟不上 2 kHz 产率，这才是根因。

### 3. 真正有效的优化（按收益排序）

| 优化 | 收益 |
|---|---|
| SPI 逐字节 `transfer` → 缓冲 `transfer(dest,count)` | 总 114.8→93.6 µs，SPI 52→30 µs |
| SPI 10→24 MHz | 总 93.6→84 µs，SPI 30→20.6 µs |
| 备份 Madgwick/欧拉/四元数降到约 200 Hz（IMU 增量/EKF 仍每样本） | 总 84→36 µs |
| 2 kHz ISR 单包 → SPSC ring，Navigation 排空 | 消费达到 mean≈2000 / std≈71 |

### 4. 无效路线（不要再试）

- FIFO 批量一次读 8 包：4218 Hz 但 EKF 退化，批量消费/重复计数不可靠
- FIFO 2 包主循环：3198 Hz、std 571，消费节拍不稳
- 单次 status+data 18B 合并：读错寄存器
- TIM8 12.8 kHz、任务推迟：无改善
- **Madgwick 单独降频：反而更差（1358/310）** —— 姿态降频只能配合每样本 IMU 增量才有收益
- 提高 ODR、SPI 升频单独做：不解决消费瓶颈
- 去掉读寄存器逐次 `endTransaction`：无效果

### 5. 三个隐蔽 bug（都靠"默认 env 实测"才暴露）

1. **遥测字段被宏挡住**：`imu_ring_drop` 原本写在 `#ifdef BFS_IMU_PROF` 里，默认 P1 没开
   PROF ⇒ **恒上报 0**，验收会误判"无溢出"。修复：ring_drop 由 `BFS_IMU_ISR_RING` 决定，
   其余耗时字段无 PROF 时填 0 占位。**教训：验收字段必须在默认 env 里实际取值，
   新增遥测列要查默认/实验/回退三种构建。**
2. **姿态降频必须用累计 dt**：降频后仍传单样本 `deltaTimeSecs`，7 个样本只积 0.5 ms，
   动态姿态明显滞后。改为累加 `s_att_dt += dt`，每次姿态更新传累计值并清零
   （静态复测 2001.9/66.1/drop0，动态待实机确认）。
3. **Navigation 排空必须限流**：一次排空 ≤64 样本会在长停顿时产生突发
   （60 s 实测 max=12800 Hz、std 262.9，验收失败）。先限每次 ≤10（2023.5/74.0），
   仍有 max≈5724 窗口突发；最终**按实际 elapsed 算允许数**：
   `allowed = 1 + elapsed_us*2000/1e6`，上限 10 → 60 s 复测
   mean=2024.8、std=44.2、min 1878.6 / max 2192.0、drop 0，PASS。
   消费节拍从此跟时间轴绑定，不再被任务提前/延后放大。

### 6. P1 架构不变量（改代码前必读）

```
TIM8 6.4kHz ISR → 按 2kHz 相位触发 imuSampleIsr()
                  → readFifo(1包) → SPSC ring.push（只搬运，不做浮点）
Navigation 200Hz → readIMUData() 按 elapsed 限流排空
                  ├─ injectFifo → 校准/滤波/轴变换/增量
                  ├─ 备份姿态 200Hz（Madgwick/欧拉/四元数）
                  └─ IMU_Packet 每样本更新
```

- **ISR 绝不跑 Madgwick/滤波/串口**，只读 FIFO + push
- ring 满时**只计数不覆盖**，`imu_ring_drop` 进 0xF4
- FIFO 初始化/读取失败自动回退 UI 轮询（`s_fifo_fallback`）
- 任何优化先做实验宏 + 独立 env，默认 UI 保留回退；**动态未验证前不飞**

## 遗留

- `max` 仍有约 2192 Hz 的单窗口尖峰，动态（振动/机动）未验证 —— **首飞前必须补动态验收**
- 24 MHz SPI 静态稳定，信号完整性在振动下未复核
- 姿态降频的累计 dt 修正只在静态确认，动态姿态滞后需实机数据
