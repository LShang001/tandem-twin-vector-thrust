## 要点

### 1. F10N 配置口径：CFG-VALSET，不是 CFG-MSG

- F10（EXT SPG 6.00 / protocol **40.00**）的正确入口是 **UBX-CFG-VALSET + `CFG-MSGOUT-*` 键**；
  `UBX-CFG-MSG` 自 >23.01 起 deprecated，F10 接口说明里已无该章节。
- 若仍用 CFG-MSG，8 字节 payload 的端口字段**必须分清**：
  `msgClass, msgID, rateDDC, rateUART1, rateUART2, rateUSB, rateSPI, reserved`。
  旧实现只写 `rateDDC`，UART1/2 为 0 —— 接收机照回 ACK，但**串口上 NAV-PVT 永不输出**。
  这就是「`ubxcfg status` 全 OK 而 `ubxstat` 的 `pvt=0`」的根因。
- **ACK ≠ 输出**：配置后必须看 `ubxstat` 的 `pvt` / `eoe` 计数是否增长。
- F10N 默认 38400 8N1 无流控、NMEA V4.11；多星座 10 Hz / 单星座 20 Hz。
  本板实测自动探测到 921600。
- 室内 `fix=0`、`ubxcfg ant` 报 `SHORT/OPEN` 属预期，先查天线，不要归因解析器。

### 2. 921600 波特率下 UART4 必须提中断优先级

- 921600 时字节间隔仅 **10.8 µs**，UART4 RX 默认中断优先级不足，被其他中断延迟就丢字节，
  实测 `bad_pvt ≈ 25%`。
- 修复：`Serial4.begin(921600)` 之后 `NVIC_SetPriority(UART4_IRQn, 0)`。
- 验收后 `ubxstat`：`rx_bytes=82584 / valid_msgs=1784 / bad_pvt=4 / pvt=594 / eoe=596`。

### 3. 调度器「丢执行」是名义 1600 实际 1552 的根因

- TIM8 实测：clk **240 MHz**、PSC=1、ARR=37500 → tick ≈ **6399.8 Hz**，1 tick = 156.25 µs。
- 调度模型 = `ISR 置 flag` + `主循环消费`，**flag 是布尔量**：若上一拍没消费，
  本次到期只把 flag 保持为 true，**这次执行永久丢失**（不是排队的）。
- 旧统计只有「迟到」（间隔 >1.5×名义），看不到合并；新增 **`missed_count`（丢执行）** 列量化。
  上板基线：ICM42688 名义 1600 / 实际 1552 / 丢执行 3451 / 负荷 16.3%。
- **200 Hz 任务实际只有 155.4 Hz**（`cnt=2125` / 13.672 s 窗口）。机理：7 个 5 ms 任务
  注册相位几乎相同，一次 pass 超 5 ms（实测 max pass 3388 µs）时它们的 flag 被合并。
  候选修复（未实施，属调度改动需专项批准）：注册时按任务序号加 1–2 tick 相位偏移。

### 4. 判断「EKF 发散」前先看是不是假原点

- `health` 的 **`rel_ned` = `lla2ned(当前GNSS, 原点)`，不是 EKF 内部位置**。
- `GNSS_INIT_MAX_H_ACC_M = 5.0 m`：只有 `hAcc∈(0,5m]` 且 vAcc/sAcc 合格才用真实 GNSS 原点；
  否则用硬编码假原点（28.2°N / 112.9°E / 50 m），`fake_origin=1`，等首次高质量 fix 再重锚。
- 判据表：

| 条件 | fake_origin | rel_ned | 结论 |
|---|---|---|---|
| 室内 hAcc=23–36 m | 1 | 3.5/9.1 km | **正常**，假原点到真实位置的偏移 |
| 室外 hAcc≤5 m | 0 | ≈0（重锚后） | 正常 |
| 室外 hAcc≤5 m | 1 | 几 km 且不收敛 | **异常**，重锚未触发，查 `gnss_quality_for_reanchor` |

### 5. 「任务频率 / 芯片采样率 / 导航消费」是三件事

- IMU 任务注册周期 = `1000/actualAccelOdrHz()`，42688 为 2 kHz → **3.2 tick**（Q8 下 3/4 tick 交替）。
  `tasks` 表里的「名义 1600 Hz」是**整数 tick 初值显示**，既不是平均 2 kHz，也不是芯片 ODR。
- **没有 FIFO**：任务没执行的那一拍，芯片已产生的新样本被下一拍覆盖，**不进 64 深增量缓冲**。
  64 深在 2 kHz 下约 32 ms、1.6 kHz 下约 40 ms —— 缓冲只能吸收导航节拍抖动，
  补不回「根本没读到的芯片样本」。
- `AnoVars imu_rate`（非 DBG）是**每个 5 ms 窗口的瞬时速率**（sample_count/dt），不是秒级平均：
  15 s 均值 1600.32（min 1143.9 / max 1763.0）、60 s 均值 1576.35（min 999.6 / max 1705.8）。
  min/max 对应某帧 5 个或 9 个样本，不等于「掉到 1 kHz」。
- **DBG 打印本身会加剧丢拍**，绝不能拿 `DBG tasks` 的数字当飞行速率依据（见 memory 11-04 §1）。

### 6. SOCP 制导联合仿真（10 m → 地面完整着陆）

链路：`fw_sil_guidance.exe`（200 Hz，6DOF plant）+ `guidance_bridge.py` + 外部 SOCP（`vtvl_sim.py`）。
判定阈值：最终 `|up|≤0.05 m`、横向 `≤0.10 m`、过程最低 `≥-0.60 m`、最大垂直速度 `≤6.0 m/s`。
发现并修正了「规划结束后的假平衡」问题。自动判定脚本 `check_socp_joint.py`（退出码 0=PASS）。
