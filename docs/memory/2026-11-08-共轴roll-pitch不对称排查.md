# 共轴 roll/pitch 不对称的排查记录与可复用判据（2026-11-08）

## 结论先行（2026-11-08 晚更新）

**已解释清楚：pitch 超限的主因是「下降段力矩权限不足」，不是控制律缺陷。**

完整链路：

1. 峰值阶段分布 `{0:1, 1:2, 2:1, 3:4}` —— 5 个超限 case 里 4 个峰值在**下降段**（80%）
2. 下降段油门约 30% → 推力 4.2 N → 控制力矩 0.63 N·m，只剩悬停时的 **51%**
3. 共轴力矩 `M = l·T·sin(δ)` 与推力成正比，力矩减半 → 姿态偏差约 2 倍
4. 与独立路径 `lever_low`（力臂减半，力矩 53.3%，实测偏差 2.00 倍）**比例一致**

两条独立证据指向同一机制：**控制器输出正确，执行器权限不够**。

详细推导见 `VER-009 §2.4d`；阶段分布见 `§2.4c`；单例定位见 `§2.4b`。

> 下面保留原始的排查过程与「待排查」清单——虽然结论已出，但排查顺序本身
> 可复用，下次遇到其它分轴不对称问题仍按这个顺序走。

## 现象

MC 100（`run_coaxial_mc.py`）统计：`roll_p50 = 1.26°`、`pitch_p50 = 29.3°`，
判据都是 30°。roll 远在范围内，pitch 的中位数已经贴着判据。

## 已排除（有证据）

| 检查项 | 怎么查的 | 结论 |
|---|---|---|
| 执行器映射对称性 | 读 `CoaxialAllocator.h:13` 的力矩公式 | `Mx = l·T·sin(δ_roll)`、`My = l·T·sin(δ_pitch)`，**逐字符对称** |
| 速率环增益 | `grep BFS_RATE_ROLL_DEFAULT / BFS_RATE_PITCH_DEFAULT` | 两者**逐位相同**（16.042818 / 5.729578） |
| 姿态环增益 | 同上，`BFS_ATT_*` | 两者**相同**（2.8 / 0） |
| 惯量接线 | 读分配器 `inertia_kgm2[1]` / `[2]` | 分别用 Iy / Iz，参数里可独立配置，没有写死同一个 |

**这四项排除了「控制律或分配层在 roll/pitch 上有差别」这个假设。**

## 原「尚未排除」三条的现状

1. ~~plant 俯仰通道扰动更大~~ —— **证据不支持**：同一 plant 下，超限 case 的
   峰值主要落在下降段而非某一段固定扰动处；改为力臂/惯量配置可复现同样的
   比例关系，说明主因是力矩权限而非 plant 扰动。
2. ~~初始条件有 pitch 方向偏置~~ —— **已排除**：峰值时刻 t_max_pitch 分布在
   5.6–38.2 s（不是 t=0），与初始条件无关。
3. ~~竖立构型下俯仰倾角影响推力竖直分量~~ —— **不是主因**：若成立，roll 应
   有对称的量级贡献，但 roll_p50 只有 1.26°，与 pitch 的 29.3° 差 23 倍。

## 下一步该怎么查（给下次接手的人）

1. **先看时间序列**：`max_pitch` 落在哪个阶段（起飞 / 悬停 / 下降 / 着陆）。
   已有 `max_pitch_preland` 可对比——若两者相等，峰值就在着陆前。
2. **再看 plant 源码**：`coaxial_dynamics_model.h` 用四元数、不含欧拉角，
   pitch 是在 `fw_sil_env_main.cpp` 里从四元数解出来的。要查 pitch 偏大，
   得看那里的姿态解算与扰动注入，而不是动力学文件。
3. **最后才动控制参数**：上面四项已经排除了控制层，先调增益大概率是白费。
   ★ 这条最重要——**不要在没排除 plant 的前提下改增益**，会把一个 plant
   问题伪装成"调好了"。

## 方法论（可复用）

**分轴不对称问题的排查顺序**：
1. 先查**执行器映射**（是不是某一轴权限天生不同）
2. 再查**控制增益**（是不是某一轴调得软）
3. 再查**惯量/几何参数**（是不是某一轴被写死或接错）
4. 上三步都对称，问题就在**被控对象或测量**，不在控制器

这轮 1–3 全对称，所以问题在 plant 或姿态解算——但这个结论**只是缩小了范围**，
不是找到了根因。文档与提交说明里都按「开放问题」标注，不写成已解决。
