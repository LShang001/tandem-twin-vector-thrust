# IMU 延迟随时间增长的根因：FIFO 速率失配（2026-11-11）

> **触发条件**：改 IMU 采样/取数/排空逻辑、调 `kOdrHz`、`kIsrPollHz`、
> `readFifo`、`ImuSampleRing` 排空参数时；排查"姿态/舵面延迟大且越放越严重"
> "控制吃旧数据""延迟随时间增长"时；判定该用几个 ISR 轮询时。

## 现象与判据

室外接 RTK 后症状：刚上电灵敏，放几分钟越来越慢；角速度模式响应滞后一拍；
`health` 的 `imu_age_us` **单调上涨**。

修复前实测（上板 22 s）：`fifo_q=38/75 包`、`imu_age_us=4020`、`ring_size=6`，
而 `isr_f == drain_f`、`ring_drop=0`、`isr_empty=0` —— **所有既有健康指标全绿，
唯独控制拿到的是几十包之前的样本**。

## 根因：两个时钟，稳态失配

- 芯片 ODR 由 **RC 晶振**决定，标称 1600 实测 **1600~1685 Hz**，随温度漂移
  （实测 23.5 ℃ 时 1656、29.5 ℃ 时 1599，同一块板）。
- ISR 取数节奏由 **MCU 定时器**决定，按标称 `kOdrHz` 派生。
- 两者都是稳态常量，差值恒定 ⇒ FIFO 每分钟稳定积压几千包。
- FIFO 是**先进先出**：积压 38 包 ≈ 22 ms，75 包 ≈ 44 ms，且随积压量线性增长。

**关键认知：FIFO 只能缓存，不能吸收稳态速率差。开大 FIFO 只是把爆炸时间往后推。**

## 修复（五处必须配合，缺一不可）

| # | 改动 | 文件 |
|---|---|---|
| 1 | `dt` 由芯片 FIFO 时间戳差分驱动（16 位、1 µs 分辨率、65.5 ms 回绕，`(cur-prev)&0xFFFF` 自动处理回绕） | `src/sensor_imu.cpp` |
| 2 | `readFifo` 每次读到空、只交最新一包（等效深度 1） | `lib/ICM45686/src/ICM45686_ImuDevice.cpp` |
| 3 | ring 窗口 24/16 → 16/8，窗口右端贴当前时刻 | `src/sensor_imu.cpp` |
| 4 | 消费时间基准按每帧真实 dt 累加（非 `processed × 1/标称ODR`） | `src/sensor_imu.cpp` |
| 5 | 空 drain 时时间基准对齐 `now_us` | `src/sensor_imu.cpp` |

**ISR 轮询必须 ≥ 2×ODR**：`readFifo` 每次最多交 1 帧，帧率上限 = ISR 频率。
实测降到 1600 Hz 时芯片产 1656 帧/s、ISR 只能交 1600 帧/s，差的 56 帧变成
ring 积压（`ring_size=4`、`imu_age` 412 → 2650 µs、CPU 34.9% → 45.1%）。
**排空只解决 FIFO 深度，解决不了取数次数不足**——已用 `static_assert` 卡死。

## 修复后实测（上板 66 s）

`fifo_q=1/1`、`imu_age_us=399`、`ring_size=0`、`dt_us=625`、
`allow_avg=5`（修复前 19/20，长期贴上限）、`conv=1`、`pos_sig=0.02`。

## 已否决的路线（不要再走）

1. **只排空 FIFO、不改 dt**：丢帧后帧间隔变 1.25/1.875 ms 而仍按 0.625 ms 积分，
   时间轴压缩 2–3 倍 ⇒ EKF 当场发散（rpy 145°、vel 782 m/s、pos 31 km）。
   **丢帧本身没错，错在固定 dt。**
2. **ISR 降到 1600 Hz**：见上，ring 积压、CPU 反升。
3. **只把 ISR 提到 2× 但不改时间基准**：能压住 FIFO 积压，但 `allow_avg` 会长期
   贴 20 上限（每帧少记账十几 µs 的误差累积），突发时没有余量。
