# GCS 平板可点性验收（2026-11-10）

## 1. 实测数据：偏小的控件是这些

用 Playwright 在真实视口（1024×768 / 1280×800）+ `has_touch=True` 量得：

| 控件 | 修复前 | 修复后 |
|---|---|---|
| 顶部导航 `.nav-btn` | 63×**31** | 67×**42** |
| 通用按钮 `.btn` | 52×**28** | 56×**42** |
| 机号选择 `#vehSelect` | 62×**24** | 84×**42** |

鼠标上完全没问题，手指上 24–31px 高的控件误触率明显偏高。
判据取 **40px** 下限（iOS HIG 建议 44，Material 建议 48dp；40 是能接受的折中）。

## 2. 两个必须记住的技术点

### 2.1 Playwright 必须开 `has_touch=True`

否则浏览器按**细指针**设备处理，`@media (pointer: coarse)` **根本不生效**，
量出来仍是桌面尺寸——**那样验证等于没验证**。

```python
pg = b.new_page(viewport={'width': w, 'height': h}, has_touch=True)
```

### 2.2 用 `pointer: coarse` 而不是宽度断点

判据应该是「**设备怎么输入**」，不是「屏幕多宽」：

- 1280px 的笔记本用鼠标 → 不需要变胖
- 1024px 的平板 → 需要

```css
@media (pointer: coarse) {
  .nav-btn, .btn, select { min-height: 42px; }
  select { min-width: 84px; }   /* 窄选择器在触屏上难命中 */
  .insp-table td, .insp-table th { padding-top: 8px; padding-bottom: 8px; }
}
```

## 3. 检查脚本自己会犯错

`tablet_check.py` 最初把 `#alarmBanner` 放进触控检查列表，但它**是显示元素、
不可点**，宽度 1024 高度 33 是正常的——把它当触控目标判是**判据错误**，已移除。

**教训**：检查列表里只放**真的会被点的**元素。把展示用的条带算进去，
会让人去"修"一个本来就没问题的东西。

## 4. 局限（不要高估这条验收）

这是**尺寸**判据，不是**实际命中测试**：

- 没验证「手指点在控件边缘」这类场景
- 没在真平板上试过
- 没测多点触控、长按、拖拽手势

真机验收仍需人来做。脚本能保证的是「不会因为 CSS 改动悄悄退化回 24px」。
