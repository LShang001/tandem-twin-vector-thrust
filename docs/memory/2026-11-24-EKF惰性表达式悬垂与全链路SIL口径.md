# EKF 惰性表达式悬垂：宿主显形、实机良性，以及全链路 SIL 的口径（2026-11-24）

> **触发条件**：写或审「返回 Eigen 表达式的 lambda」「用 `auto` 接 Eigen 表达式」；跑
> `test_host/fw_sil/fullstack/build_and_run_closedloop.sh --hover`；看到 SIL 里「同一份代码
> 时好时坏」、`alt_mean` 出现 NaN、定高读数 10.52 m 而不是 10.00 m、harness 退出码 134；
> 要用全链路 SIL 的数值推断实飞行为；用 WSL 跑 SIL 批量构建。

背景：提交 f79eb89e 修了 `lib/navigation-main/src/ekf_15_state.h` 的 `phi_at_time`
（`const auto` lambda 返回 Eigen 表达式，持有已销毁局部量 `f_tau` 的引用）。本篇是
2026-11-24 对该修复的复查结论与顺带确认的几条口径。

## 1. 这个 UB 只在宿主 `-O0` 构建上显形，实机目标码里 Φ½ 是对的

- 机制：Eigen 3.4 的 `ref_selector` 对带 `NestByRefBit` 的 `Matrix` 一律存 `const&`，
  所以推导成表达式模板的返回值在 lambda 一返回时就悬垂。修法只能是显式返回类型。
- 宿主（全链路 SIL，g++ 13 `-O0`）：修前 **100% 的传播调用 Φ½ 都错**。double 中位误差
  2.4e-2（与 `f_tau` 最大元素同量级，整项丢失）；**float（实飞配置）第一次调用就是 inf**，
  P 被钳到 1e-9 下限，EKF 从不收敛、高度 NaN。
- 实机（xPack GCC 12.3.1 `-O3`，三个 `*_ICM45686` env 的反汇编核对）：lambda 被内联，
  `f_tau` 的栈槽自填充到最后一次读没有任何存储指令命中，表达式对象在不重叠的槽里。
  所以**实飞固件里这个 UB 没有数值后果**，当时的 inf/NaN、时好时坏、「定高环稳定裕度
  不足」都只是宿主构建的表现。
- 修复在实机上的实际收益：消掉 UB（换编译器或优化级别后随时可能显形），
  `PropagateStateFromIncrements` 栈帧 11552 → 10656 B，该翻译单元代码 ±80 B 以内。
- 全固件扫描：37 处 `auto`、26 个 lambda，除这一处外没有第二个推导成 Eigen 表达式的点。
- 独立探针 `fs_lambda_dangling_probe.cpp` 的 3.5e-4 不代表真实回路（合成 F、double、
  且多一处 `Identity()` 临时量悬垂）；要量化就按 `README §7.6` 的插桩办法在真实回路里量。

## 2. 全链路 SIL 与实飞的 EKF 配置差一个宏

`build_and_run_closedloop.sh` 的 `CXXFLAGS` 没有 `-DBFS_NAVIGATION_EMBEDDED_FLOAT_COVARIANCE=1`，
而 `env:unignc` 有。也就是 SIL 跑的是 double 协方差、实飞是 float。修后两者闭环一致到
1 mm，但**凡是排查协方差数值问题，必须用带这个宏的构建**（修前两者行为天差地别）。

## 3. `--hover` 的真实高度稳态是 10.52 m，10.00 m 是气压高度

harness 按 ISA（288.15 K）由高度反推气压，温度寄存器预置为 0；而驱动
`Dps310::calculateAltitude(pressure, temperature)` 用芯片温度（273.15 K）。高度因此按
288.15/273.15 ≈ 1.055 缩放，EKF 与定高环把**气压高度**稳在 10.00 m 时，plant 的真实高度
是 10.52 m（`[10.52, 10.54]`）。这是宿主气压模型与驱动口径不一致，不是固件缺陷
（固件有 `baro_altitude_offset` 归零和 `InsComputeAbsoluteBaroAltitude` 还原绝对高度）。
判据带 `(9, 11)` m 拦不住 5% 的标度偏差。

## 4. harness 每次成功结束都会 abort（退出码 134），退出码不能当判据

退出时全局 `Dps310Sensor` 析构 → `DpsClass::~DpsClass(){ end(); }` → `standby()` →
`disableFIFO()` → 纯虚 `flushFIFO()`（`DpsClass.h:312`）。MCU 上全局对象不析构，飞行无害；
宿主上 4/4 必现。`verify-ekf-lambda-fix.sh` 只 grep `HOVER` 行所以不受影响，但它的
ASan 步骤只覆盖 double 变体，复用时记得自己补 float。

## 5. WSL 跑 SIL 的两个环境事实

- 发行版在两次 `wsl.exe` 调用之间会停机并清空 `/tmp`：`BIN_DIR` 放 `/tmp` 的对象缓存
  下一次调用就没了（`build_incremental.sh` 的默认值就是 `/tmp`）。跨调用复用要指到仓库 `tmp/`。
- 两批构建同时起（8 个变体 × 6 路 = 48 个 `cc1plus`）会把发行版直接压垮重启，
  且日志被截断、分不清是谁的错。一次只起一批，或串行跑阶段。

## 复现办法

影子头目录 + `-Wl,--wrap=_Z4loopv` 的协方差轨迹插桩 + Φ½/Qd 偏差探针，全程不改受控文件；
目标码用 `pio run -t compiledb` 导出的原始命令单独编译 `src/navigation_task.cpp`
（实飞二进制里唯一实例化 `PropagateStateFromIncrements` 的翻译单元）。临时脚本当次放在
`tmp/ekf_review/`，不入库；思路同 `test_host/fw_sil/fullstack/README.md §7.6`。
