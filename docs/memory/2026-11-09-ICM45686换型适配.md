# ICM-45686 换型适配（2026-11-09）

> 换 45686 版飞控板时的完整排查与修复记录。结论：**驱动现在能用**，两个后端可随意切换；
> 但 45686 走轮询、只到 200 Hz，与 42688 的 2 kHz 硬件 FIFO 不等价。

## 1 结论先行

| 项 | 状态 |
|---|---|
| 45686 驱动可用性 | ✅ 可用（SPI 通信、芯片识别、ODR/FSR/LPF 配置全通） |
| 数据链路 | ✅ 通（IMU→EKF→控制，`cal=1 drop=0 ring_drop=0`） |
| 42688 原功能 | ✅ 未受影响（改动全在 `lib/ICM45686/` 内，42688 版编译 6.3 s SUCCESS） |
| 可切换性 | ✅ 两套 env 并存，换 env 烧录即切换 |
| **采样率** | ⚠️ 45686 = **200 Hz 轮询**，42688 = 2000 Hz FIFO，**不等价** |

## 2 根因：`dataReady()` 恒返回 0

`ICM45686_ImuDevice::dataReady()` 读 `INT1_STATUS0`（reg 0x19）的 bit2 `DRDY` 判新数据，
但 `begin()` **从没使能** `INT1_CONFIG0.int1_status_en_drdy`——该状态位恒 0，于是：

```
dataReady() 恒返回 0
  → sensor_imu.cpp:190 采初始 100 样本时 20ms 超时
  → 打印 "[Error] IMU init data timeout."，返回 -1001
  → main.cpp:370 if (initICM42688() != 0) 进 while(1){ 闪黄灯; delay(200); }
```

**现象**：板子黄灯 2.5 Hz 闪，串口只在开机那一瞬有输出（之后不再打），
`verify_board` 全部读 `-1`/`?`。

**修复**：新增 `ICM456xx::enableIntStatusDrdy()`，只写 `INTx_CONFIG0` 的 status 使能位，
**不配 pin config、不 attachInterrupt**——板子没把 INT 引脚接到 MCU 也能工作。
`begin()` 在 `startGyro` 成功后调用它。

## 3 排查过程中排掉的三件事（都不是问题）

| 怀疑 | 实测 | 结论 |
|---|---|---|
| 波特率不对 | APB1=80 MHz、UART8 BRR=87 → 80e6/87 ≈ 921600 | 波特率正确，`Serial8.begin(921600)` |
| 时钟没起来 | RCC_CR `0x3f03c025`（HSERDY=1）、RCC_CFGR `0x1b`（SW=PLL1） | 时钟正常 |
| 固件没跑 | SWD 读 PC，值在 `0x0804c60c/610/614` 间跳变 | 在跑（当时卡在 370 行死循环的 `delay`） |

**关键坑**：一开始读串口全是 0 字节，误判成「链路坏」。
实际是**开机打印早就在我读之前发完了**，固件已经卡死在死循环里不再输出。
用 OpenOCD `reset run` **同时**开串口抓，才拿到那 705 字节的开机日志。

另一个坑：新板子的调试口不是旧板子的 COM6（CP210x），是 **COM12（CH343）**——
串口号随板子枚举变化，每次换板先列 `Get-CimInstance Win32_PnPEntity` 看实际端口。

## 4 采样率差距：200 Hz vs 2000 Hz

上层架构（`task_scheduler.cpp:211`）：TIM8 定时器中断里 `s_imu_phase += 2000`，
累到 6400 触发一次 `imuSampleIsr()`，即 2 kHz 调 `IMU->readFifo()`。

- **42688**：`readFifo` 从芯片硬件 FIFO 批量读，一次 SPI 拿数据
- **45686**：`enableFifo()` 未实现 → 返回 -1 → `s_imu_ring_ready=false` →
  ISR 直接 return → 数据改由 200 Hz 任务轮询寄存器

**试过的方案（失败，已回退）**：给 45686 补 `enableFifo()`/`readFifo()`，
`readFifo` 里先 `dataReady()` 再读六轴。实机结果是**系统过载**：
DBG 完全无响应、`verify_board` 8 项全挂。原因是在 2 kHz ISR 里做**两次** SPI
（读状态 + burst 读数据），负载远超 42688 的「一次 FIFO 批量读」。

**要真正做到 2 kHz**，得用库的 `inv_imu_adv_get_fifo_data()` 配硬件 FIFO 批量读，
而不是轮询寄存器。这是下一步的正路。

## 4.5 手册查证与 3.2 kHz 攻关（同日追加）

**手册（DS-000577 v1.0，项目内 `lib/ICM45686/doc/`）确认**：
- ODR 档位到 **6.4 kHz**：`ACCEL_CONFIG0(0x1B)` / `GYRO_CONFIG0(0x1C)` 的 bit3:0，
  `0011`=6.4k、`0100`=3.2k、`0101`=1.6k（LN 模式）。**芯片能力不是瓶颈**。
- **有完整硬件 FIFO**：`FIFO_COUNT_0/1(0x12/0x13)`、`FIFO_DATA(0x14)`、
  `FIFO_CONFIG0(0x1D)`、`FIFO_CONFIG3(0x21)`（`FIFO_IF_EN`/`ACCEL_EN`/`GYRO_EN`）、
  `FIFO_CONFIG4(0x22)`；`INT1_CONFIG0(0x16)` bit1=FIFO_THS、bit0=FIFO_FULL。
- 库已封装：`configureFifo(ICM45686FifoConfig)`、`getFifoFrameCount()`、
  **`getDataFromFifoBatch()`**（一次 burst 多帧，专为减少每帧 SPI 事务设计）。
- 帧结构 `inv_imu_fifo_data_t`：`byte_16.accel_data[3]` / `gyro_data[3]` / `timestamp`。

**据此实现 FIFO 后端，五种方案全部实测失败**：

| # | 方案 | 实测结果 |
|---|---|---|
| 1 | ODR 3.2k + 2 kHz ISR，`readFifo` 逐帧（读状态+读数据两次 SPI） | 系统过载，DBG 完全无响应 |
| 2 | ODR 钳 1.6k + 1 kHz ISR + FIFO 批量 | `ring_drop=57913` |
| 3 | ODR 3.2k + ISR 批量读 8 帧 + 消费限流按 3200 算 | `ring_drop=35785`、`cal=0` |
| 4 | 方案 3 + 独立 1 ms 消费任务 `handleImuDrain` | 系统过载（`readIMUData` 内含校准/滤波，1 kHz 跑不动） |
| 5 | 方案 3 + ring 容量 128→1024（约 32 KB） | `ring_drop=41660` |

**根因判断**：瓶颈不在驱动，在**上层消费架构**。
`readIMUData()` 每帧要做自动校准 + 一阶互补滤波 + RUB→FRD 轴映射，是重活；
Navigation 每 5 ms 排空一次，`allowed = 1 + elapsed_us·3200/1e6 ≈ 17` 帧/拍，
理论 3400 帧/s > 生产 3200 帧/s，但实测持续丢包——说明**每帧处理耗时吃满了 5 ms 预算**，
实际消费速率达不到理论值。

**要真正上 3.2 kHz，必须做架构级拆分**（不是调参数能解决）：
- 把 `readIMUData()` 拆成「取数据」（轻，只 pop + 入中间缓冲）和「处理数据」（重，校准/滤波/轴映射）；
- 取数据跟 ISR 同频或由独立轻任务承担，处理仍按 Navigation 200 Hz 走；
- 或者反过来：既然 EKF/控制只用 200 Hz，把 ODR 定在 800 Hz 更匹配，
  不必为了"跑满芯片"付架构改造成本。

## 5 两个后端怎么切换

```bash
# 42688（默认，实飞已验证）
pio run -e SingleEdf4Vane -t upload          # 单涵道
pio run -e SingleEdf4Vane_Flight -t upload   # 单涵道实飞版

# 45686（换型验证）
pio run -e SingleEdf4Vane_ICM45686 -t upload # 单涵道 + 45686
pio run -e TandemVec_FCS_ICM45686 -t upload  # 纵列 + 45686
```

两套 env 产物各自落在 `.pio/build/<env>/`，互不覆盖。

**验证是否切对**：开机日志第一行 IMU 型号——
`Onboard IMU initialized successfully: ICM-45686 @3200Hz` 或 `ICM-42688-P @...`。

## 6 复现命令（换板自查）

```bash
# 1) 列当前串口，确认调试口号（CH343/CP210x），别hardcode COM6
powershell -NoProfile -Command "Get-CimInstance Win32_PnPEntity | Where-Object {$_.Name -match 'COM\d+'}"
# 2) 抓开机日志（复位 + 同时读串口，921600）
py -3.13 -X utf8 tmp/capture_boot.py COM12
# 3) 8 项自检
py -3.13 -X utf8 tools/verify_board.py COM12 SingleEdf4Vane
```

## 7 遗留

- 45686 上 2 kHz：需要实现硬件 FIFO 批量读（见 §4）
- 磁力计 `chip=NONE`：该机型没装，只报告不判 FAIL
- `vars watch` 依赖数传（0xF2 帧走 Serial6），没接线时测不到——
  `verify_board` 已改为「未测」而不是 FAIL
