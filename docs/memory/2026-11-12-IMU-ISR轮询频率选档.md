# IMU ISR 轮询频率的选档规则（2026-11-12）

> **触发条件**：改 `imu_odr_config.h`、调 `kOdrHz` / `kIsrPollHz` / `BFS_IMU_ODR_HZ`、
> 改 `platformio.ini` 的 IMU 维度或新增 env、排查「某个 env 编不过」、
> 排查 `ring_size`/`imu_age` 持续非零时。

## 现象

2026-11-11 把 ISR 轮询频率（`kIsrPollHz`）改成硬编码 `2 × kOdrHz`，并加了
`static_assert(kSchedulerTickHz % kIsrPollHz == 0)`。当时只验证了 45686 分支
（1600→3200，6400÷3200=2 整除）；**四个 42688 env 在此后两天全部编不过**：

- `TandemVec_FCS`（纵列调试）
- `CoaxialVTVL`（共轴调试）
- `SingleEdf4Vane`（单涵道调试）
- `SingleEdf4Vane_Flight`（**单涵道实飞固件**）

只有带 `-DFCS_IMU_MODEL_ICM45686` 的 env 能出固件。`default_envs` 指向 45686，
日常只编那一个，断裂两天无人发现。

## 根因（两个约束在 42688 上无交集）

42688 的 ODR 档位没有 1600（`kSupportedHz` = 50/100/200/500/1000/2000/4000…），
只能取 2000：

```
kIsrPollHz = 2 × 2000 = 4000
6400 % 4000 = 2400 ≠ 0   → 整除断言失败
```

同时满足「≥2×2000=4000」和「整除 6400」的只有 6400 一档，但代码把 `kIsrPollHz`
写死成 2×ODR，没有"向上取到 6400 因数"的逻辑。所以 2× 这个系数本身就是错的：
它是照 45686 的档位凑出来的，不是物理需求。

## 正确规则（已实现）

```
kIsrPollHz = min{ c ∈ {100,200,400,800,1600,3200,6400} | c ≥ ceil(1.5 × kOdrHz) }
```

三条约束各自的作用：

| 约束 | 来源 |
|---|---|
| 整除 `kSchedulerTickHz`（6400） | ISR 是 TIM8 相位累加抽点（`s_imu_phase += kIsrPollHz`），不整除会在 N/N+1 拍间交替，形成长周期节奏抖动 |
| ≥ 1.5 × ODR | `readFifo` 每次最多交一帧 ⇒ ISR 帧率上限 = ISR 频率；芯片 ODR 是 RC 晶振（实测 +5%），取数次数不足会让 FIFO/ring 稳定积压（2026-11-11 实测 ISR=1600 时 ring_size=4、imu_age 2650µs、CPU 反升到 45.1%） |
| ≤ 6400 | 一拍最多抽一次 |

落点：

| ODR | 下限 ceil(1.5×) | 选中 ISR | 倍数 |
|---|---|---|---|
| 45686 @1600 | 2400 | 3200 | 2.0× |
| 42688 @2000 | 3000 | 3200 | 1.6× |
| 800 | 1200 | 1600 | 2.0× |
| 500 | 750 | 800 | 1.6× |
| 3200 | 4800 | 6400 | 2.0× |
| 6400 | 9600 | 无解 → 编译期报错 | — |

为什么不是把 42688 的 ISR 拉到 6400：4000 与 6400 不整除，差值落在 1/2 拍交替；
6400 虽然整除，但空读率 69%、ISR 次数比 3200 多一倍，而 `readFifo` 单包读的
时间轴由芯片 FIFO 时间戳驱动（与 ISR 频率无关），多出来的查询没有收益。

## 防复发

新增守卫 `tools/check-env-matrix.py`（已进 `verify-all.py` 快档，28 项）：
解析 `platformio.ini` 的 `extends` 链与 `-D/-U` 宏，对每个 env 复算
「该 ODR 能否选出合法 ISR 档」，几十毫秒出结果，不需要编译固件。
负例验证过：`BFS_IMU_ODR_HZ=6400` → 无解 FAIL；`8000` → 超时基 FAIL。

## 验证

- 编译：`TandemVec_FCS` / `CoaxialVTVL` / `SingleEdf4Vane` / `SingleEdf4Vane_Flight`
  四个 42688 env 全部 SUCCESS；45686 env 的 ISR 仍为 3200（行为不变）。
- 宿主：全量 `run_all.sh` 通过；`verify-all` 28/28。
- 未上板：42688 板当前不在手边；`imu_age`/`ring_size` 的实测判据与 45686 同源，
  下次 42688 板接上后按 `health` 的 `ring_size=0`、`imu_age≈1/ODR`、
  `isr_c≈1.6×isr_f`、`isr_empty≈0.375×isr_f` 核对。
