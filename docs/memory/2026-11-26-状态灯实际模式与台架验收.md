# 2026-11-26 状态灯改报实际模式与台架验收

> **触发条件**：改 WS2812/RGB 状态灯的配色与优先级、增减告警源、调 `ws*` 调试命令、
> 或给状态灯做上板验收时。

## 要点

### 1. 灯色必须取「实际生效模式」，不能按遥控档位推算

飞控会在三处改写模式：制导指令超时回落手动、航向不可观降为定高、GNSS 长失联降高度保持。
ELRS 模式回传（`ElrsFlightModeText.h`）与 AnoCom 0x06 帧早就改用 `g_current_flight_mode`，
只有灯还在按 CH7 档位 + `trajectoryPlanningStarted` 推算——降级时灯显示一个没在执行的模式。

修法：已解锁时直接映射 `g_current_flight_mode`。判据是「灯与其他模式消费者读同一权威量」，
不是「灯的枚举名对不对」。

### 2. 单灯要区分「主色」与「提示」

一颗灯不能同时表达模式和告警。做法是 `FcsLedPolicy` 输出 `{primary, advisory}`：

- 失控、电池危险 → 占满全灯，并可打断上电自检；
- 地面状态下弱链/待收敛/无定位 → 直接作主色；
- **已解锁时降为 2 s 一次的短闪穿插**，模式色在其余时间保持可辨。

如果让告警一律抢占，飞行中最需要的「现在是什么模式」就永远看不见了。

### 3. 告警输入各自要判有效性

| 输入 | 判据 | 不判会怎样 |
|---|---|---|
| 低电压 | 采样值 > 0 才算有数据；串数由编译宏给 | 没接电池时 `bat_voltage_mv=0` 被当成「0 V → 危险」，一直红闪 |
| 弱链路 | 必须是 CRSF 协议 **且** 统计帧 1 s 内 | 统计帧停发（低 Telem Ratio / 切 MAVLink）后旧值长期有效，误报或漏报 |
| 地面就绪 | `nav_system_initialized && g_ekf_converged` | 只看初始化标志会在未收敛时显示「可以飞」 |

电池串数取保守值（3S）时只会**漏报**不会误报。共轴机型串数至今没记录，就按 3 处理并在文档写明。

### 4. 呼吸曲线的相位零点决定「切换看到什么」

- 呼吸（cos，零点=峰值）：切入当拍就是亮的。用 `sin` 归一化时切换瞬间接近谷值，看起来像延迟。
- 上电分段（sin，两端为 0）：换色边界不跳变。两种曲线不能共用一个函数。

失控双闪若按周期相位继承，切入可能先落在 600 ms 长灭相。**相位必须自状态切入点起算**。

### 5. 调试命令的副作用必须限时自恢复

`wsstatic` 曾把驱动强制切到 bitbang 且不恢复，之后所有点灯测试跑在 NOP 估算的时序上，
整帧被判无效——被误判成「新板灯坏了」。现在所有 `ws*` 命令都是 100 Hz 任务内推进的限时效果，
到期/`exit`/解锁/紧急状态一律恢复原驱动并重发一帧。

判据：`wsstat` 的 `driver` 回到 1、`ws_frame=1`、`ws_tx` 继续增长。

### 6. 台架验收的三条实测判据

1. `ws_tx` 持续增长且 `ws_fail` 不增 —— 证明每帧 DMA 都真的完成了（本板 239 帧零失败）。
2. 命令生效看**回读字段**，不看命令回显：`wsseq 100` 要看到 `ms/color=100`，
   因为旧实现打印的 500 恒定。`ws_rgb` 必须定宽 6 位，否则 `0x00FF00` 打成 `0xFF00` 无法区分。
3. 台架无遥控/无电池时，**模式色相与告警优先级一定验不了**，只能靠宿主回归 + 代码审查；
   报告里必须分开写「已实测」与「仅宿主层证据」。

## 边界

- 本板验到的是状态组装、命令自恢复、DMA 发送链路；灯珠是否真的收到正确波形仍只有
  `ws_fail=0` 这一间接证据（未上示波器/色度计）。
- 烧的是 `CoaxialVTVL_ICM45686_Dbg` 台架变体（Serial6 上行历史上不通，DBG 走 UART8），
  默认实机 env 的灯效未单独上板。
- 电池串数：单涵道按 6S 配了宏，共轴按 3S 保持旧阈值，待实机电池确认。
