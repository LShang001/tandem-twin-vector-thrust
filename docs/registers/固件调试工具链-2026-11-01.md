# 固件调试工具链与硬件踩坑（从 TandemVec_FCS/AGENTS.md 外移，2026-11-01）

> 触发条件：需要上板调试、定位卡死、外设不亮、SPI/DMA/Flash 异常时读本文件。

## 上板验收口径

> 查上板或遥测异常先读本节。历史实测见 [VER-010](../07-验证与确认/VER-010-实机烧录验证记录-2026-11-07.md)，不替代当前环境验证。

- **区分环境与端口。** `SingleEdf4Vane` 含 `BFS_ANOCOM_DIAG`；`SingleEdf4Vane_Flight` 不含该宏，不发送 `0xF4/0xF5`。实飞版仍有 USB AnoCom 参数链路，但 USB 不提供 DBG；Serial6 在 AnoCom 模式下仍有 DBG。因此实飞版不收诊断帧属预期，先确认启动日志、机型和参数读回，再验证实际使用的标准遥测。依据：[构建配置](../../TandemVec_FCS/platformio.ini)、[通信实现](../../TandemVec_FCS/src/communication.cpp)。
- **区分芯片出帧、MCU 取数和实际消费。** 默认配置下，ICM-45686 的芯片 ODR 为 1600 Hz，ICM-42688-P 为 2000 Hz；两者的 ISR 取数轮询均为 3200 Hz。配置正本为 [imu_odr_config.h](../../TandemVec_FCS/src/imu_odr_config.h)。`isr_c` 是累计取数调用，`isr_f` 是累计交付帧，`drain_f` 是累计处理帧；同一时间窗比较各计数的增量。正常空查不等于丢帧；还需核对数据年龄和累计丢弃。细节见 [ISR 选档](../memory/2026-11-12-IMU-ISR轮询频率选档.md) 和 [FIFO 延迟](../memory/2026-11-11-IMU延迟根因-FIFO速率失配.md)。
- **时序证据和功能证据分开。** 调试版用非 DBG 的健康帧评估帧率与队列；在有 AnoVars 下行的链路上，`imu_rate` 是固件健康采样估计，不是 ISR 轮询频率。实飞版时序需独立且可比的测量链路，缺口标「未测」；不把调试版结果直接算作实飞版已测。短时 DBG 读回用于诊断，不以其输出期间的任务间隔定量评价实时性。
- **旧自检脚本有适用限制。** [verify_board.py](../../tools/verify_board.py) 的「ISR 采样率」优先算 `isr_f` 差分，实际是有效取帧率；复测与 `imu_rate` 分支仍使用独立的固定区间，未按当前 IMU 型号和环境匹配，不能把整脚本 PASS/FAIL 当通用验收。没有 DBG 或 AnoVars 信号时，不用缺字段推断硬件故障；`ring_drop`、伪原点和磁力计为脚本报告项，不是该脚本的硬门槛。
- **安全前置。** 不经要求不烧录或操作硬件。获得授权后按 [固件安全规则](../../TandemVec_FCS/AGENTS.md#安全关键修改规则) 分阶段验收；只在断动力条件检查实机输出方向、限位和联锁。`Verified OK` 只证明写入校验通过。

## 调试工具链（2026-08-08 实战沉淀，全部验证过）

- **固件内调试模式（首选诊断手段）**：Serial6 收到 `"DBG\n"` 进入调试模式（`handleDebugConsole`），命令 `help/ws/wsmode/wsfault/gpio/tim4/ver/exit`。设计要点：①与地面站协议互斥共存（`DBG\n` 不会与 AnoCom 帧头 0xAB 冲突）；②调试命令直接读**寄存器**（MODER/AFR/ARR/CCR4/NDTR/DMAMUX）而非猜参数；③退出 `exit` 恢复数传。**任何新外设调试都优先加一个寄存器转储命令，比反复烧录试参数快一个数量级。**
- **宿主 UBSan（2026-11-03）**：MinGW GCC 13 不带 `libubsan`，加 `-fsanitize=undefined` 会链接失败；改用 `-fsanitize=undefined -fsanitize-undefined-trap-on-error`，命中 UB 直接 trap。EKF 15 状态回归模板：
  `g++ -std=c++17 -O1 -g -DEKF_HOST_REGRESSION -D_USE_MATH_DEFINES -fsanitize=undefined -fsanitize-undefined-trap-on-error -Iinclude -Isrc -Ilib/eigen/src -Ilib/navigation-main/src -Ilib/units/src test_host/test_ekf_15state.cpp lib/units/src/convang.cpp lib/units/src/convangacc.cpp lib/units/src/convangvel.cpp -o /tmp/ekf_ubsan.exe && /tmp/ekf_ubsan.exe`（2026-11-03 实测 116 通过/0 失败）。
- **调度统计（2026-11-03）**：`tasks` 打印 `TIM8 clk/psc/arr/tick_hz` 和每任务 `迟到/丢执行`；`丢执行` 是 flag 合并的真实计数。**DBG 打印本身会加剧丢拍**，飞行速率用非 DBG AnoVars `imu_rate`；当前 TIM8=240 MHz、PSC=1、ARR=37500、6.4 kHz。详见 `docs/04-数学建模/代码理论核查/任务调度器与TIM8配置-2026-11-03.md`。
- **2026-11-03 新增诊断命令**：`health` 一屏输出模式/IMU 健康/气压/GNSS（pvt/eoe/fix/sv/age/qovf）/EKF（rpy/vel/pos/tilt_sig）/Serial5 上行（rx/bad/age/txskip）；`ubxstat` 增加 `last cls/id/len`；`ubxcfg monver` 读 SW/HW/PROTVER/ANTSUPERV。GNSS 配置验收必须看 `ubxstat` 的 `pvt/eoe` 增长，`ubxcfg status` 的 ACK 不足以说明输出正常。详见 `docs/04-数学建模/代码理论核查/F10N-GNSS配置与调试-2026-11-03.md`。
- **2026-11-07 新增诊断命令**：`imuraw [n]` 打印留档的**未校准/未滤波**六轴（原始轴序 RUB，acc=g、gyr=dps）与当前处理值（FRD）并排对比；`magdec [deg]` 查看/设置站点磁偏（东偏为正，默认 −4.114° 长沙 IGRF-14）。判据用法：raw 与 processed 的差异只出现在高频段 → 是滤波/校准所为；raw 本身就抖 → 传感器/供电/机械问题，此时调滤波器无效。对应 AnoVars 新增 `imu_raw_ax/ay/az/gx/gy/gz` 与 `sat_cnt_f/t/w`（分配层饱和**次数**，原来只有 `alloc_sat[]` 三个 bool，无法回答"饱和有多频繁"）。磁偏改动只影响航向初始化与磁门控参考，未执行 `magdec` 时行为与改前一致。
- **2026-11-17 新增 `i2cscan` / `magprobe`（磁力计接线定位）**：`i2cscan` 对两条总线（I2C1 PB7/PB6 = 磁力计 `MagWire`、I2C2 PB11/PB10 = 气压计 `IIC2`）分别逐地址探测 0x08–0x77 的应答，直接读 `GPIOB->IDR` 报空闲电平（不改引脚模式），并读 I2C1 上 0x0E 的 `WHO_AM_I`(0x00)（IST8310 期望 0x10）。`magprobe` 在运行期重跑一次 `MagSensor::begin(&MagWire)` 并打印结果，用于区分「上电时序问题」与「驱动/器件问题」。**2026-11-17 两次装配实测**：模块接 I2C2 时扫描到 I2C2=`0x0E+0x77`、I2C1 无应答；改接 I2C1 后扫描到 I2C1=`0x0E`（WHO_AM_I=0x10）、I2C2=`0x77`。**两种接法都能通信，固件按当前接线把磁力计挂在 `MagWire`(I2C1)。判据：磁力计接哪条总线，`i2cscan` 就在哪条上给出 `0x0E` 且 WHO_AM_I=0x10；`magcal` 的 `chip=IST8310`、`magraw` 有样本且 `cal=VALID` 为最终验收。
- **2026-11-17 上电探测需重试**：同一块板 `i2cscan` 能扫到 0x0E 且 WHO_AM_I 正确，但 setup 里首次 `magSensor.begin()` 会失败、运行期 `magprobe` 必然成功——IST8310 上电后需要短暂稳定时间。修法：`initMagnetometer()` 内最多 5 次探测重试（每次间隔 50ms）。判据：冷启动后 `magcal` 直接 `chip=IST8310`，不依赖 `magprobe` 补救。
- **2026-11-17 GNSS 串口验收**：`ubxstat` 除原有 UBX 计数外，新增 `fifo_hw/fifo_hal/irq/cfg_fail`，用于确认 `Uart::begin()` 重配后 FIFO 与 UART4 高优先级仍有效。`tools/verify_gnss_stream.py --port COM9 --seconds 120` 自动进出 DBG 并做差分验收：`cksum_fail/bad_pvt/eoe_no_pvt/frame_timeout` 必须零新增，FIFO/HAL/IRQ 必须持续为 `1/1/0`，PVT/EOE 必须持续前进。详细根因与实测见 `docs/memory/2026-11-11-GNSS串口逐字节中断丢帧.md`。
- **OpenOCD 定位卡死**：`openocd -s <scripts> -f cfg -c "reset run; sleep 2000; halt"` 读 PC，再用 `arm-none-eabi-addr2line -e firmware.elf -f -p <PC>` 映射回源码函数——几分钟定位"卡在哪个函数"，不用猜。
- **★ xPack OpenOCD 的 stdout 输出会被吞**（`reg`/`mdw`/`mrw` 的结果进不了 stdout，脚本里 echo 也部分丢失）：遇到输出异常，**放弃 OpenOCD 读寄存器，改用固件内调试命令打印**（如 `gpio`/`tim4`）——固件自己读寄存器从串口输出，100% 可靠。
- **DAPLink 通信紊乱恢复**：OpenOCD 反复连接后出现 `CMSIS-DAP command mismatch` / `init failed` → **物理拔插 DAPLink USB 线**即可恢复（软件复位无效）。
- **python 串口脚本**（比 pio device monitor 灵活）：`python -c "import serial; ser=serial.Serial('COM10',921600); ser.write(b'DBG\n'); print(ser.read(4096).decode('utf-8','replace'))"`——可编程、可发二进制、可扫波特率。注意 Serial6 波特率以 `SERIAL6_BAUDRATE` 宏为准（当前 921600，2026-08-10 COMM-001 由 2M 降频——VCP 丢帧 ~15%）。
- **★ DBG 命令经 shell 传参会被拆成多条（2026-11-10 实测，据此误判过一次）**：
  `python dbg.py COM6 param get 0` 里 shell 按空格切出三个 argv；若脚本对每个 argv
  各加一个 `\n` 发送，固件就收到三条独立命令，输出
  `param count=169` + usage + `unknown: 'get'` + `unknown: '0'` —— 看起来完全像
  **固件命令解析坏了**，实际是调用方式错。判据：发 `ab cd` 出两条 `unknown`、
  发 `ab_cd` 出一条，即可确认是参数被拆而非固件 bug。
  **正确做法**：把所有 argv 用空格拼成一整行再发，多条命令用 `;` 分隔
  （脚本 `tools/dbg_console.py` 已按此实现）。
- **DBG 文本输出在行较长处会截断并与下一行粘连**：`health` 的 `isr_c=` 打印成
  `isr__de08805` 且紧跟 `[DBG] baro ...`，是串口输出缓冲截断，不是固件数据错——
  判据是同一窗口内其它字段（`isr_f`/`drain_f`/`ring_drop`）全部正常。
- **跨平台编译验证**：库要支持多平台时，在 /tmp 建独立 PlatformIO 项目（仅库 + 最小 main.cpp），用目标板 env（如 genericSTM32F407）编译——**无硬件也能验证编译层**，不污染主项目。
- **分层验证外设不亮**：①GPIO 配置（MODER/AFR）→ ②静态电平输出 → ③协议时序（寄存器/示波器）→ ④供电接线。每层有明确通过判据，避免在错误层反复试。


## WS2812 / 硬件踩坑记录（2026-08-08，通用教训保留，细节见 docs/memory/2026-08-08-WS2812驱动调试.md）

- **★ W25N01GV NAND Flash (SPI3) 已点亮**：驱动 `lib/W25N01GV/`（RAM 环形缓冲/后台批量写/游标持久化/坏块跳过），调试命令 `flash id|erase|stat|dump|test`。
- **★ SPI 硬件 NSS 与手动 CS 冲突**：`SPIClass(mosi,miso,sclk,ssel)` 传 ssel 引脚 → 硬件 NSS 覆盖 GPIO 配置 → 读 ID 全 0x6E。**SSEL 必须传 NC（软件 NSS）**，CS 手动 `digitalWrite`。
- **★ WS2812 (PD15) 已点亮并库化**：`lib/WS2812Driver/`（BSRR bitbang + TIM_UP DMA + fallback），应用状态机 `include/Ws2812AppStatus.h`（待机蓝/解锁绿/校准黄/故障红）。
- **★ 非对齐 float/int 访问 HardFault（ARM 通用）**：`uint8_t` 数组强转 `(const float*)` 读，地址未 4 字节对齐 → HardFault → **复位循环**（现象"复位后正常"，OpenOCD 抓假象，极难定位）。修复用 `memcpy` 逐元素拷贝。
- **★ 变长帧在混合帧流里靠定界符搜索不可靠**：payload 里的 0x00 误命中 `\0` 定界 → CRC 错 → 时有时无丢帧。**修复：固定长度 + pad**（CRC 固定位置）。通用教训：协议帧优先定长或帧内长度字段。
- **PWM+DMA 两个必踩**：① `ARR = clk/800000-1`（漏零则 16 位 ARR 溢出，频率全错）；② DMA 完成回调里必须关外设请求使能位（TIM_UDE 等），否则残留请求卡死 DMA 状态机、下帧 HAL_BUSY。
- **DMA1_Stream6_IRQHandler 是 weak→Default_Handler**（startup 无强定义），`HAL_DMA_Start_IT` 不使能 NVIC → 中断永不触发。**用 HAL_DMA_Start + PollForTransfer**。
- **调试命令可靠性**：`DBG\n` 检测必须在串口协议解析（receiveData）**之前**；调试模式下 Flash 写页与 CAN 互斥（`s_flashWriting`），否则 MCP2515 超时 reset 卡死 SPI2。
- **重构教训**：所有模式共用的资源（引脚掩码）必须在**构造函数**初始化，不能放在某个模式的 begin 里。
