# 卫惯组合导航 PPS 延时标定与接入方案

> 日期：2026-10-22  
> 范围：GNSS PPS/TIMEPULSE 到 PVT 本地接收链路的延时标定与 EKF 量测年龄接入。
> **本文不修改固件默认参数；当前固件仍固定 `BFS_NAVIGATION_GNSS_DELAY_S = 15 ms`。**

## 1. 结论

1. 绝对 GNSS 链路延时在匀速平飞中**不可由新息可靠辨识**；
2. PPS 是可靠、不依赖飞行状态的标定源；
3. 已实现纯算法层 `include/ins_gnss_pps_latency.h`，
   25/50 ms + 2 ms 抖动回归 8/8；
4. 当前硬件文档没有找到现成 PPS 走线，**硬件捕获尚未接入**；
5. 在接入前，固件应保留 15 ms 先验，不能直接用估计值覆盖。

## 2. 现有硬件事实

- 飞控：STM32H743；
- GNSS：UART4，UBX/NMEA，PVT 10 Hz；
- 硬件参考：`TandemVec_FCS/docs/电路拓扑参考.md`、`.agents/docs/hardware-reference.md`；
- 上述文档中**没有 PPS/TIMEPULSE 的现成连接器/引脚定义**；
- 因此必须先确认：
  - GNSS 模块是否引出 PPS；
  - 接到哪个 GPIO/定时器；
  - 电平/极性/是否需要隔离；
  - 是否与现有 PWM/串口冲突。

## 3. 算法层接口

`include/ins_gnss_pps_latency.h`：

```cpp
struct InsGnssPpsEdge { uint32_t tow_ms; uint32_t local_us; };
struct InsGnssPvtArrival { uint32_t tow_ms; uint32_t local_us; };
struct InsGnssPpsLatencyEstimate {
  bool valid;
  float latency_s;
  float spread_s;
  uint32_t sample_count;
};

InsGnssPpsLatencyEstimate InsGnssEstimatePpsLatency(
    const InsGnssPpsEdge*, size_t,
    const InsGnssPvtArrival*, size_t,
    uint32_t max_abs_delta_ms = 1000);
```

算法：

- PPS 边沿和 PVT 按 `tow_ms` 最近匹配；
- 计算 `local_recv - (local_pps + fractional_tow)`；
- 折叠到 `[0,1s)`，兼容 `micros()` 回绕；
- 中位数 + MAD；
- 少于 3 样本或无 PPS 返回无效。

注意：

- 该值包含“PVT 分数秒 + 本地接收差”，用于 EKF 年龄；
- 它不是“接收机内部解算时延”的完整分解；
- 没有 PPS 时无法得到绝对延时。

## 4. 固件接入建议（未实施）

### 4.1 硬件捕获

```text
PPS GPIO -> TIMx CHy input capture / EXTI
ISR: g_pps_local_us = timer_counter_to_us()
```

要求：

- 捕获时刻尽量靠近边沿，不要在 ISR 里做串口/浮点；
- 记录序号，检测丢脉冲；
- PPS 与 PVT 的 `tow` 必须同一秒。

### 4.2 队列

每个 UBX epoch 记录：

```text
(ubx pvt_tow_ms, pps_local_us, receive_local_us)
```

- 只保留最近 5–10 个；
- 丢 PPS 的 epoch 标记无效，不参与估计；
- `tow` 跳变/周翻转要处理。

### 4.3 估计与使用

```text
if (estimate.valid && estimate.spread_s < 10 ms) {
  gnss_measurement_age_s = clamp(estimate.latency_s, 0, 0.2);
} else {
  gnss_measurement_age_s = BFS_NAVIGATION_GNSS_DELAY_S; // 15 ms 先验
}
```

- 估计值低通/限幅；
- 单次异常不能直接切换；
- 连续 N 次一致才启用；
- 保留 15 ms 回退路径；
- 记录标定值到遥测/黑匣子，便于复盘。

### 4.4 时序注意

- PPS 上升沿对应 GPS 整秒；
- UBX PVT `tow` 可能带分数秒；
- 本地 `micros()` 回绕 71.6 min；
- 接收机内部滤波/钟差可能使“PPS→PVT”延时与“解算时刻→PVT”不同；
- 先用已知延时信号源/示波器验证，再接飞。

## 5. 验证计划

### 主机

- `test_host/test_gnss_pps_latency.cpp`：8/8；
- `run_all.sh` 已包含。

### 台架

1. 信号源产生 PPS + 已知延时 UBX PVT；
2. 捕获 PPS 本地时刻；
3. 比对估计值与信号源设定；
4. 扫 0–100 ms、±10 ms 抖动；
5. 检查 PPS 丢失/TOW 跳变/串口拥塞。

### 飞行

- 先只记录，不参与控制；
- 对比固定 15 ms 与 PPS 估计的 EKF 位置/速度；
- 确认无 PPS 时回退正常；
- 再考虑让估计值参与量测年龄。

## 6. 风险

| 风险 | 处理 |
|---|---|
| PPS 未引出/无引脚 | 保持 15 ms，先做软件延时表 |
| PPS 丢脉冲 | 标记无效，回退先验 |
| TOW 周翻转/跳变 | 用模运算+合理性窗口 |
| `micros()` 回绕 | 已有归一化，仍需测试 |
| 接收机内部时延不等于 PPS→PVT | 用信号源/示波器标定，不只看算法 |
| 估计值抖动导致 EKF 切换 | 低通+滞回+连续一致门控 |
| 接入后行为变化 | 先记录后控制，保留默认 15 ms |
