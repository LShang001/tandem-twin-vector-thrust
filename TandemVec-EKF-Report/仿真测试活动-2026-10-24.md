# 飞控全固件超大规模仿真测试活动（2026-10-24）

## 1. 目标与边界

目标：在 Arduino Core 3.0 迁移后的固件基线上，做一次可复现、分层、尽可能大的仿真验证，
覆盖固件控制律、EKF 组合导航、GNSS 延时/振动鲁棒性、全包线闭环与故障场景。

边界：
- **不是实机测试**，不烧录、不替代上板/系留/飞行验证；
- SIL 只链接真实 `flight_control.cpp` / `state_data.cpp`，传感器与执行器是替身；
- Python hifi 是固件语义闭环，不是 C++ 固件 HIL；
- 气动/推进参数仍为 `MODEL-DEFAULT`，结论不代表实机性能。

### 4.9 根因与修复（低延时发散，2026-10-24 追加）

复现 case 54（latency=1.47 ms）：

- `auto_delay=0` 与 `auto_delay=1` 都复现：`fused=1`、`rejected=599`，
  comp pos3d≈1927 m；`base`（无延迟补偿）pos3d=0.076 m；
- 因此根因不在批处理估计器，而在 **EKF 延迟量测年龄处理**。

根因：`Ekf15State::GetDelayedSnapshotIndexByAge()` 在 `delay_s < 0.5*dt_s` 时，
首段累计已超过 delay，但候选误差大于初始 `best_error_s=delay_s`，`best_idx` 仍为 -1，
函数返回 false；`MeasurementUpdateDetailed(..., require_delayed_snapshot=true)`
于是**整帧拒绝** GNSS 更新，comp EKF 从启动起就是纯惯导，低延时子组因此漂移。
5k CSV 中 146 个 >500 m 坏例里 **142 个 latency <2.5 ms**，与阈值一致。

修复：`GetDelayedSnapshotIndexByAge()` 初始化 `best_idx = latest_idx`（最新快照年龄 0，
即 delay 的最近邻），再让更近的历史候选覆盖它；新增 T12 回归（2 ms/4 ms 延迟必须融合）。

修复后验证：

- `test_ekf_15state` **38/38 PASS**（含 T12）；
- case 54：`fused=600/rejected=0`，pos3d=0.076 m（修复前 1940 m）；
- 500 例低延时定向（latency 0–5 ms、auto_delay=1）：**499/500 fused≥500、
  pos<10 m**，P95=0.594 m，max=324.95 m（仅 1 例离群）；
- 全量 5k 复跑（`delay-closed-loop-5k-postfix.csv`，仅含子帧修复）：
  **mean=4.36 m、P95=2.54 m、max=4325.38 m**；`>10 m` 37 例、`>20 m` 32 例、
  `>50 m` 31 例、`>100 m` 27 例、`>500 m` 4 例。**31 个 `>50 m` 案例全部
  `outage=1`**，低延时子组不再发散（原 `<20 ms|无失锁` P95≈1985 m 已消失）。
  剩余尾部是独立的“失锁 + 高振动”机制，见 §4.10。

结论：低延时发散已定位并修复到可解释、可回归的状态；5k 剩余的米级/百米级
尾部全部与 GNSS 失锁相关，进入 §4.10 的恢复机制处理。

- 触发条件（全部满足）：失联 ≥2 s；连续 **3 帧** GNSS 残差都不可信；
  相邻帧 GNSS 速度差 ≤3 m/s（排除单帧/双帧跳点串）；
- 动作：把位置/速度重锚到当前 GNSS（位置按量测年龄用 GNSS 速度前推），
  位置/速度协方差抬到 8/12 m 与 1.0/1.5 m/s，清空延迟回放历史；

  `navigation_task.cpp` 计入 `AidSource::Gnss::reset_count`；
- 回归：`test_ekf_15state` T13（3 帧一致触发）与 T13b（矛盾跳点串不触发），
  共 **51/51 PASS**。

| vib_hz | 20 | 40 | 60 | 80 | 100 | 150 | 198 | 199.9 | 199.96 | 200 |
|---|---:|---:|---:|---:|---:|---:|---:|---:|---:|---:|

199.9 Hz 单频在 200 Hz 采样后变成 ~0.1 Hz 准直流（幅值可达整个 `vib_g`）；

199.96 Hz 时 pos3d 从 21.98 m 降到 **0.275 m**，20–60 Hz 结果不变（通带），
80 Hz 为 0.329 m（约 −3 dB，符合模型）。抗混叠 5k 结果见 §4.10.1。

- mean=0.903 m、P95=2.407 m、P99=3.293 m、**max=4.931 m**；
- `>10 m` / `>20 m` / `>50 m` / `>100 m` / `>500 m` **全部为 0**；
- 26 例触发重锚（每例 1 次）；无失锁子集 max=4.105 m，失锁子集 max=4.931 m；
- 原 8 个 `>10 m` 尾部全部消失；四例失联离群：1439 0.307、2840 0.736、
  3082 1.332、3727 0.210 m。

结论：在 20–200 Hz 全频段、带 IMU 抗混叠模型的 5k 包线内，延时闭环无发散、
无 `>5 m` 案例；最大 4.93 m 与 GNSS 位置噪声（1.5–5 m）和高延时一致，属于
正常估计残差。原始模型（无抗混叠）的 24 m 尾部是测试模型混叠伪影，不是 EKF 缺陷。

边界：本层只检查 GNSS 帧间速度一致性，位置多径/慢变偏移仍依赖上游 fix
质量门控；失联期间飞控仍必须执行失效保护。该机制是“恢复”而非“失联可飞”。

## 5. 结论摘要（截至当前快照）

- **通过**：GNSS 延时批处理 10k（99.9% ≤20 ms）、导航验收 4/4、SIL 验收 3/3、
  全包线有效场景 9/9、P0 航向口径改善、宿主/GCS/Node/静态门禁。
- **延时闭环 5k 已从 FAIL 修到 PASS（原始振动模型）**：两个独立根因——
  ① `GetDelayedSnapshotIndexByAge()` 对 `delay < 0.5*dt` 返回 false，整帧拒绝
  延迟 GNSS（修 `best_idx=latest`，补 T12）；② 高振动 + 长失联后纯惯导漂出
  25 m/6 m/s 残差门，GNSS 永久拒绝；新增连续 3 帧一致后的自动硬重锚
  （T13/T13b）。全量 5k **mean 0.908 m / P95 2.419 m / max 24.078 m，
  `>50/100/500 m` 全为 0**；剩余 8 个 `>10 m` 已定位为 199–200 Hz 近 Nyquist
  混叠伪影（§4.10），不是滤波发散。给仿真台加 IMU 抗混叠模型后同一 5k：
  **mean 0.903 / P95 2.407 / max 4.931 m，`>10 m` 为 0**。实机仍应保留 GNSS
  失效保护，并用实测振动谱确认 ODR 前 LPF。
- **已知边界失败**：SIL `flow1 seed2` NaN、SIL F4 全部 NaN/90°（单前摆卡死硬件单点）、
  A8_yaw90 目标定义不成立。这些是已知故障/无效目标路径，不计入健康场景通过率，
  但保留在原始结果中。
- **需要复核**：高保真 `run_all.py` 当前是三方程纵向参考点，旧 README/JS 是四方程全配平；
  δt/thr/ω0 差异属于口径变化，不应直接判为回归。modes 表新输出只保留 3 个纵向模态，
  需确认 `analyze_modes`/`export_latex` 是否有意裁剪；新表已另存，历史基线未覆盖。
- **测试设计问题**：振动 Policy C 的 10k 随机分布大多落在 q=0.25 等价区；
  定向低振动检查才看到 fixed/adapt 差异。后续应按振动/延时分层抽样。
- **覆盖边界**：当前没有 QEMU/Renode 全芯片仿真或硬件 HIL；SIL 只覆盖真实
  `flight_control.cpp`/`state_data.cpp` + 注入传感器，不能替代上板/系留/飞行验证。

## 6.5 证据等级与不可证明项（2026-10-24 追加）

当前没有实机/硬件在环，所有结论必须按以下等级标注，不能把“模型自洽”写成“实物正确”：

| 等级 | 含义 | 本项目当前证据 |
|---|---|---|
| L0 | 代码/数学自洽 + 宿主单元回归 | `test_ekf_15state`、`run_all.sh`、GOV-004 |
| L1 | 模型级仿真（Python hifi / MC 台） | 5k 延时 MC、hifi 全包线、参数扫频 |
| L2 | 真实固件源码 + 注入传感器的 SIL | `fw_sil`、`--real-nav`、SIL 矩阵 |
| L3 | HIL/硬件在环 | **未做** |
| L4 | 系留/飞行实测 | **未做** |

**不能证明（必须标“待实测”）**：

- 真实气动/推进模型是否准确（kT/kQ、阻力、桨效、电池压降）；
- 真实 IMU/GNSS/气压/磁/光流的噪声、振动、温漂、延迟、标定误差；
- 真实舵机/电机滞后、回差、饱和、卡死/推力损失；
- 真实任务调度、CPU 负载、栈/内存、看门狗时序；
- 实机稳定裕度、失效保护是否真能救回。

**当前可写/不可写**：

- 可写：“在假设 X（传感器模型、参数范围、无气动/无硬件）下，算法逻辑/边界通过 L1/L2”；
- 不可写：“实机没问题”“全包线通过”“失效保护已验证”；
- SIL 的传感器模型是 **MODEL-DEFAULT**，不是实机标定；`--real-nav` 是 L2，不是 HIL。

## 6.6 EKF 进控制闭环定位与真实导航 SIL（2026-10-24 追加）

### 6.6.1 EKF-in-loop 10/10 FAIL 根因（L1 消融）

- 控制用**真值姿态**、EKF 只做导航：5 seeds × A0/A2/A9 全部 0.7–2.4°、
  位置 0.5–1.7 m；控制用 EKF 姿态：A0 3.5–38°、A9 可达 68°。
- 根因是**悬停姿态/航向不可观**：闭环速率抖动使静止检测的
  `|ω|<0.01 rad/s` 门永不满足（A0/A2/A9 静止确认 0%），ZUPT/重力/静止陀螺
  全部关闭，EKF 姿态误差 1:1 进入控制回路。
- 默认 `run_full_envelope.py` 无位置保持/磁矢量，A2/A5/A3 的 `pos_ne` 不能
  单独当控制失败判据；A0/A9 的 EKF-vs-真值位置也不等于控制失败。
- 加 `--pos-hold --mag-vector --flow-aiding --baro-hz 2 --baro-phase 2`：
  **A0–A7/A9 全部 PASS（9/9，A8 目标定义不成立单列）**；A9 0.32 m/0.43°、
  A5 0.51 m/0.42°。这是 L1 + 理想磁/光流，不是固件/实机结论。
- 固件新增 `MeasurementUpdateMagVectorDetailed`（T15 验证），但磁力计数据链、
  软/硬铁标定、干扰门控尚未接；SIL `--mag` 只是实验路径。

### 6.6.2 真实导航任务 SIL（L2）

新 `--real-nav` 把真实 `navigation_task.cpp` + 真实 UBX 解析接入，2 kHz IMU、
200 Hz 导航、GNSS 延迟/噪声/失联/野值、气压、光流、RC 丢失、IMU 丢样：

- clean/nominal/degraded × 3 seeds **9/9 PASS**；
- clean final_alt≈10.0 m / hold_end 1.1–1.5 m；nominal 9.2 m / 0.5–1.4 m；
  degraded 6.1 m / 0.6–1.1 m（气压漂移），野值拒绝 5–7 次；
- RC 链路丢失单独注入真实 `linkDownCallback`：飞行中保持解锁 + AUTO_ALTITUDE，
  不再把“命令 disarm 后坠落”混进传感器退化验收；nominal + `--rc-loss 30:31`
  实测 final_alt 8.18 m、hold_end 0.87 m，无空中 disarm；
- 修复项：anti-alias 按 2 kHz ODR（800 Hz）、32-bit 虚拟时钟、IMU 丢样补 dt、
  逐帧统计、GNSS 初始化/重锚质量门、NMEA 回退、假原点重锚、静止油门门控。

**证据等级**：本 SIL 是 L2（真实固件源码 + 注入传感器），不是 HIL；传感器参数
为 MODEL-DEFAULT，不能证明真实气动/推进/传感器/执行器/调度行为。

### 6.6.4 IMU 故障注入（L2，2026-10-24）

在 real-nav SIL 注入 1 s IMU NaN / 2 s 输出冻结：

- 修复前 NaN 直接进入控制/混控，出现 `servo=nan`、位置/姿态 NaN；
- 修复后 `navigation_task` 跳过非有限 IMU 帧，`flight_control` 陀螺保持上一有效值，
  **不再输出 NaN**；但 1 s NaN/2 s 冻结仍会导致姿态/位置失稳（无 IMU 故障检测与
  failsafe），属于失效路径边界，不是通过项。
- 结论：需要增加 IMU 非有限/冻结检测（方差/一致性）并接入可控下降；当前只做了
  NaN 传播防护，没有故障恢复。
- **GNSS spoof（h_acc 正常）**：20 m 位置台阶（15 s 起）被融合
  （outlier_rejects=0），pos_rms=16.45 m、hold_end=20.04 m；20 m + 0.5 m/s
  慢偏 pos_rms=23.79 m、hold_end=32.46 m。30 m 野值门对“小于门限且自报精度
  良好”的欺骗无效；需要 GNSS 与惯导/气压/光流的交叉一致性或外部基准，
  当前没有。**这是已确认的失效路径，不是通过项**。

## 7. 建议

1. **上板/系留回归优先**：SIL 和 Python hifi 不能替代硬件；重点验证 IWDG、8 路串口、
   PWM/舵机方向与 ±15° 限幅、ADC、I2C/SPI 传感器、2 kHz 调度与 200 Hz 导航时序。
2. **复核 SIL `flow1 seed2` NaN 与 F4 全发散**：前者是 0.1 s 光流延迟路径，
   后者是单前摆卡死硬件单点；应在故障注入/硬件在环中单独建预期与安全边界。
3. **实机验证 GNSS 长失联重锚**：用录包/系留注入“失联 5–15 s → 恢复”，检查
   `AidSource::Gnss::reset_count`、位置/速度跳变和控制回路响应；上游 fix 质量/
   跳点门控必须保留，失联期间飞控失效保护不能被该恢复路径绕过。
4. **实测 IMU 抗混叠与振动谱**：仿真台的 `anti_alias` 是 8 阶 Butterworth
   假设；上板后用真实振动谱确认 ICM-42688 在 200 Hz ODR 下的 LPF 配置，
   不要把仿真台的通带当成实机结论。
5. **复核高保真配平/模态表**：`run_all.py` 的新 δt/thr/ω0 与旧论文基线不一致，且
   modes 表缺行；先确认 `trim_analysis.py`/`export_latex.py` 的版本与理论口径，再决定
   是否回写论文数据。历史基线和本次新表已分开保存。
4. **重做 Policy C 验证**：不要再用宽随机 10k；按“低延时/无失锁/低振动”和
   “高振动/失锁”分层抽样，统计配对差与置信区间。
5. **全芯片/硬件 HIL**：如需真正“全固件”验证，下一步应引入 QEMU/Renode 或
   硬件在环台架（含真实传感器/执行器/通信），当前软件仿真已到边界。
