CTL-008 单涵道 + X 型四燃气舵机型移植（2026-11-05）

一句话：把外部工程 Universal-EDF（UniversalFCS v4 系列化框架派生的单涵道 VTVL 固件） 的「单涵道推进器 + X 型四燃气舵」机型，按本固件（TandemVec_FCS）的分层接入第三种机型： 复用导航/任务/传感器/姿态环，只替换 L2 分配与 L3 输出；编译期开关 BFS_SINGLE_EDF_4VANE， 默认纵列双发与共轴构型行为零改动。

状态：2026-11-05 已完成首次自由飞（出厂默认参数即稳定）；代码级接入与 AnoCom 在线调参链路均已完成。质量/推力/舵效/惯量仍为 MODEL-DEFAULT 未实测，舵效矩阵与 参数实测待补；台架/带动力测试须按 §7 标定阶梯执行。

1. 源机型研究结论（Universal-EDF）

1.1 它是什么

项 值
工程 Universal-EDF（外部快照，PlatformIO，STM32H743 WeAct Mini）
来源 UniversalFCS v4 系列化框架复制后接入新构型；core 文件逐字节未改
机型 单涵道推进器（EDF/单台可节流发动机）+ X 型四片燃气舵
关键差异 共轴的偏航靠双电机差速；单涵道只有一个推进器，偏航必须由四舵产生

1.2 源实现的控制链

遥控/制导 → 模式判定 → 姿态外环(角度→角速率) → 速率内环(角速率→修正角)
          → 归一化(ControlDemands) → 机型混控器(3×4 分配) → 四舵 PWM + 油门 PWM
  • 层2（混控）是唯一新增的实质逻辑：defl_i = Σ_j H[j][i]·d_j，其中 d_j = 归一化力矩 × 满舵角；四舵联合等比限幅（任一超限整体缩放，保持方向）。
  • 三条推进联锁：未解锁 / 使能开关关 / 大倾角 > 45° → 压最低油门；舵面始终受控。 （本固件后续差异：2026-11-05 停用 CH6 使能联锁、阈值放宽到 120°，见 §4/§8。）
  • 舵方向拆成两级：几何分配符号（矩阵，固定）+ 物理方向符号（VANE*_DIR，待标定）。

1.3 源实测到的分组（台架 2026-09-23）

源工程在设计阶段按"标准 X 型"假设（对角=滚转、前后=偏航），台架实测发现 滚转与偏航分组互换了 90°，代码按实测修正。修正后的分组：

轴（源 FRD） 分组
pitch {1,2} vs {3,4}
roll {2,3} vs {1,4}
yaw {1,3} vs {2,4}

物理原因：舵面产生的力方向由转轴朝向与安装角决定，无法从象限位置推导——只能实测。

1.4 源工程自身的不一致（移植时必须取舍）

# 项 源工程现状 本固件取舍
1 满舵角 参数表 max_correction_deg = 45°，但文档/注释多处写 20°，且 VANE_PWM_SPAN=16.67% 与之绑定 取 20° 保守值（待实测替换），并在注释标注口径冲突
2 反扭矩配平 YAW_TRIM_DEG 加在源 yaw 通道（绕 z_EDF），但其注释写"抵消涵道风扇反扭矩"——反扭矩绕推力轴（源 roll 轴） 本固件把配平明确作用在偏航轴（绕 z_b = 推力轴），并在参数注释写清语义
3 偏航通道油门门控 源 core 的 execute_yaw_controller 要求 throttle_raw > 1050 才出偏航，源工程选择"不改 core" 本固件同样不改该 core 行为；台架标定偏航时必须先关 CH6 使能再推油门摇杆（联锁会把 PWM 压在 1000µs）
4 舵占空比硬限位 33.33/66.66% 与满行程 ±16.67% 完全重合，实际永不触发 保留同样的硬限位作兜底，并在文档写明"真正防撞结构要把 min/max 收窄到实测行程"
5 大倾角联锁：单位 bug 混控器写 fabsf(AHRS_Packet.Roll) > 45.0f，但 AHRS_Packet.Roll/Pitch 单位是 弧度（deta100_types.h）→ 阈值 45 rad = 2578°，该联锁实际从未生效（源 docs/knowledge/roll-spin-tuning.md §3.1 已记录） 本固件改用 acos|R33|（推力轴偏离天向角），singleEdf4VaneThrusterEnable() 只接受已换算角度，单位混用不可能再发生
6 大倾角联锁：语义不匹配 即使修好单位，"竖直箭体正常飞行时 pitch≈90°"会让 |Pitch| > 45° 恒成立 → 恒切推进器（源文档 §3.2 已指出） 判据改为"偏离天向夹角"：竖直=0°、倒扣=180°、绕纵轴自旋不改变该角
7 CH9 角速率档 + 手动舵 手动分支 rollTarget = AHRS_Packet.Roll（rad）被下游当 deg 用 → 实际量级约 1/57，且摇杆被忽略（源文档 §2 记录） 本固件手动/标定分支直接用摇杆映射，不经 core 的 rollTarget，绕开该缺陷
8 舵方向符号状态 头文件 VANE_DIR = (+1,−1,+1,−1)，源 knowledge/ 记录 2026-10-12 用户台架逐舵核对确认无误；但 README/AGENTS 仍写"未标定" 本固件沿用该组符号为默认值（轴置换不改变"舵机正转=哪个物理方向"），并标注"换舵机/换安装必须重标"

2. 轴系映射（本次移植的核心推导）

两套轴名是同一机械布局的纯旋转置换，不能跨文档混读：

项 源机型 Universal-EDF（机体 FRD） 本固件存档系
推力轴 x（推流沿 +x，悬停时指天） z_b（推力轴，悬停竖直指地，推力沿 −z_b）
横向轴 y（右）、z（下） x_b（滚转）、y_b（俯仰）
置换 x_EDF = z_b，y_EDF = y_b，z_EDF = −x_b（det = +1）

★ 物理口径 = 标准 NED/FRD（2026-11-05 用户明确）：导航解算与姿态都是 NED/FRD； 悬停时机头朝天，机体 x_FRD 朝天、推力沿 +x_FRD 朝上。本固件的"悬停存档系"只是 把机头方向命名成 z_b 的负向，固定对应：z_b = −x_FRD、x_b = z_FRD、y_b = y_FRD。 三轴力矩的两种叫法（悬停语义）一一对应：

物理轴（标准 FRD） 固件悬停动作名 单涵道矩阵行 舵分组（源台架实测 2026-09-23） 世界动作
绕 x_FRD（推力轴） 偏航 yaw（绕 z_b） Mz {1,3} vs {2,4} 绕竖直轴 = 航向
绕 y_FRD（右） 俯仰 pitch（绕 y_b） My {1,2} vs {3,4} 前后倾倒
绕 z_FRD（下） 滚转 roll（绕 x_b） Mx {1,4} vs {2,3} 左右倾倒
沿 +x_FRD 推力（油门通道） — 四舵不参与 竖直向上
倾角判据 acos|R33| — — 竖直=0°、倒扣=180°

本固件的分配矩阵 H（行 = 存档系 Mx/My/Mz，列 = 舵1..4），直接取自 include/SingleEdf4VaneAllocator.h:73-75 的 kSingleEdf4VaneMatrix：

      舵1   舵2   舵3   舵4
Mx    −1    +1    +1    −1      绕 x_b（倾覆轴）→ 滚转
My    +1    +1    −1    −1      绕 y_b → 俯仰
Mz    +1    −1    +1    −1      绕 z_b = 推力轴 → 偏航（世界航向）

行序即语义：roll = 绕 x_b、yaw = 绕 z_b（推力轴）。分配器与 plant 共用这张表， 不要把源机型的「roll 是绕推力轴」直接平移过来——那是源机型的轴名，本固件已按存档系重排。

  • 三行两两内积为 0（行正交，编译期 static_assert 锁定），三轴可独立分配；
  • H·Hᵀ = 4I，故最小范数解退化为 δ = Hᵀ·τ/(4k)（k = 单舵舵效 N·m/deg）；
  • 物理解释：纵列的"偏航"（世界航向）对应源机型的"滚转"（绕推力轴）——因为推力轴就是竖直轴； 纵列的"滚转/俯仰"对应源机型的"偏航/俯仰"（倾覆方向）。

★ 矩阵只保证"轴语义对齐"，不保证实物符号。实物方向由 vane_dir[4] 逐舵标定。

3. 移植架构（本固件侧）

runGNCExecutive（200Hz 共用）
 ├─ 步骤1–5 输入/模式/定高/目标姿态          ← 复用（未改）
 ├─ 步骤6 execute_attitude_controller         ← 复用：输出 α_roll/α_pitch（rad/s²）
 ├─ 步骤7 execute_yaw_controller              ← 复用：输出 α_yaw（rad/s²）
 └─ 步骤8 mix_and_output_single_edf()         ← 新增（#elif defined(BFS_SINGLE_EDF_4VANE)）
        ├ 层2a 油门：期望天向比力 → 总推力 → 油门%（ThrustAllocation，可切 F∝w²）
        ├ 层2b 联锁：未解锁 / 倾角 > sedf.att_limit_deg（默认 120°） → 压最低油门（舵仍受控）
        ├ 层2c 四舵：α → τ=I·α → δ=Hᵀτ/(4k) → 逐舵方向 → 联合等比限幅
        └ 层3  输出：kSingleEdf4VaneProfile（4 舵 + 1 油门）→ PA0–PA3 + PC8

为什么复用 α 链而不是照搬源机型的"修正角"：本固件的控制层契约是 α_cmd → L2 分配器 → 执行器（见 ControlContracts.h），速率环输出已是 deg/s²。 单涵道机型的物理换算（τ=I·α、δ=Hᵀτ/(4k)）正好落在 L2 —— 这样姿态环增益与纵列/共轴 同尺度，机型差异全部收敛在分配器里。

引脚（与纵列双发共用同一块板，只换语义）

宏 引脚 纵列双发语义 单涵道语义（舵编号沿用源机型物理编号，方位按本固件存档系 x_b=滚转、y_b=俯仰、z_b=推力轴）
VANE1_PIN PA0 (TIM2_CH1) 上摆/滚转舵机 燃气舵 1（+x_b, +y_b）
VANE2_PIN PA1 (TIM2_CH2) 下摆/俯仰舵机 燃气舵 2（−x_b, +y_b）
VANE3_PIN PA2 (TIM2_CH3) 前电机 燃气舵 3（−x_b, −y_b）
VANE4_PIN PA3 (TIM2_CH4) 尾电机 燃气舵 4（+x_b, −y_b）

★ 飞控与传感器安装方向、机体外形与共轴 VTVL 完全一致（用户 2026-11-05 确认）， 因此全链只用同一套存档系轴名：姿态量、分配矩阵、输出槽位、倾角判据都是 x_b=滚转、y_b=俯仰、z_b=推力轴。源机型机体 FRD 的象限（(+Y,−Z) 等）只作 编号对照，等价关系见 state_data.h 的引脚注释；置换由 kSingleEdf4VaneMatrix 吸收。

PWM 全局 333 Hz / 16 bit（airframe_common 的 CUSTOM_PWM_FREQUENCY）；四舵与油门共享。

★ 已修复的一处一级安全冲突

纵列固件的 process_control_inputs 尾部有一行"燃料阀门"输出：

SetServoPos(inputs.is_manual_tvc ? 100.0f : 0.0f, SERVO7_PIN);   // PC8

单涵道机型下 PC8 已重定义为推进器油门——手动舵（CH8 高位 >1750， 即 is_manual_tvc=true）时这行会把推进器直接推到 满油门 2000µs。移植时已用 #ifndef BFS_SINGLE_EDF_4VANE 屏蔽，并注释说明 "PC8 由混控器独占"。这是移植审查发现并修掉的真实缺陷。

CH8 极性说明：固件判据是 raw_rc_values[7] > 1750 为手动 TVC （flight_control.cpp:273），低位（默认）= 飞控自稳介入。上电无信号时 raw_rc 全 0 → 低位 → is_manual_tvc=false → 走锁定分支，这是有意的安全设计。

4. 安全联锁（与源机型同语义）

# 联锁 实现位置 行为
1 未解锁 mix_and_output_single_edf 推进器强制最低油门；四舵可动（地面检查）
2 CH6 推进使能关 同上 2026-11-05 已停用（用户要求）：CH6 不再影响推进器，解锁后油门指令直达电调；代码保留 (void)ignition_enabled 与恢复方法注释
3 大倾角 > sedf.att_limit_deg（默认 120°，在线可调 10–180°，180° 等效关闭） 同上（acos|R33|：推力轴偏离天向角） 推进器最低油门；舵保持受控。★ 源实现用 |Roll|/|Pitch| > 45° 比较，因"字段单位是 rad"与"竖直飞行时 pitch≈90°"双重失效；本移植已按 acos|R33| 修正。阈值 2026-11-05 由 45° 放宽到 120°（大机动/翻跟头时切推力反而失去恢复能力）
4 四舵联合限幅 allocateSingleEdf4Vane 任一超满偏角 → 整体等比缩放（方向不畸变）
5 舵占空比硬限位 mapSingleEdf4VaneOutputs 33.33–66.66% 兜底钳位
6 参数/输入非法 分配器 四舵回中位（不保留上一拍偏置）
7 无链路 混控器手动分支 四舵中位（上电 raw 全 0 不会被钳成满偏）

联锁（未解锁 / 大倾角）只切推进器，舵面始终受控：地面检查舵面需要舵能动；飞行中 姿态失控时保留舵面控制比回中更利于恢复（与源机型一致的刻意设计）。

8. 与源机型的有意差异

项 源机型 本固件 理由
控制层输出 修正角（deg） α（rad/s²）→ 分配器换算 与纵列/共轴同契约，姿态环增益同尺度
油门曲线 线性 线性（可用 BFS_THRUST_CURVE_QUADRATIC 切 F∝w²） 保持与纵列一致；EDF 物理口径需标定后启用
故障诊断 无 未接 ActuatorFaultMonitor（按纵列 dMax 口径标定） 首次移植不引入未标定阈值
在线辨识 无 未接（TandemVec 差速/摆座专用） 不适用
遥测 四舵各自通道 三轴力矩 + 前两舵角（0x40 帧未扩展） 不扩协议，避免动 GCS 解析
满舵角默认 45°（代码）/20°（文档） 20° 保守值，待实测
大倾角切推进阈值 45° 120°（在线可调 10–180°，180° = 关闭） 用户 2026-11-05 要求放宽：45° 太保守，大机动/翻跟头时切推力反而不利恢复
