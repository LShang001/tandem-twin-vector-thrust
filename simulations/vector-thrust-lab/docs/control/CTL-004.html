CTL-004 固件-仿真一体化

目标：固件是唯一算法源，仿真只是适配器。任何算法（导航、控制、分配、参数） 只保留一份实现；仿真通过稳定 ABI 调用它，而不是在 Python/JS 里再写一遍。 本文给出分层、ABI 契约、消费者登记表、扩展步骤与边界；控制律本身见 CTL-001，多机型抽象见 CTL-003。

1 要解决的问题

症状 后果
同一算法在固件与仿真各一份（如 hifi_core.FirmwareControl） 固件修复（nav-raw、速率环量纲、轴置换）必须再改一次 Python；两份结论可能相反
仿真脚本各自维护编译参数/源清单 宏不同（如 FW_SIL_REAL_NAV、EKF_NAV_TELEMETRY）⇒ 跑的不是同一份代码
实验不知道"这条特性到底编进去了没有" 把"没启用"误判成"无收益"（§4.24o 构造性无差异）

一体化后的判据：删除任何一份复刻实现，仿真结论不变；新增算法只改固件源码 + 源清单。

2 架构：一份源码，两个链接目标

TandemVec_FCS/src/*.cpp + include/*.h（平台无关模块）
        │
        │  唯一源清单：test_host/fw_algo/build_fw_algo.sh::CORE_SOURCES
        │
        ├──► fw_real.exe      SIL：固件核心 + plant 主循环（test_host/fw_sil）
        │
        └──► fw_algo.dll      宿主直调：固件核心 + 三组 C ABI
                 ├─ L1  fw_ekf_*    15 态 ESKF（fw_algo_api.h）
                 ├─ L2  fw_alloc_*  分配 / 推力（fw_ctrl_api.cpp）
                 └─ L2  fw_gnc_*    控制链 + 能力查询 + 参数注册表（fw_gnc_api.h）
  • SIL 与直调库共用同一份 C++ 源：flight_control.cpp、navigation_task.cpp、 state_data.cpp、ano_params.cpp、ublox、DPS310、Madgwick、单位库、SIL 桩。
  • 库默认输出到 ASCII 临时目录（MinGW 不能在中文路径链接），Python 侧按 mtime 增量构建。
  • 新增一个固件 .cpp 时，必须同时加进 test_host/fw_algo/core_sources.sh；build_fw_algo.sh 会先做漂移检查（SIL 的 build_incremental.sh 缺同一条目就直接失败），避免两侧跑不同代码。

3 ABI 契约（v1）

约定 内容
版本化结构 所有入/出结构前两字段 = struct_size + abi_version；加字段只能追加尾部，库只写自己已知长度
返回码 fw_gnc_step：0 成功 / 1 空指针 / 2 ABI 不匹配 / 3 输入结构过小 / 4 输出缓冲过小 / 5 数值非法
单例 控制层 PID/滤波器是全局状态：一个进程一个实例；多条独立轨迹用子进程隔离
角速度 输入必须是已去偏的实测角速度（库内 nav_ekf 不运行，零偏恒 0）
时间 调用方推进：每次 step 把虚拟时钟前移 dt_s（millis()/micros() 与固件一致）
单位 遥控 PWM µs；执行器输出 %（0–100，固件混控层原值）；姿态 rad / 角速率 rad/s / 摆角 deg
可观测性 输出同时回报 mode_degraded_heading/gnss、failsafe_in_flight、actuator_fault_bits（舵机卡死/推力损失/请求下降）⇒ 实验能区分"控制变差"与"门控降级/故障"；另回报 target_alt_m、specific_force_up_mps2、thrust_cos_tilt、throttle_cmd_pct，用于把"高度环输出"与"推力分配"分开对拍

3.1 能力查询（fw_core_caps）

回报 core/ekf/ctrl/gnc/nav 五个 ABI 版本、param_count、vehicle_profile （tandemvec / coaxial_vtvl / liquid_rocket）、feature_bits（raw-imu、失联速度保持、 失联定高、长失联下降、气压健康门、GNSS 垂直门、gnc_available、nav_available）、 build_id（git 短哈希）。nav_abi_version 追加在结构尾部（旧字段偏移不变）。

实验脚本必须用 fwapi.caps() 断言特性位，而不是假设"默认开/关"。

3.2 参数注册表（fw_param_*）

直接复用固件 ano_params.cpp 的 133 项注册表（与 GCS 0xE0–0xE3、MAVLink PARAM_SET 同一份）：按名查找、读、写、写后 applyFlightCtrlParams() 无扰同步。 ⇒ 仿真调参与实机在线调参语义一致，不再维护第二张参数表。 fwapi.param_dump() 可一次性导出名字→值字典，实验开始时落盘即可复现参数集。

5 扩展步骤

  1. 新增算法：写到 src/（有硬件依赖）或 include/（平台无关），配宿主测试与 opt-in 宏；加进 CORE_SOURCES；SIL 与直调库同时获得。
  2. 新增 ABI 字段：追加到结构尾部 → 升 abi_version → 在 fw_core_caps 增特性位 → Python 结构体同步；旧调用方按 struct_size 自动兼容。
  3. 新增消费者：只依赖 ABI（Python/MATLAB/C++/未来 WASM），禁止复制算法。
  4. 新增机型：编译期 profile（BFS_COAXIAL_VTVL 等）+ caps.vehicle 标识； 运行期多机型仍是下一步（见 §7）。
  5. 新增实验设施：SIL 研究开关放 FW_SIL_REAL_NAV 内并进 trace/JSON 自证据， 不改变生产默认。

6 验证记录（2026-10-29）

  • 构建：bash test_host/fw_algo/build_fw_algo.sh → fw_algo.dll（1.2 MB，冷构建约 4 min，增量约 3 s）。
  • run_fw_gnc_demo.py：caps（gnc_abi=1、param_count=133、vehicle=tandemvec）、参数往返、 上锁电机 <5%、定高误差 0→5 m 时油门 31.2%→43.1%、ABI 返回码 0/2/3/5 全通过； python -m fwapi selftest PASS。
  • SIL ↔︎ 直调库逐拍对拍（sim/check_fw_gnc_parity.py + SIL --trace-ctrl）： 5 个 profile（mag_clean 20 s；nominal / mag_nominal / degraded 各 15 s；manual 8 s）， 每 profile 1600–4000 拍。修复根因后全部通过预登记严格判据 C4b 与工程判据 C6：

⇒ 控制输出（执行器/摆角/差速/角速率指令/角加速度）在全部 profile 上达到 CSV 精度量级 （最差 0.0057%，阈值 1%）。alt_err 是只读诊断：它只在 AUTO 分支刷新，手动模式保留 各自最后一次 AUTO 的历史值 ⇒ 不参与控制等价判定（单独限 0.5 m）。

  • 根因（2026-10-29 收口）：is_origin_lla_set 是控制链的隐藏输入。 固件 process_control_inputs() 在“原点未建立”时把 relative_* 兜底清零（真机上电未定位时 防止上一架次残留）。宿主 ABI 只注入 relative_down，从未置位该标志 ⇒ 控制链每拍看到 高度 0，表现为 alt_err ≡ target、自动模式电机 % 残差 0.24–4.89%（手动模式不经高度环， 所以一直是 5e-5）。修复：fw_gnc_step 在注入点每拍重申 is_origin_lla_set = true （fw_gnc_create 也置一次）；修复后残差 4.89% → 0.0057%。
  • 本轮对拍抓出并修复的 ABI 缺陷（每条都有“失败→通过”的实测证据）：
    1. 原点标志（上述，影响最大）；
    2. 航向口径：固件 AHRS_Packet.Heading 用 wrapAngleTwoPi（[0,2π)），ABI 原用 quaternionToEuler（±π）⇒ yaw 指令差 ±24 dps；
    3. 角速度源：控制链用 icm_gyro_* 重新两级滤波，ABI 只注入滤波后值 ⇒ 二次滤波 且实际忽略了输入（姿态环差 2968 dps²）；
    4. 单例生命周期：fw_gnc_destroy 未清空静态指针 ⇒ 第二次 create 返回悬空指针（堆损坏）；
    5. 缺失输入：导航层门控 g_heading_hold_allowed / g_pos_hold_degraded / g_gnss_outage_age_s 未注入 ⇒ 航向锁走保守分支（yaw 0 vs ±24 dps）。
  • 诊断代码自身的坑：alt_err/target_vz 最初只在“油门杆死区内”分支赋值，出死区后 两边各自停在不同的历史值，制造出假的 4.39 m 高度误差差（看起来像固件缺陷）。 已改为函数末尾每拍无条件刷新。判据：任何被用作对拍/验收信号的诊断量，必须每拍刷新， 不能在单分支里赋值。
  • 行为中性对照：missile seed 73 @23 500 N 在加入 trace/注入设施前后均为 pos_rms 35.16 / 拒帧 25 / 重锚 1（共享核心与新增设施不改导航行为）。

6.1 姿态目标直驱 ABI（fw_gnc_track_step，2026-10-30）

给 execute_attitude_controller + execute_yaw_controller + mix_and_output_commands 一个"目标姿态 + 油门"入口（跳过遥控模式机），供没有 RC 的宿主（模型系仿真/HIL）复用 同一条姿态/速率/分配子链。run_fw_gnc_track_demo.py 13 项断言： 零误差角加速度 0 / 摆角居中、+roll/+pitch/+yaw 目标同号有限、油门 0/30/70/100 直通单调、 大误差有界、摆角 0–100%、ABI 返回码 2/5。 行为中性：flight_control.cpp 仅新增导出的 setYawHoldReferenceRad() 与遥测写入， 5 个 profile 重跑对拍与归档逐项一致（最差仍 0.0057%）。

6.2 导航步进 ABI（fw_nav_*，2026-10-30）

fw_nav_api.h + fwapi.Nav：输入 = 导航任务 200 Hz 消费的外部量（聚合 IMU 和/双子样、 AHRS 四元数、GNSS 历元字段、气压、磁、光流、解锁/油门），库内生成 NAV-PVT/EOE 帧走 真实 UBX 解析器，再调 handleNavigationSystem()；输出 EKF 状态 + GNSS/气压/航向门控状态。 边界：sensor_imu.cpp 的 2 kHz 低通与 Madgwick 不在共享核心里（硬件耦合）， 那一层由调用方负责 —— ahrs_quat_wxyz 就是它的输出。

run_fw_nav_demo.py（1.5 s 地面对准 + 飞行，含 2 kHz 聚合 ×10 与微量噪声）： 静止悬停水平误差 0.19 m（float32 LLA 量化）、高度 0、航向 −0.02°； 2 m/s 匀速北向速度 2.000 m/s、绝对位置误差 1.00 m；ABI 返回码 2/3/5 与 reset 全部通过。 踩坑：理想恒定 IMU 会被固件 IMU 健康检测判成"精确冻结（Failed）"并停止积分 ⇒ 导航永不初始化；合成输入必须带噪声（demo 用 σa=2e-3、σg=2e-4）。

7 边界与未做

  1. 浏览器仿真未接 WASM（工具链缺失，已探测）：本机 which emcc em++ emsdk clang wasm-ld 全部为空 ⇒ 当前无法产出 WASM。接入配方（装好 emsdk 后）： em++ -std=c++17 -O2 -DTANDEMVEC_FIRMWARE -DFW_SIL_REAL_NAV -DARDUINO=300 -sMODULARIZE=1 -sEXPORTED_FUNCTIONS=_fw_gnc_create,_fw_gnc_step,... $FW_CORE_SOURCES， 即与 core_sources.sh 同一份源清单；vector-thrust-lab 在此之前仍标注"设计模型"。
  2. 单例：固件控制层 PID/滤波器为全局状态，一进程一个实例；批量独立轨迹用子进程。
  3. 机型编译期：运行期多机型需要把 runGNCExecutive 的机型分支改成 profile 查表， 属 CTL-003 的后续工作。
  4. L3 导航步进 ABI（fw_nav_*）未做（2026-10-30 已做，见 §6.2）：fwapi.Nav 可直接驱动 handleNavigationSystem()（含真实 UBX 解析器/门控/重锚）； 传感器层（2 kHz 低通 + Madgwick + 高频振动通道）仍在调用方侧，这是有意的边界。 未做：把高频振动/自适应 Q 的输入（vib_high）也做成 ABI 输入；在此之前 振动/降级 profile 的对拍不成立（见 §6.2 表）。
  5. hifi 复刻迁移：判定为"不可机械迁移"（2026-10-30）。hifi_core.FirmwareControl 与固件控制链不是同一刚体坐标约定：hifi 的模型系是 x'=推力轴 / y'=下摆 / z'=上摆， 固件 SIL 按 M_body=(−Mz', My', −Mx') 把它嵌进 FRD（fw_sil_main.cpp:57）， 两者相差一个反射 + 惯性轴分配不同。用 sim/hifi/check_fw_ctrl_frame.py 枚举 全部 24 个真旋转做物理符号测试（模型系 +1° 误差应产生 M·e>0）， 结果 0/24 通过 ⇒ 不存在能把两系对齐的刚性置换；换控制器必须同时改 hifi 的 刚体/惯性约定，属于 plant 模型变更。因此 FirmwareControl 明确登记为 "设计模型 L1 控制器"（不是固件复刻），hifi 的结论不外推到固件。 证据 sim-data/hifi_fw_ctrl_frame_2026-10-29.json。
  6. 高度/油门回路的等价性未闭环（2026-10-29 已闭合）：根因是宿主未置位 is_origin_lla_set，控制链每拍看到高度 0。修复后 5 个 profile 全部通过严格判据 （最差 0.0057%）。余留：alt_err 等诊断量在手动模式下是历史值，不能当控制等价信号。
