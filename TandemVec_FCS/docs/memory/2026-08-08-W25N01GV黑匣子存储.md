# 2026-08-08 W25N01GV NAND Flash 黑匣子存储实现

> 主题：板载 W25N01GV (1Gbit NAND, SPI3) 驱动从零实现 + 黑匣子日志层。
> 关联：`lib/W25N01GV/`（命令层+日志层）、调试命令 `flash` 组、`docs/电路拓扑参考.md` §12.2。

## 要点

### 1. 芯片关键事实（datasheet）
- 1Gbit SLC NAND：页=2048B+64B spare，块=64页，共 1024 块，坏块≤20（BBM LUT 可重映射）
- **ECC 上电默认使能**（SR2 配置寄存器 ECC_E=1），写页自动算 ECC 存 spare 区
- **上电块写保护**（SR1 BP 位默认保护！必须先清，否则页编程 P-FAIL）
- SR3 状态寄存器：BUSY(bit0)/WEL(bit1)/LUT-F(bit2)/ECC-1:0(bit4-5)/P-FAIL(bit6)/E-FAIL(bit7)
- 命令：读ID 0x9F / 块擦 0xD8 / 页编程=装载0x02+执行0x10 / 页读=0x13+读0x03 / BBM 0xA1 / 状态寄存器 SR1=0xA0写 SR2=0xB0写 SR3=0xC0读
- 时序：页编程~0.7ms、块擦~2ms（BUSY 轮询）

### 2. ★ SPI 硬件 NSS 与手动 CS 冲突（本次最隐蔽的坑）
- `SPIClass(mosi, miso, sclk, ssel)` 传 ssel 引脚 → spi_com.c L255-256 设 `SPI_NSS_HARD_OUTPUT` + L339 `pinmap_pinout` 把 ssel 配成 AF
- 结果：读 JEDEC ID 全 0x6E（MISO 无响应，SPI 时序被硬件 CS 干扰）
- **修复：SSEL 传 NC（默认 PNUM_NOT_DEFINED）→ `SPI_NSS_SOFT`，CS 完全由驱动 `digitalWrite` 手动控制**（命令层本就手动拉 CS）
- 排查过程：0x6E 连续重复 = MISO 读到发送数据自身 → 引脚/时序问题 → 读 variant SPI3 映射（PB2=AF7/PC11=AF6/PC10=AF6/PA15=AF6 都在）→ 定位 NSS 冲突

### 3. 架构（3 层）
- **命令层** `W25N01GV`：读ID/擦块/页写/页读/状态，全部阻塞 BUSY 轮询 + noInterrupts 保护事务，SPIClass 注入（仿 CAN_SPI 模式）
- **日志层** `W25N01GVLog`：RAM 环形缓冲(32帧) + `logPush()`(µs级非阻塞) + `logService()`(每tick≤2帧预算) + 顺序游标 + 游标持久化(super page=倒数第8页) + 坏块跳过(整块)
- **帧格式**：magic(0xAA55) + seq(4) + t_ms(4) + payload(84) + CRC8（复用 lib/crc8 的 Crc8 类，注意 len 是 uint8_t<255）

### 4. 验证结果（全部通过）
- `flash id` → 0xEF/0xAA/0x21（芯片点亮）✅
- `flash test` → 5 帧写入+读回，magic=0xAA55, seq 正确, CRC 通过 ✅
- 掉电恢复：复位后 cursorPage 正确恢复 ✅
- 续写：从上次游标继续，无覆盖 ✅

### 5. 调试命令（DBG 模式）
- `flash id | erase | stat | dump <page> | test | export <page> <count>`
- 后台写任务：`handleFlashService` 100Hz 注册（main.cpp），每 tick ≤2 帧

## 要点 6: v2 优化（2026-08-08 晚，I/P 差分帧 + 环形段 + 坏块表）

### 6.1 帧格式 v2（参考 Betaflight flashfs）
- **I 帧**（全量，每 32 帧）：magic(2)+type(1)=0x49+seq(2)+t_ms(4)+21×float(84)+crc16(2) = 95B
- **P 帧**（差分，其余 31 帧）：magic(2)+type(1)=0x50+seq(2)+dt_ms(2)+21×int16(42)+crc16(2) = 51B
- 差分量化 `(cur-prev)*100`，I 帧重置参考，误差不累积
- 平均 52.4B/帧，容量提升 ~1.8 倍（v1 的 CRC8→CRC16）

### 6.2 存储管理 v2
- 环形段（32 块/段 = 2048 页），段头页持久化游标（每段一次，磨损 ÷64）
- 上电坏块表扫描（spare 区 0x00 标记）+ 运行时 P-FAIL 跳过（限 64 页防死循环）
- ★ 页内打包默认关闭（每页 1 帧稳定模式）——大页 2048B 传输在 stm32duino SPI 层不稳定（多次实测卡死主循环/IWDG 复位），每页 1 帧（95B）写入稳定。后续换 SPI DMA 再启用打包（容量可再 ×40）

### 6.3 ★★★ 本次最隐蔽的坑：非对齐 float 访问 HardFault（根因）
- **现象**：`flash test` 第二帧（P 帧）后板子复位循环，OpenOCD 抓到各种假象（spi_transfer 卡死/CAN reset/EKF 运行），误导排查数小时
- **根因**：`buildPFrame` 里 `const float *pf = (const float*)payload`——payload 是 `uint8_t[84]` 数组，**地址未 4 字节对齐 → ARM Cortex-M7 非对齐 float 读 → HardFault → 复位循环**！
- **为什么难找**：HardFault 后板子复位，复位后跑正常代码（EKF），OpenOCD 抓到的是"正常"状态；只有**逐步打印**（push#0 ok → push#1 卡）才定位到 P 帧构建
- **修复**：`memcpy(&cur_f, payload+i*4, 4)` 逐元素拷贝（对齐安全）
- **教训**：**uint8_t 数组强转 float*/int32_t* 在 ARM 上必须 memcpy**；调试时"板子复位后看起来正常"是 HardFault 的典型假象，要用逐步打印缩小范围

### 6.4 调试基础设施修复（v2 配套）
- **DBG 检测必须在 handleAnoCom 的 receiveData() 之前**——否则 "DBG\n" 字节被 AnoCom 帧头逻辑（非 0xAB 丢弃）吃掉，调试命令不可靠（2026-08-08 定位）
- **CAN 写页互斥**：Flash 写页（关中断 + 阻塞）让 MCP2515 超时 → CAN.reset() → SPI2 transfer 卡死（OVR）→ 主循环冻结。`s_flashWriting` 标志 + 50ms 窗口跳过 CAN 任务
- **flash test 大栈数组改 static**（2048B 局部数组会栈溢出）

### 6.5 v2 验证结果（全部通过）
- `flash test`：5 帧 push/service/读回 ✅（magic=0xAA55, type=P, progErr=0）
- `datalog 3s`：**pushCount=600, written=600, dropped=0**（零丢帧）✅
- 导出解析：`I=8, P=46` 差分还原正确 ✅
- 板子全程无 IWDG 复位 ✅

## 要点 7: 飞行段管理 + 通道自定义（2026-08-08 晚）

### 7.1 飞行段（S/E 帧）
- **S 帧**（解锁边沿）：magic+type 0x53+段号+起飞t_ms+通道名表（列名自描述）
- **E 帧**（锁定边沿）：magic+type 0x45+段号+时长+帧数
- 工具 `--list` 列出飞行段、`--segment N` 按段导出

### 7.2 通道表自定义（改一行加通道）
- `kBbChannels[]`：{name, get(), scale}——增删通道只改这里
- 固件 payload、Serial3 CSV、S 帧列名三处自动同步
- 导出工具从 S 帧读列名（换通道旧数据仍可解析）

### 7.3 ★★★ 本次踩坑：S 帧变长切分不稳定（根因）
- **现象**：S 帧（变长）在导出时时而解析到时而 S=0
- **根因**：变长 S 帧靠 `\0` 搜索切分——**I/P 帧 payload 里的 0x00 字节会误命中**（find 找到错误的 \0），CRC 错 → S 帧被丢弃
- **修复**：**S 帧改固定长度**（通道名 pad 0x00，CRC 固定位置），工具按固定长度切分——稳定
- **教训**：**变长帧在混合帧流里靠定界符搜索不可靠**——用固定长度 + pad 最稳（或帧内嵌长度字段）

### 7.4 ★ 通道名表截断（连带坑）
- 22 通道名总长 202B，CHNAME_MAX 从 160→192→224 逐级加大才够
- **症状**：S 帧解析出 17 个通道名（截断在 "tvc1"）、或 names 尾截 "r"（rc_throttle 变 r）
- **教训**：**通道名表长度要按实际通道数算余量**（名字长度随通道增减变化）

### 7.5 工具动态通道数
- decode_frames 用 `N_F = PAYLOAD_LEN // 4`（不再硬编码 21）——加通道自动适配
