# 2026-08-08 WS2812 驱动调试全记录

> 主题：PD15 (WS2812B-Mini) 驱动的完整调研、方案选型、踩坑与最终双方案实现。
> 关联：`include/WS2812Status.h`（双方案驱动）、`src/communication.cpp`（DBG 调试串口）、`.agents/docs/hardware-reference.md` §12.3。

## 要点

### 1. H743 硬件限制：TIM4 独缺 CH4 的 DMAMUX 请求
- PD15 = TIM4_CH4（AF2，唯一定时器映射，无 SPI AF）。
- H743 的 DMAMUX1 请求表里 **TIM4 只有 CH1/CH2/CH3/UP**（`DMA_REQUEST_TIM4_CH1..3`=29/30/31, `TIM4_UP`=32），**没有 CH4**。
- 因此 `HAL_TIM_PWM_Start_DMA(htim, TIM_CHANNEL_4, ...)` 在 TIM4 上硬件不触发（DIER.CC4DE 置位但 DMAMUX 无路由）。
- 绕道：用 **TIM4_UP 事件**的 DMA 请求，DMA 目标地址手动设为 `&TIM4->CCR4`（0x40000840），每次定时器溢出更新下一周期占空比 → 800kHz PWM 编码 WS2812。
- 底层可行性已逐行验证：`HAL_DMA_Init` 自动配置 DMAMUX1 CxCR（H7 无独立 dmamux 文件）；`HAL_DMA_Start_IT` 不校验目标地址；`HardwareTimer::getHandle()` 可用但 `hdma[TIM_DMA_ID_UPDATE]` 初始 NULL，必须 `__HAL_LINKDMA` 手动链接。

### 2. Adafruit NeoPixel 库在 stm32duino 上对高位引脚有 bug（勿用）
- 库的 `__arm__` bitbang 路径（`Adafruit_NeoPixel.cpp` L1866）：`volatile uint8_t *set = portSetRegister(pin)`。
- stm32duino 的 `portSetRegister` 返回 `&(GPIO->BSRR)`（32 位寄存器），库用 `uint8_t*` 写 `*set=1` **只写 BSRR 低 8 位** → 只能操作 GPIO 0-7。
- PD15 是 bit15，永远够不着 → 灯不亮。PD8-PD15、PE8-PE15 等高位引脚都受影响。
- 结论：本项目 WS2812 必须自实现驱动，不能依赖 Adafruit NeoPixel / 类似 portSetRegister 方案的库。

### 3. DWT CYCCNT 在 -O3 + 关中断 + 调试 halt 下不可靠
- 自写 `while (dwt_getCycles() - cyc < N)` 时序等待，在 -O3 内联 + `noInterrupts()` 下死锁（PC 卡在循环里，飞控整个卡死）。
- 根因：编译器对 `dwt_getCycles()` 内联后，CYCCNT 计数在关中断/调试场景下行为不稳（也可能 DWT 未真正使能——Cortex-M7 需 `dwt_access(true)` 解锁 LAR 写 `0xC5ACCE55`，见 `SrcWrapper/src/stm32/dwt.c`）。
- **改用纯 NOP 循环延时**（`subs + bne` 3-cycle 循环）最可靠——无外设依赖，纯指令周期。

### 4. 调试串口方案（Serial6 共用，DBG 切换）
- Serial6 = USART6，波特率见 `state_data.h` 的 `SERIAL6_BAUDRATE` 宏（2026-08-07 对齐 2.4G 数传为 2M，随数传模块可调）——抓串口前先查宏值，波特率不匹配会全乱码。
- `handleAnoCom()` 入口拦截 `"DBG\n"`（4 字节）→ 进入调试模式；调试模式下 `handleDebugConsole()` 消费所有输入，命令集：`help / ws <r> <g> <b> / wsoff / wsseq [ms] / wsstat / wsmode <0|1> / wsstatic <0|1> / gpio / ver / exit`。
- `exit` 回正常数传。地面站协议帧头 0xAB 与 "DBG\n" 不会冲突。
- 诊断命令 `gpio` 直接读 GPIOD MODER/ODR/IDR/AFR2 → 确认 PD15 已正确配置为输出模式（MODER bits[31:30]=01）。

### 5. GPIO 直写 BSRR 的正确姿势
- `_setMask = 1UL << pinBit`（BSRR 低 16 位=SET）、`_resetMask = 1UL << (pinBit+16)`（高 16 位=RESET）。
- `_port->BSRR = _setMask` 拉高、`_port->BSRR = _resetMask` 拉低，一条指令原子完成，无需关中断保护 GPIO 本身。
- 读回验证：`(_port->IDR & _setMask) != 0`。

### 6. 当前状态（2026-08-08 完成）
- **★ DMA 方案（TIM4_UP DMA）正式固化**：上电默认 TIM4_DMA（`begin()` 里 DMA 成功则 `setMode(WS_MODE_TIM4_DMA)`，失败回落 bitbang）。
- **已验证**：待机=蓝色呼吸 ✅、故障=红色快闪 ✅（`wsfault 1` 触发）。解锁绿/校准黄需遥控器/校准按键触发，代码路径与已验证状态相同。
- **bitbang 方案（备选）**：能点亮但呼吸亮度梯度失真（NOP 时序参数估算不准，T0H≈0.28µs 偏短），如需完善需示波器校准。
- **两个关键 bug 修复**（DMA 方案从"不亮"到"呼吸正常"）：
  1. **ARR 公式错误**：`Period = clk/800 - 1` 应为 `clk/800000 - 1`（800kHz=800,000Hz，漏三个零）！错误时 ARR 溢出截断（0x93DF=37855），PWM 频率全错。240MHz 无分频正确值：ARR=299, CCR1=192(0.8µs), CCR0=96(0.4µs)。
  2. **DMA UDE 残留竞态**：DMA 传完必须立即 `__HAL_TIM_DISABLE_DMA(htim, TIM_DMA_UPDATE)`（在 `XferCpltCallback` 静态回调里做，经 `_self` 指针访问实例），否则 TIM4 持续产生 UP→DMA 请求、DMA 状态机卡 BUSY、下帧 `HAL_DMA_Start_IT` 返回 HAL_BUSY → 帧跳过 → 灯闪烁。
- 调试命令全集：`DBG\n` 进入，`help/ws/wsoff/wsseq/wsstat/wsmode/wsstatic/wsfault/gpio/tim4/ver/exit`。

### 7. 调试方法论（本案例最有价值的部分）
- **LED 这类外设不亮，先分层验证**：①GPIO 配置（MODER/ODR/IDR）→ ②静态电平输出（wsstatic）→ ③协议时序（示波器/逻辑分析仪）→ ④供电/接线。每层都有明确的通过/失败判据，避免在错误层反复试。
- **读寄存器诊断 > 猜参数**：`tim4` 命令直接读 ARR/CCR4/NDTR/DMAMUX CCR，立刻暴露 ARR 溢出和 DMA 未触发问题——比盲调 NOP 参数高效得多。
- **DMA 外设的"完成回调必须清理请求源"是通用模式**：任何外设驱动 DMA（TIM_UDE、UART_TXE、ADC_EOC），传输完成回调里都要关掉请求使能位，否则残留请求导致状态机卡死。

### 8. 库化重构经验（2026-08-08 第二次踩坑）
- **★ STM_GPIO_PIN(pn) 返回位掩码不是位编号**：`#define STM_GPIO_PIN(X) (1<<STM_PIN(X))`（PinNamesTypes.h L128），PD15 → 0x8000。写 `1UL << STM_GPIO_PIN(pn)` 是 **UB（移位≥32）**，g.Pin/掩码变垃圾值 → HAL_GPIO_Init 配错引脚 → AFR 从未写入 → 灯不亮但 MODER 看似正常。**正确：直接用 `STM_GPIO_PIN(pn)` 作位掩码**（`g.Pin = STM_GPIO_PIN(pn)`、`_setMask = STM_GPIO_PIN(pn)`、`_resetMask = pinMask<<16`）。
- **重构时"初始化在哪一步做"要画清楚**：旧版引脚掩码在构造函数算；库化时移到 beginBitbang()，但 DMA 模式 begin() 跳过 beginBitbang() → 掩码恒 0 → bitbang 永不亮。**所有模式都要用的资源必须在构造函数初始化**。
- **DMA1_Stream6_IRQHandler 在 stm32duino 是 weak→Default_Handler**（startup L399-400），项目未提供强定义。`HAL_DMA_Start_IT` 只设 DMA CR 的 IT 位，不使能 NVIC——**中断从不触发，回调也不执行**。库最终用 `HAL_DMA_Start + HAL_DMA_PollForTransfer`（轮询）彻底绕开中断依赖，130µs 等待对 100Hz LED 任务无影响。
- **configurePinAf 必须在 beginDmaPlatform 内、PWM Start 之前调用**：否则引脚停留在 GPIO 模式，PWM 信号出不到引脚（MODER=01 而非 03）。旧版 setMode 里做，库化时易漏。
- **WS2812Driver 库（lib/WS2812Driver/）已通过全部验证**：DMA 方案蓝色呼吸 ✅、bitbang 方案蓝色呼吸 ✅（F_CPU 推导参数比旧版手调更准，呼吸梯度正常）、F4 跨平台编译 ✅。
