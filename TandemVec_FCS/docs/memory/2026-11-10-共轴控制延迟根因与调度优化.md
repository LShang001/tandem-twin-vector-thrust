# 共轴控制延迟根因与调度优化（2026-11-10）

实飞确认：修复后控制稳定、响应灵敏。本文件记录完整排查过程、根因链、修复手段与踩坑清单，
供后续会话直接复用，不要再重复走一遍弯路。

## 一、现象

共轴（CoaxialVTVL）统一到 UniGNC 通用层之后，出现三类互相矛盾的反馈：

1. 推进油门就大幅摆动、抖得厉害
2. 姿态响应"慢一拍"，晃动机体后修正明显滞后（上位机看波形也慢）
3. 调增益时"小一点软、大一点爆"，没有稳定区

对照：同一块板、同一套代码，换成 ICM-42688（2000Hz）时姿态"非常丝滑"。

## 二、走过的弯路（都是错的，不要重走）

| 尝试 | 结论 |
|---|---|
| 怀疑 EKF 姿态延迟 | 原版固件姿态输出**也是** `bfs::Ekf15State`（原版 main.cpp:2945），不是差异源 |
| 换 Madgwick（backup_ahrs）做 A/B | 该路径姿态被重力缓慢拉回、明显滞后，从未被当主姿态验证过，A/B 无效 |
| 关掉 EKF 在线零偏补偿 | 对抖动无改善；根因不在零偏 |
| 调惯量（0.003 → 0.05 → 0.015） | 惯量与 kp 同缩放时**实际输出舵角不变**，只改数值表示，白忙 |
| 降采样 3200 → 1600Hz | Navigation 耗时 2.51 → 2.45ms，几乎无变化，说明瓶颈不在 IMU 帧数 |
| 删除 FlashLog 任务（而非仅禁用页写） | 改变调度序列，实测 Navigation 反而恶化到 22~25ms |
| 把 DPS310/垂直KF/Debug 标为可推迟 | 被推迟的任务会积压，FPS310 单次读 227us、间隔爆到 24ms，GNC 降到 183Hz |

## 三、根因链（实测数据支撑）

1. **ICM-45686 晶振有 +5% 偏差**：配置 1600Hz，ISR 帧数差分实测 **1683.4Hz**
2. 排空式 `allowed = 1 + elapsed_us × rate / 1e6` 用标称值算，比实际生产**少 5%**
3. 排空频率又受主循环限制（实测 191Hz × 8 帧 = 1528Hz < 生产 1683Hz）
4. → `s_imu_ring` 持续积压到 **123 帧**，并开始 `ring_drop` 丢帧
5. **ring 是 FIFO，排空从最旧端取** → 控制律吃的是 123 帧 ≈ **73ms 之前**的 IMU 数据
6. 表现就是"姿态响应慢一拍"。此前所有增益/滤波调参都建立在这个大延迟上，方向必然全错

**为什么 42688 没暴露**：2000Hz 每 5ms 积 10 帧，`allowed = 1+elapsed×2000/1e6 ≈ 11` 刚好够；
45686 当时配置 3200Hz、每拍 16 帧，本来就紧，再叠加晶振偏差就形成持续欠量（现已降到 1600Hz，每拍 8 帧）。

## 四、修复（四件套）

1. `allowed` 由 `1 + elapsed*rate/1e6` 改为 **`2 + ...`**，每拍补足余量
   （多算的帧 pop 不到会自然 break，无副作用）
2. **ring 积压保护**：深度 > 24 帧（≈15ms）时丢弃最旧帧到剩 16 帧
   宁可丢一段历史，也不能让控制拿几十毫秒前的数据
3. **GNC 执行前强制 `readIMUData()`**：消费掉 handleICM42688 之后 ISR 新推的 1~2 帧，
   保证"控制必须使用最新传感器数据"
4. **陀螺一阶低通曾临时调到 0.30，2026-11-11 已按要求统一回 0.15**（全机型一致）。
   该滤波在 readIMUData 里按 ODR 每帧执行，τ=(1-α)/(α·fs)：α=0.15 时
   45686@1600Hz 约 3.4ms、42688@2000Hz 约 2.8ms；α=0.30 可压到约 1.4ms，
   但会改变已验证机型的滤波行为，故未保留。要再优化应按 ODR 自适应另立任务。

配套：排空单次上限 64→20（打断"卡顿→下次取更多帧→更卡"的正反馈）；
时间基准由"直接跳到 now"改为**按实际消费帧数推进**（避免卡顿后 EKF dt 少算）。

## 五、验证（实机）

修复前 → 修复后：

- `ring_size`：123 → **0**
- `ring_drop`：259 → **0**
- `drain_f` vs `isr_f`：153313 / 152931（差 382）→ **37724 / 37724（完全相等）**
- GNC 迟到：约 20 次/s → **0.8~3.7 次/s**，间隔 max 17.5ms → 8.5ms
- 大卡顿（Navigation 单拍 22~25ms）消失，Navigation 稳定 2.45~2.5ms

**判据（以后查同类问题直接用）**：
`ring_size` 应长期为 0；`drain_f` 与 `isr_f` 必须相等；`allowed` 应略大于每拍实际帧数。

## 六、必须记住的不变量

1. **采样率只有一个真源**：`src/imu_odr_config.h` 的 `bfs_imu_odr::kOdrHz`。
   ODR 配置 / 排空 `kTargetRateHz` / 批量帧 `s_fifo_frame_dt_s` / ISR 抽点频率四处
   全部由它派生（2026-11-11 重构完成），禁止再分别手写。换档位只改那里或 `-DBFS_IMU_ODR_HZ`。
2. **后端禁止吸附**：两个后端的 ODR 映射已改为严格匹配，不支持直接 `begin()` 失败。
   旧的"取第一个 ≥ 目标"逻辑会让 42688 传 1600 时静默跑 2000，是本次事故的成因之一。
3. **ISR 抽点频率 == ODR**：对齐后 `isr_empty` 应为 0（重构前 45686 的 ISR 跑 3200
   而 ODR 是 1600，一半中断空转）。ISR 与 ODR 不等时 `isr_empty` 会立刻暴露。
4. **目标值必须在型号支持列表内**：45686 整数档 50/100/200/400/800/1600/3200/6400；
   42688 为 50/100/200/500/1000/2000/4000/8000/16000/32000（无 1600）。
   采样率还受调度时基 6400Hz 上限约束（`static_assert` 把关）。
5. **Flash 黑匣子扇区擦除会整体卡死主循环 14~28ms**（所有任务间隔 max 同步飙高），
   飞行构型必须禁用页写：任务保留占位（删任务会扰动调度序列），函数内直接 `return`。
6. 调试开关（A/B 宏）验证完必须删干净，否则下次会话会拿错误前提继续推理。

## 七、剩余可优化项（按收益排序，均有代价）

当前实飞值：反馈 `spd_alpha`=0.8、输出 `out_alpha`=0.5、陀螺低通 0.15、`rc_rate`=0.12。

1. 输出滤波 `out_alpha` 0.5 → 0.7：省 3ms（τ 5→2.1ms），代价是舵机跟高频噪声走
2. 速率反馈 `spd_alpha` 已到 0.8（τ≈1.25ms），继续放开收益很小、噪声代价大；
   若要更稳可反向回到 0.4~0.5（τ 5~7.5ms）
3. 加速度计低通 0.02（τ≈29ms）→ 0.05：改善 EKF 重力修正滞后，代价是振动进姿态

**建议一次只动一个，动完飞一次看手感**。三项同时放开必抖。

## 八、偏航换算的特殊说明

偏航链路 `diff = (I_yaw / k_yaw) · α_rad` 只用到**比值** `I_yaw/k_yaw`，不是两个绝对值。
2026-11-10 把 `yaw_moment_nm_per_us` 从 1e-6（SIL 巧合值）重标定到 2e-4（电机差速力矩估算），
同时把 `rate_yaw` 的 kp/ki/out_max/int_limit 全部 ×200 补偿，保证差速输出与等效闭环增益不变。

**任何人改其中一项都必须同步改另三项**，否则差速输出会瞬间变化 200 倍，航向直接失控或失灵。
