## 一、ICM-42688-P 核对结果

| 项目 | 手册要求 | 驱动实现 | 结论 |
| --- | --- | --- | --- |
| WHO_AM_I | 0x75 = 0x47 | `WHO_AM_I = 0x47`，`begin()` 校验失败返回 -3 | ✅ |
| 软复位 | DEVICE_CONFIG(0x11) bit0=1，等待 ≥1ms | `reset()` 写 0x01 + `delay(1)` | ✅ |
| 上电模式 | PWR_MGMT0(0x4E)=0x0F：accel/gyro LN | `begin()` 写 0x0F | ✅ |
| ODR 编码 | 0x01=32k、0x02=16k、0x03=8k、0x04=4k、0x05=2k、0x06=1k…0x0F=500 | 枚举 `odr32k=0x01 … odr2k=0x05 … odr500=0x0F`，写入 CONFIG0 低 4 位 | ✅ |
| FSR | GYRO_CONFIG0[7:5]、ACCEL_CONFIG0[7:5] | `(fssel<<5) \| (reg&0x1F)` | ✅ |
| 量程换算 | ±16g: 2048 LSB/g；±2000dps: 16.4 LSB/dps | `_accelScale=(1<<(4-fssel))/32768`、`_gyroScale=(2000/(1<<fssel))/32768` | ✅ |
| **UI 低通（DLPF）** | **GYRO_ACCEL_CONFIG0(0x52) bit3:0=陀螺、bit7:4=加计；编码 0=ODR/2、1=max(400,ODR)/4、2=/5、3=/8、4=/10、5=/16、6=/20、7=/40** | **旧实现写 GYRO_CONFIG0/ACCEL_CONFIG0 低 4 位（ODR 字段），LPF 从未生效** | ❌→已修 |
| SPI 读 | 16+ 时钟，首字节 bit7=1 读地址，后续字节数据，无 dummy | `transfer(addr\|0x80)` 后连续读 | ✅ |
| SPI 时序 | Mode3、MSB first、≤24MHz | 调用方 `SPISettings(10MHz, MSBFIRST, SPI_MODE3)` | ✅ |
| 温度 | `T = raw/132.48 + 25`（TEMP_DATA 0x1D/0x1E） | `TEMP_DATA_REG_SCALE=132.48`、`TEMP_OFFSET=25` | ✅ |
| 中断 | INT1 数据就绪（未使用，轮询 getAGT） | 未配置 | ⚪ 未用 |

### 修复内容（42688）

- `ICM42688::setLowPassFilter()` 重写：先读 CONFIG0 的 ODR 码 → 按手册编码表（不是 ODR/2^n）
  选最接近目标带宽的档 → 写 `GYRO_ACCEL_CONFIG0(0x52)` 对应半字节。
- 新增 `setLowPassFilterBw(code)`、`selectLpfCode(odr, targetHz)`、`actualLpfHz()`。
- `ICM42688_ImuDevice::begin()` 顺序改为 **先 FSR/ODR、后 LPF**（选档依赖实际 ODR），
  并记录真实截止频率（陀螺 100Hz 目标 → ODR=2000 时 code6=100Hz；加计 50Hz → code7=50Hz）。

### 行为影响（必须上板确认）

修复前 42688 的 LPF 配置实际无效（写错寄存器后又 ODR 覆盖），等效默认/旁路；修复后
LPF 真正生效：高频噪声下降，但**群延迟增加**（100Hz 档约 +1.6ms、50Hz 档约 +3.2ms）。
这会影响姿态/EKF 的相位裕度与 delay 补偿假设，需：
1. 上电日志核对 `actualGyroLpfHz/actualAccelLpfHz` 是否为 100/50Hz；
2. 重跑 SIL/台架，确认姿态环无振荡、GNSS 延迟补偿仍匹配；
3. 若延迟不可接受，可把陀螺 LPF 目标改 200Hz（code4）或旁路（code0）。

## 二、ICM-45686 核对结果

| 项目 | 手册要求 | 驱动实现 | 结论 |
| --- | --- | --- | --- |
| WHO_AM_I | 0x75 = 0xE9 | 库 `inv_imu_adv_init` 校验 | ✅ |
| ODR | 2 倍档：12.5/25/50/100/200/400/800/1600/3200/6400 | 后端表 50…6400，2000Hz 目标落 3200Hz | ✅（无 2000 档属实） |
| UI LPF | IPREG_SYS1_REG_172 / SYS2_REG_131：000=Bypass、001=ODR/4、010=ODR/8、011=ODR/16、100=ODR/32、101=ODR/64、110/111=ODR/128 | `shift 2..7 → Div4..Div128`，宏值 DIV_4=0x01 等 | ✅ |
| FSR | 陀螺 15.625…4000dps、加计 2…32g | 后端开放 125…2000dps、2/4/8/16g（与 42688 对齐） | ✅（有意收窄） |
| DRDY | INT1_STATUS0(0x19) bit2=DRDY（bit3=AUX1_DRDY） | `dataReady()` 读 0x19 & 0x04 门控 | ✅ |
| 数据读取 | UI 数据寄存器 burst（6 轴 + 温度） | `getDataFromRegisters` 一次 burst | ✅（库内实现） |
| 温度 | 原始温度 `temp_data`，按手册公式换算 | `rawRegisterTempToC(last_.temp_data)` | ✅（库函数） |
| SPI | Mode3、bit7=1 读、无 dummy（DS-000577 §9.5） | 库 transport 配置 | ✅（库内实现，待上板确认） |
| FIFO/APEX/中断 | 可选高级功能 | 未启用（轮询） | ⚪ 未用 |

### 待确认项（需上板）

1. `inv_imu_adv_init()` 的默认配置是否开启 FIFO/中断/APEX（轮询路径不应受影响）；
2. SPI 读时序与 CS 建立/保持时间在 10MHz 下的实测余量；
3. 温度换算与 42688 的偏差（两器件温度读数不应直接混用标定）。

## 三、与仿真参数的关系

导航性能测试（`test_host/test_imu_nav_perf.cpp`）的 IMU 噪声/零偏取自：
- 42688：DS-000347 典型值（陀螺 0.0028 °/s/√Hz、ZRO ±0.5 °/s、加计 70 µg/√Hz）；
- 45686：DS-000577（陀螺 0.0038 °/s/√Hz、ZRO ±0.4 °/s、加计 70 µg/√Hz、零 g ±20mg）。

**42688 LPF 修复后**，仿真中的 LPF 假设（一阶 50/100Hz）才与实机一致；此前的仿真是按
"设计意图"而非"实际驱动行为"建模，需在修复后重跑性能矩阵，确认精度变化。
