## 一、ICM-42688-P 核对结果

| 项目 | 手册要求 | 驱动实现 | 结论 |
| --- | --- | --- | --- |
| WHO_AM_I | 0x75 = 0x47 | `WHO_AM_I = 0x47`，`begin()` 校验失败返回 -3 | ✅ |
| 软复位 | DEVICE_CONFIG(0x11) bit0=1，等待 ≥1ms | `reset()` 写 0x01 + `delay(1)` | ✅ |
| 上电模式 | PWR_MGMT0(0x4E)=0x0F：accel/gyro LN | `begin()` 写 0x0F | ✅ |
| ODR 编码 | 0x01=32k、0x02=16k、0x03=8k、0x04=4k、0x05=2k、0x06=1k…0x0F=500 | 枚举 `odr32k=0x01 … odr2k=0x05 … odr500=0x0F`，写入 CONFIG0 低 4 位 | ✅ |
| FSR | GYRO_CONFIG0[7:5]、ACCEL_CONFIG0[7:5] | `(fssel<<5) \| (reg&0x1F)` | ✅ |
| 量程换算 | ±16g: 2048 LSB/g；±2000dps: 16.4 LSB/dps | `_accelScale=(1<<(4-fssel))/32768`、`_gyroScale=(2000/(1<<fssel))/32768` | ✅ |
| **UI 低通（DLPF）** | **GYRO_ACCEL_CONFIG0(0x52) bit3:0=陀螺、bit7:4=加计；编码 0=ODR/2、1=max(400,ODR)/4、2=/5、3=/8、4=/10、5=/16、6=/20、7=/40** | **旧实现写 GYRO_CONFIG0/ACCEL_CONFIG0 低 4 位（ODR 字段），LPF 从未生效** | ❌→已修 |
| SPI 读 | 16+ 时钟，首字节 bit7=1 读地址，后续字节数据，无 dummy | `transfer(addr\|0x80)` 后连续读 | ✅ |
| SPI 时序 | Mode3、MSB first、≤24MHz | 调用方 `SPISettings(10MHz, MSBFIRST, SPI_MODE3)` | ✅ |
| 温度 | `T = raw/132.48 + 25`（TEMP_DATA 0x1D/0x1E） | `TEMP_DATA_REG_SCALE=132.48`、`TEMP_OFFSET=25` | ✅ |
| 中断 | INT1 数据就绪（未使用，轮询 getAGT） | 未配置 | ⚪ 未用 |

### 修复内容（42688）

- `ICM42688::setLowPassFilter()` 重写：先读 CONFIG0 的 ODR 码 → 按手册编码表（不是 ODR/2^n）
  选最接近目标带宽的档 → 写 `GYRO_ACCEL_CONFIG0(0x52)` 对应半字节。
- 新增 `setLowPassFilterBw(code)`、`selectLpfCode(odr, targetHz)`、`actualLpfHz()`。
- `ICM42688_ImuDevice::begin()` 顺序改为 **先 FSR/ODR、后 LPF**（选档依赖实际 ODR），
  并记录真实截止频率（陀螺 100Hz 目标 → ODR=2000 时 code6=100Hz；加计 50Hz → code7=50Hz）。

### 行为影响（必须上板确认）

修复前 42688 的 LPF 配置实际无效（写错寄存器后又 ODR 覆盖），等效默认/旁路；修复后
LPF 真正生效：高频噪声下降，但**群延迟增加**（100Hz 档约 +1.6ms、50Hz 档约 +3.2ms）。
这会影响姿态/EKF 的相位裕度与 delay 补偿假设，需：
1. 上电日志核对 `actualGyroLpfHz/actualAccelLpfHz` 是否为 100/50Hz；
2. 重跑 SIL/台架，确认姿态环无振荡、GNSS 延迟补偿仍匹配；
3. 若延迟不可接受，可把陀螺 LPF 目标改 200Hz（code4）或旁路（code0）。

## 三、与仿真参数的关系

导航性能测试（`test_host/test_imu_nav_perf.cpp`）的 IMU 噪声/零偏取自：
- 42688：DS-000347 典型值（陀螺 0.0028 °/s/√Hz、ZRO ±0.5 °/s、加计 70 µg/√Hz）；
- 45686：DS-000577（陀螺 0.0038 °/s/√Hz、ZRO ±0.4 °/s、加计 70 µg/√Hz、零 g ±20mg）。

**42688 LPF 修复后**，仿真中的 LPF 假设（一阶 50/100Hz）才与实机一致；此前的仿真是按
"设计意图"而非"实际驱动行为"建模，需在修复后重跑性能矩阵，确认精度变化。

## 四、导航改进验证：GNSS 观测年龄补偿（2026-11-01）

**背景**：`test_host/test_imu_nav_perf.cpp` 的 GNSS 延迟档（RTK 10Hz + 100ms）此前
把滞后测量当成"当前时刻"调用 `MeasurementUpdate()`。固件实际走
`MeasurementUpdateDetailed(..., measurement_age_s)`（`navigation_task.cpp:2865`），
EKF 会按年龄回暖历史快照后重传播。

**实验**：`IMUPERF_DELAY_AB=1`，同一 100ms 延迟数据分别跑 comp=off（3 参数）与
comp=on（4 参数，age=latency），2 IMU × 3 场景 × 4 seeds。

| IMU | 场景 | 位置 RMSE（off → on） | 变化 |
| --- | --- | --- | --- |
| ICM42688P | static | 0.0095 → 0.0098 m | +2.5% |
| ICM42688P | maneuver | 0.0097 → 0.0101 m | +4.0% |
| ICM42688P | cruise | 0.0670 → 0.0213 m | **−68.2%** |
| ICM45686 | static | 0.0083 → 0.0086 m | +3.4% |
| ICM45686 | maneuver | 0.0109 → 0.0114 m | +5.1% |
| ICM45686 | cruise | 0.0682 → 0.0200 m | **−70.7%** |

**结论**：
1. 有平移运动时，年龄补偿把光级延迟引入的位置误差压回噪声底（6.7cm→2.1cm），
   收益 −68%~−71%，与手册/理论一致（延迟 0.1s × 1m/s = 0.1m 量级）；
2. 静止/纯旋转时无平移位移，补偿反而引入历史回放的微小抖动（+2.5%~+5%，
   绝对值 <1mm），可接受；
3. 固件已走带 age 的接口，这条改进**已在固件生效**；测试只是量化其价值，
   并防止以后有人把调用退回 3 参数版本；
4. 建议：`BFS_NAVIGATION_GNSS_DELAY_AUTO_ESTIMATE` 保持开启（默认 1），
   PPS/投递时间戳标定的真实年龄越小，补偿收益越准。

## 五、第二轮深读手册（2026-11-01，逐寄存器表复核）

用 MinerU 转换的 `.md`（表格保留 `<table>`）逐节复核，补充确认与新增发现：

### 已确认正确的项

| 项 | 手册依据 | 实现 |
| --- | --- | --- |
| 42688 DRDY 位 | INT_STATUS(0x2D) bit3 = DATA_RDY_INT | `getAGT()` 读 0x2D 并检查 `0x08`，无新样本返回 0 |
| 42688 数据块 | TEMP_DATA1(0x1D) 起 14 字节：TEMP+ACCEL+GYRO | `readRegisters(0x1D, 14)` 后按 16-bit 大端拼装 |
| 42688 温度 | `(TEMP_DATA / 132.48) + 25` | `TEMP_DATA_REG_SCALE=132.48`、`TEMP_OFFSET=25` |
| 42688 SPI 模式 | DEVICE_CONFIG(0x11) bit4 SPI_MODE，默认 0 = Mode0/Mode3 | 不写该位，外部 `SPI_MODE3` 兼容 |
| 42688 量程换算 | ±16g: 2048 LSB/g；±2000dps: 16.4 LSB/dps | `_accelScale=(1<<(4-fssel))/32768`、`_gyroScale=(2000/(1<<fssel))/32768` |
| 45686 软复位 | REG_MISC2 soft_rst=1，等待 1ms，检查 RESET_DONE | 库 `inv_imu_soft_reset` 逐项实现 |
| 45686 UI 数据块 | 0x00-0x0B = accel XYZ + gyro XYZ；0x0C-0x0D = TEMP | `inv_imu_get_register_data` 从 0x00 burst 读 14 字节，结构体顺序一致 |
| 45686 温度 | `25 + raw/128` | `rawRegisterTempToC` 一致 |
| 45686 串口配置 | UI_SPI4 写 INTF_CONFIG1_OVRD 4-wire override | 库 `configure_serial_interface` 实现 |
| 45686 LPF 间接寄存器 | IPREG_SYS1_REG_172 / SYS2_REG_131 经 IREG 窗口读-改-写 | 库 `inv_imu_set_gyro_ln_bw`/`set_accel_ln_bw` 实现 |

### 新发现的缺陷（未使用路径，已显式拒绝）

| 接口 | 旧实现问题 | 处理 |
| --- | --- | --- |
| `setAntialiasFilter` | 把频率枚举按位写进 `GYRO/ACCEL_CONFIG_STATIC2`（那是 AAF/NF 的 DISABLE 位），从未配置 DELT/DELTSQR/BITSHIFT | 改为恒返回 -1 + 注释；当前项目不用 AAF |
| `setNotchFilter` | 把中心频率/带宽写进 STATIC3/4（实为 AAF DELT/DELTSQR），且 `enable=true` 时置位 STATIC2 bit0=NF_DIS（1=禁用，极性反） | 改为恒返回 -1 + 注释 |
| `setFilters` | 只写使能位、不配 AAF 参数，启用的是未定义带宽的 AAF | 改为恒返回 -1 + 注释 |

结论：现役飞控路径只调用 `begin(cfg)`（FSR/ODR/DLPF），不触碰这三个接口；把它们从"静默写错"改为"显式拒绝"，防止后续有人启用 AAF/notch 时得到错误配置。

## 六、第三轮：AAF/notch 实现 + 45686 FIFO/APEX 接口（2026-11-01）

### 42688 AAF/notch（从“显式拒绝”改为真正实现）

| 接口 | 手册依据 | 实现 |
| --- | --- | --- |
| `setAntialiasFilter` | §5.3 AAF 表（63 档，42..3979Hz → DELT/DELTSQR/BITSHIFT） | 内嵌 63 档表 + 最近邻选择；陀螺 bank1 STATIC3-5、加计 bank2 STATIC2-4；清/置 AAF_DIS |
| `setNotchFilter` | §5.2：COSWZ=cos(2π·f/32)，f 单位 kHz（1..3）；Step2 的 SEL 分支；NF_BW_SEL 0..7 | 计算 9-bit COSWZ/SEL，写 STATIC6-9（三轴同值）+ STATIC10 带宽；STATIC2 bit0=NF_DIS 控制使能 |
| `setFilters` | STATIC2 的 AAF_DIS 位 | 只切换使能位，参数须先由 `setAntialiasFilter` 配置 |

### 45686 FIFO / APEX

- **FIFO**：库已有 `configureFifo` / `getDataFromFifo` / `getDataFromFifoBatch` /
  `getFifoFrameCount` / `flushFifo`（底层 `inv_imu_adv_set_fifo_config` 与
  `inv_imu_get_fifo_frame`），本次未改动，保持可用。
- **新增 WOM 接口**：`configureWom()`（阈值 mg→1g/256、OR/AND、1..4 样本、先以推荐
  ODR 启动加计）、`enableWom()` / `disableWom()`、`readWomStatus()`（读
  INT1_STATUS1 0x1A 的 WOM_X/Y/Z 位）。
- **新增 APEX 接口**：`enablePedometer()` / `disablePedometer()`、`enableTilt()` /
  `disableTilt()`、`readApexStatus()`（INT_APEX_STATUS0/1 事件位）、
  `readPedometerSteps()`（APEX_DATA0/1，0x31/0x32）。
- 注意：APEX 与 FIFO/eDMP 共享 SRAM/中断资源，启用前不要同时跑 FIFO 压缩模式。
