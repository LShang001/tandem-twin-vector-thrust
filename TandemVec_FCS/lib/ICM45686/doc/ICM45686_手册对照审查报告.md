# ICM45686 驱动库手册对照审查报告

审查对象：`lib/ICM45686`

手册依据：`doc/mineru_DS-000489_ICM-45686_v1.1/DS-000489_ICM-45686_v1.1.md`

审查范围：Arduino 封装 `ICM45686.h/cpp`、飞控适配层 `ICM45686_FlightAdapter.*`、底层 InvenSense C driver、示例与当前文档。

## 总体结论

底层寄存器映射整体与 ICM-45686 v1.1 手册一致，核心六轴读取链路可以作为继续开发基础：

- `WHO_AM_I` 地址 `0x72`、复位值 `0xE9` 与手册一致。
- UI 传感器寄存器从 `ACCEL_DATA_X1_UI(0x00)` 到 `TEMP_DATA0_UI(0x0D)` 连续读取，与手册寄存器表一致。
- `ACCEL_CONFIG0(0x1B)`、`GYRO_CONFIG0(0x1C)` 的 ODR/FSR 枚举与手册位域一致。
- FIFO、APEX、WOM、I2CM、间接寄存器访问的底层 C driver 基本覆盖了手册主要寄存器。
- SPI 频率上限限制为 `24 MHz`，与手册主 SPI 上限一致；当前 SPI 使用 `SPI_MODE3`，符合手册“数据上升沿采样、下降沿切换”时序。

本轮修复后，Arduino 封装已经从“bring-up 级接口”推进到“可继续做飞控前期验证的自有库接口”：WOM 单位、小数 ODR/FSR、FIFO 20-bit/深度/decimation、寄存器读写校验、自检、DRDY、FSYNC/INT2 条件接口都已经补到公开 API，并新增编译期覆盖测试。

仍然不能直接称为“完整飞控级双 IMU 驱动”。主要剩余边界是：多实例和回调对象隔离尚未彻底重构；APEX 高级事件仍未全参数化；用户 offset/校准写入 API 尚未封装；本报告只完成静态手册对照和编译验证准备，真实 FIFO 中断、WOM、自检、FSYNC 波形和高频数据质量仍需要上板验证。

## P0 级问题

### 1. WOM 默认阈值的宏名和单位表达混乱

源码位置：`src/ICM45686.cpp:72-76`、`src/ICM45686.cpp:1546-1571`

手册依据：Markdown 手册 `ACCEL_WOM_X/Y/Z_THR` 说明阈值格式为 `1g/256`，约 `3.9 mg/LSB`，见 `DS-000489_ICM-45686_v1.1.md:3283-3293`。

修复前代码：

```cpp
#define DEFAULT_WOM_THS_MG     (52 >> 2) // 52 mg
```

这里宏名和注释都表示 `mg`，但实际传入 `inv_imu_adv_configure_wom()` 的值是寄存器 LSB，不是 mg。`52 >> 2` 等于 `13`，实际阈值约为 `13 / 256 g = 50.8 mg`，不是注释里的“52 mg 经过公式换算”也不是宏名表达的“mg”。如果后续开发者按 `mg` 理解，会直接配置错 WOM 灵敏度。

修复状态：

- 已修复。`DEFAULT_WOM_THS_MG` 和 `DEFAULT_WOM_AID_THS_MG` 改为真实 mg 值，不再预先右移成寄存器 LSB。
- 已新增 `ICM456xx::womThresholdMgToReg(uint16_t mg)`，按 `round(mg * 256 / 1000)` 换算并限幅到 `0..255`。
- 已新增 `ICM45686WomConfig`，允许配置 X/Y/Z 阈值、AND/OR 模式、持续样本数和 WOM 加速度 ODR。
- 旧接口 `startWakeOnMotion(uint8_t, handler, int odr)` 继续保留，并把旧整数 ODR 映射到强类型 ODR，避免兼容层静默丢参数。

### 2. 小数 ODR/FSR 被整数 API 截断表达，容易静默选错档位

源码位置：`src/ICM45686.h:124-130`、`src/ICM45686.cpp:1895-1981`

手册依据：

- 陀螺仪 FSR 支持 `±15.625/31.25/62.5/125/.../4000 dps`，见 `DS-000489_ICM-45686_v1.1.md:931`。
- 加速度和陀螺仪 ODR 支持 `1.5625/3.125/6.25/12.5/25/.../6400 Hz`，见 `DS-000489_ICM-45686_v1.1.md:931`、`959`、`2165-2169`。

修复前 API 只使用 `uint16_t`：

```cpp
int startAccel(uint16_t odr, uint16_t fsr);
int startGyro(uint16_t odr, uint16_t fsr);
```

代码用 `case 1/3/6/12` 近似表示 `1.5625/3.125/6.25/12.5 Hz`，用 `case 15/31/62` 近似表示 `15.625/31.25/62.5 dps`。这会造成两个问题：

- 调用者传入真实手册值 `12.5` 不可能被 `uint16_t` 准确表达。
- 调用者传入 `12` 时含义不清，是 12 Hz 还是 12.5 Hz 档位。

修复状态：

- 已新增强类型枚举：`ICM45686AccelOdr`、`ICM45686GyroOdr`、`ICM45686AccelFsr`、`ICM45686GyroFsr`。
- 已新增 `startAccel(ICM45686AccelOdr, ICM45686AccelFsr)` 和 `startGyro(ICM45686GyroOdr, ICM45686GyroFsr)`。
- 旧整数 API 保留给历史示例和简单调用；README 已明确 `1/3/6/12` 是对 `1.5625/3.125/6.25/12.5 Hz` 的兼容映射，`15/31/62` 是对 `15.625/31.25/62.5 dps` 的兼容映射。
- `icm45686_spi_test`、`icm45686_spi_diagnostic`、`icm45686_vofa_highrate` 已迁移到强类型 API 或宏到强类型枚举的转换路径。

## P1 级问题

### 3. FIFO 20-bit 高分辨率能力在底层存在，但 Arduino API 暴露不足

源码位置：`src/imu/inv_imu_driver.c:311-322`、`src/imu/inv_imu_driver.c:402-446`、`src/ICM45686.cpp:255-277`

手册依据：手册说明 FIFO 支持 20-bit 高分辨率格式，陀螺仪按 `±4000 dps`、加速度按 `±32 g` 固定缩放，见 `DS-000489_ICM-45686_v1.1.md:1564-1568`、`1731`、`2189-2193`。

修复前底层 `inv_imu_get_fifo_frame()` 已有 20 字节解析，但 Arduino 封装 `enableFifoInterrupt()` 固定：

```cpp
.hires_en=false
```

用户无法通过公开 API 启用高分辨率 FIFO，也没有对应的单位换算辅助。对飞控高速记录和振动分析来说，这是明显缺口。

修复状态：

- 已新增 `ICM45686FifoConfig` 和 `configureFifo()`，可配置 accel/gyro 使能、20-bit hires、watermark、stream/snapshot、timestamp/FSYNC、FIFO 深度和 accel/gyro FIFO decimation。
- 已新增 `enableFifoInterrupt(uint8_t, handler, const ICM45686FifoConfig&)`，旧 watermark 版本仍保留。
- 已新增 `rawFifo20AccelToG()`、`rawFifo20GyroToDps()`、`rawFifoTempToC()`，README 已说明 20-bit FIFO 按手册固定 `±32 g`、`±4000 dps` 缩放。
- `icm45686_api_compile_test` 已覆盖 20-bit FIFO 配置签名；真实 20-bit FIFO 数据质量仍需上板验证。

### 4. FIFO 8KB/2KB 深度语义没有清楚暴露

源码位置：`src/imu/inv_imu_defs.h:312-330`、`src/ICM45686.cpp:255-277`

手册依据：默认 FIFO 为 2KB，可在禁用 APEX 时扩展到 8KB；`FIFO_CONFIG0` 中 `000111` 为 2KB、`011111` 为 8KB，见 `DS-000489_ICM-45686_v1.1.md:911`、`1564`、`2173`。

修复前代码使用 `FIFO_CONFIG0_FIFO_DEPTH_MAX`，注释来自 Errata，不直观说明到底是 8KB 还是受 APEX 限制的最大深度。对上层用户来说，无法明确选择“飞控主循环低延迟 FIFO”还是“日志记录大深度 FIFO”。

修复状态：

- 已新增 `ICM45686FifoDepth::Depth2KB` 与 `ICM45686FifoDepth::Depth8KB`。
- README 已说明 APEX/eDMP 占用 SRAM 时应优先使用 `Depth2KB`。
- 尚未实现运行时 APEX/eDMP 状态检测和自动降级；如果后续要把 APEX 与 FIFO 混合到同一诊断流程，应再加互斥状态检查。

### 5. SPI 写读回调无法检测总线层失败，错误码可靠性有限

源码位置：`src/ICM45686.cpp:1859-1893`

手册依据：SPI 主接口最高 `24 MHz`，4-wire SPI 时序见 `DS-000489_ICM-45686_v1.1.md:1076`、`1815-1824`。

Arduino SPI `transfer()` 本身通常没有错误返回，因此当前 `spi_write()` 和 `spi_read()` 永远返回 `0`。这在裸 SPI 下很常见，但对飞控健康监测而言会造成风险：断线、MISO 悬空、CS 错误时，只有上层数据异常或 `WHO_AM_I` 校验能发现，普通寄存器读写不会直接报错。

修复状态：

- 已新增 `readWhoAmI()`、`readRegister()`、`readRegisters()`、`writeRegister()`、`writeRegisterChecked()`，可以用于初始化后复读 WHO_AM_I、关键配置写后读回和手册寄存器对照测试。
- `icm45686_spi_diagnostic` 已保留裸 SPI `WHO_AM_I` 检查，并使用库内换算函数输出飞控关心的统计。
- 尚未在 `ICM45686_FlightAdapter` 中加入重复帧、全 0/全 1 帧和周期性 WHO_AM_I 健康策略；这是飞控接入前的下一步。

### 6. 公开 API 未覆盖手册 v1.1 的若干关键能力

手册依据：

- Self-test：`SELFTEST` 和 `INT_APEX_STATUS1.SELFTEST_DONE`，见 `DS-000489_ICM-45686_v1.1.md:3295-3297`。
- FSYNC：`FSYNC_CONFIG0/1`、`TMST_FSYNCH/L`，见 `DS-000489_ICM-45686_v1.1.md:2201-2205`。
- ODR decimation：`ODR_DECIMATE_CONFIG`，见 `DS-000489_ICM-45686_v1.1.md:2217`。
- INT2：手册说明 AUX1 启用时 INT2 可用性受限，见 `DS-000489_ICM-45686_v1.1.md:1175`。
- 用户 offset：`IPREG_SYS1/2` 中 gyro/accel offset，见 `DS-000489_ICM-45686_v1.1.md:3317-3387`。

修复前底层 C driver 已有部分能力，例如 `inv_imu_selftest.*`、FSYNC helper、endian helper、offset 相关寄存器定义，但 Arduino `ICM456xx` 没有稳定公开 API。当前库适合 bring-up 和诊断，但还不适合当成完整飞控 IMU 驱动接口。

修复状态：

- 已新增 `runSelfTest()`，并在诊断台加入 `selftest`/`st` 命令。
- 已新增 `configureDataReadyInterrupt()`，默认 INT1，但允许传入底层 `inv_imu_int_num_t`。
- 已新增 `configureFsync()` 和 `configureInt2PinUsage()`，分别受 `INV_IMU_FSYNC_SUPPORTED` 和 `INV_IMU_INT2_PIN_SUPPORTED` 条件编译保护。
- FIFO decimation 已通过 `ICM45686FifoConfig::accel_decimation` 和 `gyro_decimation` 暴露。
- 受控寄存器读写 API 已补齐。
- 尚未封装用户 gyro/accel offset 写入 API，原因是该功能会直接影响后续姿态估计和零偏管理，建议等飞控校准策略确定后再做。

## P2 级问题

### 7. 多实例和中断回调仍不是对象隔离

源码位置：`src/ICM45686.cpp:65-70`、`src/ICM45686.cpp:96-99`、`src/ICM45686.cpp:149-188`

当前仍存在静态缓存和全局 driver 指针：

- `accel_data[]`
- `gyro_data[]`
- `mag_data[]`
- `icm_driver_ptr`

这与前期文档里“官方 Arduino 封装不适合多实例”的判断一致。对单 IMU bring-up 可接受，但对后续双 IMU 冗余或一主一备架构，需要重构。

建议修复：

- 把事件回调上下文透传到实例，取消全局 `icm_driver_ptr`。
- 中断 ISR 只设置实例级 `volatile` 标志，由主循环读取。
- 明确禁止复制 `ICM456xx` 对象，避免浅拷贝总线指针和底层状态。

当前状态：未修复。本轮没有重构回调架构，库仍按单 IMU bring-up/诊断使用更稳妥。后续如果要做双 IMU 冗余，必须优先处理这一项。

### 8. APEX 事件接口功能较多，但参数不可配置

源码位置：`src/ICM45686.cpp:1118-1368`、`src/ICM45686.cpp:1370-1779`

手册依据：APEX 支持 pedometer、tilt、tap、raise-to-wake、wake-on-motion、free-fall、significant motion、low-g、high-g 等，见 `DS-000489_ICM-45686_v1.1.md:894-904`、`1759-1763`。

当前封装能启动多个 APEX 功能，但大多数阈值、持续时间、tap 参数、high-g/low-g 参数使用默认值或硬编码逻辑。对飞控准备阶段可以用于验证事件是否能工作，但不能满足后续“按机体振动、姿态、任务阶段调参”的需求。

建议修复：

- 给 APEX 各事件增加参数结构体。
- 明确 APEX 会重配 ODR、LPF、eDMP、中断，禁止与飞控主数据读取链路混用。
- 增加“APEX 诊断模式”和“飞控主 IMU 模式”的互斥状态机。

当前状态：部分修复。WOM 已有参数结构体，APEX 其他事件仍未全参数化。诊断台已经把 APEX 作为独立模式运行，但库内部还没有完整互斥状态机。

### 9. 文档声称“功能全面”，但实现更像 bring-up + 部分高级功能

源码和文档位置：`README_中文.md`、`library.properties`、`examples/`

修复前库的底层确实包含很多官方能力，但 Arduino 层没有全面封装，且不少能力只存在于底层 C driver。文档如果直接说“支持全部复杂功能”，容易让后续项目误用。

修复状态：

- README 已补充“编译验证”和“上板验证”的边界，明确 `icm45686_api_compile_test` 不访问硬件。
- README 已明确飞控接入顺序：先 WHO_AM_I、begin、startAccel/startGyro、单位/轴向/采样周期，再考虑 FIFO/中断，最后接入姿态解算和控制闭环。
- APEX 已明确定位为诊断、低功耗唤醒、事件检测，不建议作为姿态或导航主数据源。
- 后续仍建议把 README 再拆成 API 手册、硬件 bring-up、飞控接入三份文档，降低单文档长度。

## 已确认正确或基本合理的实现

- `WHO_AM_I` 校验：底层初始化会读取并比较 `INV_IMU_WHOAMI`，见 `src/imu/inv_imu_driver_advanced.c:51-54`。
- 软件复位后读取 `RESET_DONE`：符合复位后确认流程，见 `src/imu/inv_imu_driver.c:27-63`。
- UI 寄存器数据读取：从 `ACCEL_DATA_X1_UI` 连续读取 `inv_imu_sensor_data_t`，并按 `SREG_CTRL` 端序解析，见 `src/imu/inv_imu_driver.c:205-229`。
- 寄存器温度换算：飞控适配层 `25 + raw / 128` 与手册一致，见 `src/ICM45686_FlightAdapter.cpp:95-98` 和手册 `DS-000489_ICM-45686_v1.1.md:2111-2117`。
- FIFO 温度换算文档：README 中区分寄存器温度 `/128` 与 FIFO 温度 `/2`，与手册一致。
- I2C 读路径已有超时，避免设备掉线时无限阻塞，见 `src/ICM45686.cpp:1817-1857`。
- 间接寄存器访问避开手册/Errata 禁止区域，见 `src/imu/inv_imu_transport.c:82-105`。

## 后续重构建议顺序

1. 已完成：修正 WOM 阈值单位和 API。
2. 已完成：用强类型枚举补充 `uint16_t odr/fsr` 参数，保留兼容层。
3. 已完成：新增底层受控寄存器读写 API 和写后读回校验工具。
4. 已完成主要接口：扩展 FIFO 配置 API，覆盖 2KB/8KB、20-bit hires、decimation、timestamp、stream/snapshot。
5. 部分完成：已增加 self-test、FSYNC、DRDY、INT2；offset API 尚未封装。
6. 未完成：重构回调和缓存为实例级状态，明确单实例/多实例能力边界。
7. 已完成第一版：README 已同步新增接口、测试命令和验证边界。

下一轮建议优先级：

1. 把 `ICM45686_FlightAdapter` 升级为飞控健康监测入口，增加重复帧、全 0/全 1、连续错误、周期性 WHO_AM_I、配置寄存器读回。
2. 重构中断回调和全局缓存，消除多实例隐患。
3. 增加用户 offset/校准 API，但必须先确定飞控校准策略和保存位置。
4. 给 APEX tap/high-g/low-g/free-fall 等事件增加参数结构体，并建立与主 IMU 模式的互斥状态机。
5. 上板验证 20-bit FIFO、DRDY、WOM、自检和 VOFA+ 高频输出，再把硬件实测结果写回文档。

## 审查状态

本报告已随本轮代码修复同步更新。当前状态是：已按手册修复 P0 问题，并补齐多项 P1 级公开接口；后续仍需运行 PlatformIO 编译验证和上板验证。上板验证前必须确认 SPI 接线、INT1 接线、供电电压和地线；后续如果接入飞控或执行机构，必须先断开电机/推进动力。
