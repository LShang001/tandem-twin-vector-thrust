# 飞控磁标定与航向链路工程闭环

## When to Use
- 拿到外部参考工程（其它机型飞控包）要评估「磁融合值不值得移植」时。
- 磁力计标定采集不到数据、标定能拟合但保存失败、磁数据被门控永久拒收、换标定后航向偏一个固定角度时。
- 要改默认航向源模式（磁连续融合 / 磁仅初始对准 / 无磁）并需要给出证据与代价时。
- 同一架飞行器换代码库运行，要把旧代码库的标定参数/轴表移植过来时。

## Prerequisites
- 能跑宿主单测与固件编译（PlatformIO 环境可用），能跑生产路径 SIL（real-nav / nav_ekf）。
- 明确区分**生产路径**与**legacy 实验环**：两者观测模型不同，结论不可互换。
- 项目内 `tmp/` 作临时目录；盘符映射用完即删（`subst` 空输出才算清干净）。

项目坐标（UniGNC / TandemVec_FCS）：
- 磁链路源码：`lib/MagSensor/MagSensor.{h,cpp}`（双芯片探测+标定管线：芯片系 applyCal → 轴对齐 FRD）、`lib/MagSensor/MagMath.h`（灵敏度+轴对齐表，按机型宏分支）、`lib/MagCal/`（椭球拟合/两圈引导/Flash 存储）、`include/mag_cal_defaults.h`（编译期兜底，机型门控）、`include/mag_measurement_gate.h`（全门控+自适应噪声）、`include/mag_reference.h`（站点参考场/磁偏）。
- 生产调用点：`src/sensor_imu.cpp`（initMagnetometer 加载顺序 Flash→defaults→直通；guideUpdate 喂重力方向=比力取反）、`src/navigation_task.cpp`（磁门控+MagVectorDetailed，mode 0 才连续融合）、`src/communication.cpp`（DBG magcal/magraw/magdec）。
- 命令：`pio run -e CoaxialVTVL_ICM45686 -e TandemVec_FCS`；宿主磁相关段 mp/mc/mg/mref/mgate（`test_host/run_all.sh`）；生产路径 SIL `bash test_host/fw_sil/build_and_run_env.sh --real-nav --mag --seed N --seconds 40`（不带 `--real-nav` 是 legacy 实验环 g_ekf）；`py -3.12 tools/verify-all.py`。
- 文档正本：`docs/registers/踩坑记录-AGENTS.md` 2026-11-16 节、`docs/05-控制与分配/CTL-005-无磁航向与运动EKF.md`、`docs/registers/固件调试工具链-2026-11-01.md`、`TandemVec_FCS/AGENTS.md` 磁标定/magraw/航向源节。
- 共轴标定参数一手来源：VTVL_ElectricDualRotor_FCS_CNmodify_new 包 `include/mag_cal_defaults.h` + `main.cpp kMagAxisToBody`（2026-11-15 户外重标，同一架共轴实机 45686 配置，用户 2026-11-16 确认机体同一）。

## Procedure
1. **先分维度对比架构，再决定移植方向。** 逐项列：磁芯片数量与探测、门控完整度（模长/倾角/跳变/多帧一致性）、融合形式（磁矢量融合 vs 标量 yaw 观测）。本项目更强的一侧**不反向移植**；只移植对方更成熟的**工程闭环**（标定引导、存储可靠性、编译期兜底、调试命令、门控参考取法）。
2. **逐项移植并各配一条宿主回归。** 每项改动落一条可命名的回归用例（如姿态门符号 S9、模长门参考 G11），先复现失败再修。
3. **校核每个门控的物理量约定与调用点。** 打开门控实现看它期望什么（重力方向 vs 比力），再打开**生产调用点**看实际喂什么，符号/坐标系逐项对上。宿主测试喂的量必须与生产调用点同源。
4. **存储可靠性三件套**：清 Flash 状态寄存器的粘滞错误标志（SR2 类）、擦除前做保护/校验（探针先失效 D-Cache）、长擦写循环里保留看门狗喂狗。症状「能拟合但 saved=0」优先查这三处。
5. **编译期标定兜底按机型宏门控**：`mag_cal_defaults.h` 用 `#if defined(BFS_COAXIAL_VTVL)` 之类分支，已标定机型 kValid=true、未标定机型 kValid=false。参数**机体专属**：同一架飞行器换代码库可以移植（先经用户确认机体同一），不同机型绝不抄。上电加载顺序 Flash→defaults→直通；强制改用 defaults 用 `magcal erase` 后重启。
6. **参数与轴表是实测组合，必须成对移植**：椭球拟合的软铁白化矩阵含不可观旋转（约 +90°），轴对齐表（MagMath.h）要按机型分支用源工程户外实测表，不能只抄参数沿用安装推导表。移植后 `magraw` 复核：机头朝北水平 yaw_est≈0°、朝东≈+90°。
7. **灵敏度单位系差异如实标注、不擅自换算**：源固件驱动系数可能与本项目不同（如 IST8310 0.30303 vs 0.3 uT/LSB）。b/scale 按源单位系原值移植（一手来源），注释写明理论残差量级（~0.15 uT / 航向 ~0.2°，相对标定自身残差是二阶小量）；M 无量纲不受影响。换算依赖「哪个系数是真物理值」的假设，要高精度应在本项目固件上重标。
8. **模长门参考优先取标定拟合的 scale/场强**，不要用写死的站点总场常量（不同纬度地磁总场差可达数 µT，会导致异地永久拒收）；scale 无效（≤5 µT/非有限）回退站点总场，绝对模长门与倾角/方位门不变。
9. **切默认航向源前跑生产路径 SIL 三组对照**：新默认+磁 / 旧默认+磁（连续）/ 无磁基线，同 seed 同时长，记 `mag_fused` 计数、`yaw_rmse`、`pos_rms`。数字由脚本从结果文件生成，不手抄。
10. **写清代价与回退开关**：保守模式（磁仅初始对准）通常牺牲位置保持能力（如仅离地后 20 s 窗口，到点降级定高），必须在控制文档里写明窗口、降级行为，以及一行回退办法（GCS 设 `hdg_mode=0`）。
11. **收口**：宿主磁测试全绿（含机型变体轴表回归）→ 固件涉及机型 env 编译成功 → 按改动面跑最小守卫集 → 同步控制文档/踩坑记录/调试工具链/AGENTS.md → 窄提交 + push → 清 `tmp/` 本次产物。

## Pitfalls
- **宿主测试恒绿盲区（最贵的一条）**：门控期望重力方向、生产调用点喂比力（符号相反），实机永远采不到数据；而宿主测试自己喂重力方向，于是长期全绿。凡是「实机不工作但测试全绿」，第一件事是对齐测试输入与生产调用点的物理量，而不是怀疑硬件。
- **只移植参数不移植轴表** → 航向整体偏一个固定角（曾实测多转 +90°）。参数+轴表是户外实测组合，换任一项必须 magraw 复核；安装推导表配实测标定参数会错。
- **机体同一性两个方向的误判**：不同代码库≠不同机体（同一架飞机换固件运行，参数可移植，先经用户确认）；同代码库≠同机体（不同机型安装/磁环境不同，绝不抄）。门控落在机型宏上，不落在代码库上。
- 把 **legacy 实验环**的发散当作生产结论。标量 yaw 观测的实验环发散，不代表生产磁矢量融合不行；下结论前先确认 SIL 跑的是哪条路径（`--real-nav` 与否）。
- 用固定站点总场常量做模长门 → 换城市/换纬度后磁数据被判永久异常；拟合场强偏低（如 41.8 vs 长沙 48.97）时本地也会永久拒收。
- 编译期兜底默认 `kValid=true` 或抄别机标定值 → 换板后带着错误标定起飞，比没有标定更危险。
- Flash 长擦除里删掉喂狗 → 标定保存触发看门狗复位；擦除前不失效 D-Cache → 保护探针读脏数据。
- 把「保守默认」说成算法能力边界。要如实写：连续磁融合在生产路径实测精度最好，取保守模式是防实机磁干扰的决策。
- 只做完宿主/SIL 就宣称已验证。标定与保存路径改动若只影响未解锁地面阶段，要明确标注「未做实机验证」及影响范围；SIL 磁注入 bypass 轴对齐（silInjectFrdSample 直接注 FRD），轴表/defaults 正确性只能靠源工程实测+上板 magraw，SIL 验不了。

## Verification
- 宿主磁相关测试全部通过，且**包含本轮新增回归**（符号门、模长门参考、机型变体轴表各一条）。
- 固件涉及机型 env 编译 SUCCESS（共轴+纵列至少各一），记录 RAM/Flash 占用。
- 按改动面选定的守卫集全部通过（不无脑跑全量）。
- 生产路径 SIL 三组对照表齐备，数字来自结果文件；`mag_fused` 计数能证明该模式是否真的在融合。
- 上板清单可执行：引导标定两圈 → `magraw` 核对轴向（朝北水平≈0°、朝东≈+90°）→ 标定值填入编译期兜底头 → 初始对准生效。
- 文档四处同步、工作树干净、提交已 push、`tmp/` 本次临时产物已清、盘符映射无残留。
